## 質問事項

[Critical] [Warning] [Suggestion] で診断:

1. **Partition / Fold の長さ不変条件**: synthesis § 4.3-4.4 確定値 (62+8+1+6+1+6+1+6+1+12=104, fold 5×5+(36+1+5)=62) が deterministic に計算される設計で問題ないか
2. **Stage A の時間軸位置**: 時系列で B より後 (recent proxy) という synthesis § 5.2 確定が設計に正しく反映されているか
3. **半開区間 [start, end) 規約**: 後段 engine 側 (T070) で `start <= bar.timestamp < end` で消費される前提で問題ないか
4. **既存 walk_forward.py:make_wf_folds との置換タイミング**: Phase 2 (T061-T064 と同時) で置換、 T060 PR 単独では touch しない方針で問題ないか
5. **Period の label 規約**: `stage_b` / `stage_a` / `stage_c_lite_1` / `stage_c_lite_2` / `stage_c_lite_3` / `stage_c` / `embargo_after_a` / `embargo_after_c_lite_*` で network される downstream が依存する命名で適切か
6. **見落とし論点**: bar 数換算 / partition の yaml override / 6m fallback / 異なる stride 等
