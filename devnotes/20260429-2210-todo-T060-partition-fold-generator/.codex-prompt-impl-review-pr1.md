## 検証観点

### A. partition.py の正しさ (= 詳細設計 行 41-391 の意図充足)

A1. **`PeriodLabel` SSOT**: 13 値が string literal 依存を回避する SSOT になっているか。 partition 用 10 値 (stage_b / stage_a / embargo_after_a / stage_c_lite_1-3 / embargo_after_c_lite_1-3 / stage_c) + fold suffix base 3 値 (fold_train / fold_embargo / fold_test) の構成。 grammar `[a-z0-9_]+` 適合。

A2. **`Period` UTC 厳密性 (Round 1 [Warning] 反映)**: `__post_init__` で tzinfo あり + `utcoffset() == timedelta(0)` を要求、 JST `+09:00` 等の non-UTC timezone-aware datetime も reject。

A3. **`Period` 半開区間 [start, end)**: `end > start` を `__post_init__` で強制 (= T072 規範踏襲、 同値 `end == start` も reject)。

A4. **`Partition` 10 領域構造**: `epoch_window` + 10 Period field (stage_b / stage_a / embargo_after_a / c_lite_1 / embargo_1 / c_lite_2 / embargo_2 / c_lite_3 / embargo_3 / stage_c)。 `all_periods` が時系列順 list を返し、 `c_lite_periods` が 3-tuple を返す。

A5. **`PartitionGenerator.generate` の deterministic 性**: window.start を起点に時系列順で 10 領域を切り出す。 同 window から常に同 Partition。 cursor 連続性 (gap / overlap なし) を save → assert で強制。

A6. **不変条件**: 10 領域合計 = 104w (62 + 8 + 1 + 6 + 1 + 6 + 1 + 6 + 1 + 12)、 timedelta 厳密一致。 window span !=104w で `PartitionMismatchError`。 cursor != window.end で `PartitionMismatchError` (二重 guard)。

A7. **`Fold` 連続性 (gap なし)**: `train.end == embargo.start` / `embargo.end == test.start` を `__post_init__` で強制。 `fold_index >= 0` も強制。

A8. **`FoldGenerator.generate` の rolling-origin**: fold k (k=0..4) が train 36w + embargo 1w + test 5w + step 5w で生成される。 train.start = stage_b.start + k * 5w。 末端 fold (k=4) test.end = stage_b.end と一致。

A9. **不変条件**: 5 fold 構造の最後 fold end = (5-1)*5 + 36 + 1 + 5 = 62w、 stage_b span !=62w で `FoldMismatchError`。 末端 test.end != stage_b.end で `FoldMismatchError` (二重 guard)。

A10. **label 検証**: `FoldGenerator.generate` が `stage_b.label != "stage_b"` で `ValueError`。 fold ラベルは `f"fold_{k}_{train|embargo|test}"` で動的生成 (Period.label に直接代入)。

C9 Falsification-first 原則に従い、 まず以下の **反証仮説** を探すことから始めよ:

- 仮説 H1: 「`PeriodLabel` の fold suffix base (FOLD_TRAIN / FOLD_EMBARGO / FOLD_TEST) は実コードで `Period.label` に直接代入されない (= `f"fold_{k}_train"` のように動的生成される)、 13 値中 3 値が dead code 化していないか」
- 仮説 H2: 「`PartitionGenerator.generate` は cursor 連続性を `_slice` 内で nonlocal cursor で保証しているが、 個別 Period の境界を直接 dataclass field として持つため、 万一 _slice 順序を間違えても type-check は通る (= 順序入れ替え regression 検出力の弱さ)」
- 仮説 H3: 「`Period` の UTC 厳密性 (utcoffset==0) は厳しすぎる。 真夏の DST shift で `+00:00` から逸脱するケースは UTC 自身では発生しないが、 caller が `astimezone()` を呼び忘れた場合 silent fail でなく早期 reject する設計になっている (= Defense-in-depth 妥当性)」
- 仮説 H4: 「`FoldGenerator.generate` は stage_b.start を起点に train_start を計算するが、 stage_b.start が EpochWindow.start と一致する保証は `PartitionGenerator.generate` 経由でのみ成立し、 caller が直接 Period を渡した場合は EpochWindow との接続が切れる (= partition → fold の chain でのみ正しい使用パターン)」
- 仮説 H5: 「34 test のうち、 `_canonical_24m_window()` / `_canonical_stage_b()` を共通 fixture として使い回しているため、 fixture 自体に bug があれば全 test が同方向に誤読する (C5 framing 独立性懸念)」
