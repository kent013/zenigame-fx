1. A・B・C 評価期間を強い根拠なしに延長する（過学習の隠蔽）

5. やたらに複雑な案を提案する（大規模リファクタリング、新フレームワーク導入等）
6. 取引回数を削減して見かけの成績を上げようとする（entry_threshold 過剰引き上げ等）
7. オーバーナイト保有前提の設計（スイングトレード化）
8. ゲノム archive スキーマ変更時の値伝搬漏れ（config → GaConfig → meta → consumer の 4 段接続漏れ）

## Round 2 で実施した修正

### Critical 1 対応 (defensive な except 追加)

`src/alpha_factory/calibrate_gate_history.py` の import に `SchemaContractError` を追加し、
`HistoryRecord.from_dict_or_none` の except 節を以下のように更新:

```python
from src.alpha_factory.schema_contract import (
    CALIBRATE_HISTORY_SCHEMA_VERSION,
    SchemaContractError,
    SchemaEnforcementMode,
    assert_calibrate_history_v2,
    validate_epoch_id,
)

@classmethod
def from_dict_or_none(cls, obj: Mapping[str, Any]) -> HistoryRecord | None:
    """v1 record (dataset_epoch_id 不在) は None を返す (skip 用).

    v2 record は ``cls(**obj)`` で構築。 不正 record (TypeError /
    ValueError / SchemaContractError) も None を返し、 caller 側で
    skip + warning。 ``SchemaContractError`` は ``ValueError`` 派生だが
    defensive に明示追記 (Codex impl-review-pr3 round 1 [Critical] 1)。
    """
    if "dataset_epoch_id" not in obj or not obj.get("dataset_epoch_id"):
        return None
    if obj.get("calibrate_history_schema_version") != (
        CALIBRATE_HISTORY_SCHEMA_VERSION
    ):
        return None
    try:
        return cls(**obj)
    except (TypeError, ValueError, SchemaContractError):
        return None
```

注: 実装上、 `schema_contract.py:71-72` で `class SchemaContractError(ValueError):` と定義されており
`except ValueError` は `SchemaContractError` も catch する。 ただし Round 1 指摘の通り、
defensive な明示記述は将来の class 継承変更に対する抗 fragile な保険となる。

加えて `from_dict_or_none` 単体の grammar 違反 catch を直接検証する

```python
def test_from_dict_or_none_returns_none_for_grammar_violation(self) -> None:
    rec = _record()
    from dataclasses import asdict as _asdict
```

### Warning 1 / 3 への対応判断

- **Warning 1** (`dataset_epoch_id` default の compat 弱さ): 設計 SSOT (詳細設計 行 922) では
  `dataset_epoch_id: str = ""` を採用する判断で、 `__post_init__` で reject する設計が前提。
  default 値は **dataclass 構築時の引数省略を許す** ためのものであり、 behavioral compat
  ではなく construction-time compat (= 既存の keyword 順序を変更しない) 目的。 設計通りなので
  維持。
- **Warning 3** (epoch_legacy 重複): PR 3 タスク指示で「RunContext 全 artifact propagate は
  PR 5 で実装」と定められており、 短期定数化は PR 5 で RunContext に統合する際に同時に
  解消される (= 現時点で `EPOCH_LEGACY` 定数を 1 個増やしても、 PR 5 で削除する重複工事
  になる)。 PR 5 の RunContext propagate でリゾルブする方針を維持。
