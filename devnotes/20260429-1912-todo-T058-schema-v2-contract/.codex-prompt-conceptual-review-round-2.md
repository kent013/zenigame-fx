## Round 2 — Round 1 修正反映

Round 1 [Critical] 4 件 + [Warning] 多数を反映した改訂版概念設計を提示する。 主要修正点:

1. **4 field 全経路必須は誤り** → artifact 別 contract に分割 (genome-entry / calibrate-history / run-report / diagnostics)、 共通必須は `dataset_epoch_id` のみ
2. **dataset_epoch_id 最上流供給源欠如** → `RunContext` (新規 dataclass) を T058 で導入、 値生成は T059 担当
3. **schema_version 名前衝突** → `cascade_contract_version` 別キー新設、 既存 summary.json `schema_version: "1.1"` は維持
4. **T058 単独 fail-closed で writer 全滅** → passive validation (log_only) で start、 T067 合流時に activate
5. **validator 配置 coverage 不足** → 10 artifact 経路 (Codex Round 1 で identify されたもの全部) を inventory 表で全列挙
6. **期待効果文言** → 「品質低下を検出可能」 から「層別観測可能」 に下方修正
7. **enum 永続値** → 全部 lower_snake_case (`mission_pass`, `c_lite`, etc)
8. **dataset_epoch_id grammar** → `^[a-z0-9_]+$`、 lowercase、 空文字禁止、 deterministic 一致

### 1. artifact 別 contract 分割の妥当性

| artifact | 必須 field |
|---|---|
| Parquet archive | dataset_epoch_id + genome_entry_schema_version + archive_role + source_stage |

これで artifact-class 別の意味論を保てているか。 抜けがあれば identify。

### 2. RunContext 設計の最上流性

`RunContext.dataset_epoch_id` を T059 で生成、 T058 では `RunContext` の構造定義 + 受け皿のみ。 全 component (GA loop, archive, calibrate, diagnostics, FSP, sieve) が同じ source から読む設計で、 4 段伝搬契約 (config → context → meta → consumer) は満たせるか。

### 3. passive → fail_closed 切替戦略

```python
def assert_genome_entry_v2(record: dict, mode: Literal["log_only", "fail_closed"] = "log_only") -> None:
    missing = GENOME_ENTRY_CONTRACT_V2 - record.keys()
    if missing:
        if mode == "fail_closed":
            raise SchemaContractError(f"missing fields: {missing}")
        else:
            logger.warning(...)
            _validation_failure_counter.inc()
```

config (`schema_contract.enforcement_mode`) で切替。 default `log_only`、 T067 合流時に `fail_closed` に変更。 これで T063/T066 前の writer 全滅を回避できるか。

### 4. enforcement_mode の運用

T058 段階で全 artifact passive、 T063 (Stage A 評価器) で source_stage="a" を書き始め、 T066 (Archive admission) で archive_role 書き込み開始。 T067 (Warmstart) 合流時に **enforcement_mode を fail_closed に切替**、 同時に旧 v1 archive を排除 (T075 で物理削除)。

この activation timing で incremental 移行できているか。
