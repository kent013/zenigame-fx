### q_force 動的計算

```python
def compute_q_force_base(feasible_ratio_ema: float) -> float:
    """synthesis § 5.1 確定式: q_force_base = clamp(0.15 + 0.15 × max(0, 0.10 - ratio)/0.10, 0.15, 0.30).

    feasible_ratio_ema 高い (>= 0.10) → q_force = 0.15 (探索集中)
    feasible_ratio_ema 低い (< 0.10) → q_force 引き上げ (供給確保)
    feasible_ratio_ema = 0.0 → q_force = 0.30 (最大供給)
    """
    deficit = max(0.0, Q_FORCE_FEASIBLE_RATIO_THRESHOLD - feasible_ratio_ema)
    raw = Q_FORCE_BASE + Q_FORCE_RANGE * (deficit / Q_FORCE_FEASIBLE_RATIO_THRESHOLD)
    return clamp(raw, Q_FORCE_BASE_MIN, Q_FORCE_BASE_MAX)


def compute_q_force_with_divergence(
    base_q_force: float,
    divergence_cycle_count: int,
) -> float:
    """synthesis § 8.7 確定式: A→B 乖離時に q_force_offset を加算.

    divergence_cycle_count: A→B 乖離が連続している Run 数 (negative=回復中、 zero=正常)
    - cycle_count > 0 (乖離中): q_force = base + 0.02 × cycle_count (上限 0.40)
    - cycle_count == 0 (正常): q_force = base
    - cycle_count < 0 (回復中、 corr>=0.5 戻し中): q_force = base + 0.02 × (回復前の cycle - |cycle_count|)
        実装上は controller が state で実値を管理、 本 helper は base + offset を返すのみ

    Returns:
        clamp(base_q_force + 0.02 × cycle_count, base_q_force, Q_FORCE_DIVERGENCE_MAX=0.40)
    """
    offset = Q_FORCE_DIVERGENCE_STEP * max(0, divergence_cycle_count)
    raw = base_q_force + offset
    return min(raw, Q_FORCE_DIVERGENCE_MAX)
```

### gate_score + hard_pass 判定

```python
def compute_gate_score(canonical_five_result: CanonicalFiveResult) -> float:
    """synthesis § 5.1: gate_score = 1 / (1 + worst_gap).

    worst_gap = canonical_five_result.gate_worst_gap
    - 全達成 → worst_gap=0 → gate_score=1.0 (max)
    - 1 指標未達 → worst_gap>0 → gate_score < 1.0
    - infeasible → gate_score 計算は不可、 caller (is_hard_pass) で別途排除
    """
    return 1.0 / (1.0 + canonical_five_result.gate_worst_gap)


def is_hard_pass(
    canonical_five_result: CanonicalFiveResult,
    trade_count: int,
    hard_floor_min_trades: int = HARD_FLOOR_MIN_TRADES,
) -> bool:
    """synthesis § 5.1 hard floor 判定: invariant feasible AND trades >= 2.

    Args:
        canonical_five_result: T061 評価結果
        trade_count: 当該個体の trade_count (T061 内に含まれる)
        hard_floor_min_trades: synthesis § 5.1 の「trades>=2」、 default 2

    Returns:
        True if invariant feasible AND trade_count >= hard_floor_min_trades
    """
    return (
        canonical_five_result.invariants.is_feasible
        and trade_count >= hard_floor_min_trades
    )
```

### 重要な設計判断

**1. T061 への直接依存 (T062 と同じ logical pipeline)**

- **採用**: T063 は T061 `CanonicalFiveResult` list を直接 input に取る
- **理由**: T061 が pure stateless engine、 T063 は state-ful controller。 T063 で T061 を再実装しない (synthesis § 5.5 「Stage A の gate_score は Stage A 専用ランキング」 だが、 metric 計算は T061 SSOT)

**2. trade_rate 評価の実装方針 (synthesis § 5.1 「trade_count は absolute でなく trade_rate」 の解釈)**

- **採用**: T063 が `StageAThresholds` を構築する際、 `trade_count_min/max` を Stage A window (8w) 比例した値に変換
- **理由**: T061 thresholds に Stage A 用の特別 mode を入れない。 T063 が caller として「8w 評価では trade_count [4, 384] 相当」 を T061 に渡す
- **代替案 (棄却)**: T061 自体に trade_rate モード追加 → T061 engine 単純性失う

**3. hard floor (trades>=2) の独立判定**

- **採用**: T063 内 `is_hard_pass(result, trade_count)` で判定、 T061 thresholds の trade_count_min とは独立
- **理由**: synthesis § 5.1 「絶対値判定なし、 trades>=2 の破綻排除のみ」 を素直に実装。 trade_count_min が window 比例で 4 になっても、 hard floor は固定値 2

**4. State 管理は Controller class (T061-T062 は pure、 T063 は state-ful)**

- **採用**: `StageAGateController` 内に `StageAControllerState` を保持
- **理由**: q_force_offset は Run 跨ぎで state を持つ。 pure function だけでは表現できない。 state はすべて immutable dataclass で管理
- **state persistence**: T067 (Loop closure) で archive metadata に保存する責務 (T063 PR では interface のみ)

**5. A-fail の完全排除は engine 側で signal 提供のみ**

- **採用**: T063 は `a_pass_indices: frozenset[int]` を返す、 a_fail individuals に追加情報を付けない
- **理由**: T065 (NSGA-II) で「A-fail 個体は Pareto 圧計算から除外」 は別経路で実装する責務 (T063 申し送り)
- **代替案 (棄却)**: T063 が a_fail individuals の `is_excluded_from_selection` flag を返す → T065 と responsibility 重複

**6. A→B 乖離 corr 計算の責務分離**

- **採用**: T063 は `update_a_b_divergence(corr)` で external に corr を受け取る、 corr 計算自体は別 module (T064 評価器側 or T071 observability)
