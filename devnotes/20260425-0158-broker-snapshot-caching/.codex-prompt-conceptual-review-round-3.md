### 差分（cache key 設計）

```
**実装の骨子**:
- `self._cached_snapshot: PortfolioSnapshot | None = None`
- `self._cache_valid: bool = False`
- `self._cached_bar_id: int | None = None`  # `id(bar)` を保持（Round 2 Critical 対応）
- `_snapshot_at(bar)` の最初で `cache_valid and id(bar) == cached_bar_id` なら cache hit → cached snapshot を即 return
(...)

**cache key 設計 (Round 2 Critical 対応)**:
- `bar.bar_time` 単独ではなく `id(bar)` で object identity を見る
- 理由: 同一 `bar_time` で異なる価格を持つ bar が入力される経路（重複タイムスタンプ・再サンプリング・データ補正）で stale を返すリスクを消すため
- `PriceBar` は frozen dataclass（`src/domain/price.py`）なので同一 object は必ず同一内容
- engine loop は同一 iteration 内で 3 経路すべて同一 reference を渡すため（P10）、cache hit は確実に発生する
- **安全側**: cache 書き込み時に `id(bar)` を記録し、次 iteration で異なる bar object が来た瞬間に cache miss となる
```
