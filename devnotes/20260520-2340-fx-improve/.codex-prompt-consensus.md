# 使命
config/alpha_factory/default.yaml の live_criteria を全て同時に満たす FX イントラデイ戦略個体を 1 つ見つけること。Stage C 通過は最低条件。

# FX 固有の絶対制約
- イントラデイ前提（オーバーナイト保有前提の設計は禁止）
- ロング・ショート両方向許容
- スワップ・スプレッド控除後の純利益で評価

# rejection rule（禁止事項に基づく即 REJECT）
1 評価期間延長 / 2 見かけの数値改善 / 4 live_criteria 緩和で stage 飛ばし / 6 取引回数削減で見かけ改善 / 7 オーバーナイト前提。ショート追加で見かけだけ改善していないかも点検。

# メタ過学習ガード（GA ハイパラ変更の分類必須）
date_pool は限定期間。同一データへの繰り返し数値調整はメタ過学習。
- Structural（新機能/新ガード追加）→ APPROVE 可
- Principled Parametric（理論・一般原則に基づく数値、根拠明示）→ APPROVE 可
- Reactive Parametric（「直近 Run で X が悪かったから Y を調整」）→ 原則 REJECT、構造的対策に変換を促す

# 候補レバー（Claude の暫定案、Codex が取捨選択）
- ①Stage B fold-CV に cost stress（spread×1.25 等）を前倒し → cost-fragile 個体を上流で filter（Structural）。リスク: Stage B pass 激減・variance 増。
- ②直近期間整合の selection 項（holdout に近い直近 fold の符号/PnL を selection_score に反映）→ regime drift 耐性（Structural）。リスク: recency 過学習。
- ③Stage B→C 汎化ギャップの diagnostic instrumentation（holdout 失敗が cost stress 由来か / 短窓低頻度由来か / regime drift 由来かを固定フォーマットで分解）。低リスク・情報価値高。

# 制約・方針
- 本ループは「フルサイズ・無制限 repeat・絶対に止まらない」。**loop 停止リスク（テスト破壊・大規模変更）を避け、低リスクを最優先**。cycle 1 は確実に前進する 1 つの最小変更が望ましい。
- improve-cycle 守備範囲: GA パラメータ軽量調整 / 新ガード追加 / バグ修正。プリミティブ大幅改良は範囲外。
