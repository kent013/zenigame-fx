## 1. 背景・課題

synthesis § 8.4-8.5 で確定した **Warmstart 注入** + **Emergency Mode** を zenigame-fx に big-bang 移植する。 T065/T066 で per-generation / per-Run 内の選抜・archive 操作は実装済、 T067 は **Run 間境界** (新 Run 開始時の population 構築 + 過去 archive からの warmstart 引継 + emergency mode 状態管理) を担う。

T067 が提供する責務 (Phase 1 = 単体 module + テストのみ、 既存 ga loop に未配線):

1. **Warmstart 候補抽出 (synthesis § 8.4)**:
   - 過去 archive (CA + DA) から warmstart_share% を選抜
   - ramp: run1=0% / run2=10% / run3=15% / run4+=20%
   - 通常 CA:DA = 26:12 (CA 寄り) / emergency CA:DA = 19:19 (1:1)
2. **多様性制約**:
   - `max_per_source_run=2`、 `max_per_session_pattern=2`、 `max_family=2`
   - 緩和順 (制約充足不能時): `session_pattern → source_run → family`
   - `max_reuse=3`、 `cooldown=2 Run`、 `rolling=10 Run`
3. **epoch-aware filter**:
   - `prev_epoch` 由来は最大 20% (Stage A quick recheck 通過時のみ、 caller 検証済)
   - `epoch_age >= 2` は warmstart 対象外
4. **Emergency mode 発動 (synthesis § 8.5)**:
   - 発動条件: `mission_pass=0` が 3 連続 AND `MA3(best_mission_signed_margin) < MA6(best_mission_signed_margin) - 0.05`
   - 動作: warmstart_share 20% → 25% (1 run のみ)、 CA:DA 比率 1:1
   - prev_epoch 制約 20% 上限は維持 (緊急時も緩めない)
   - 解除: `progress_pass >= 2` OR `best_mission_signed_margin >= MA6`
5. **WarmstartState 永続化**:
   - 過去 run の `mission_pass` / `best_mission_signed_margin` 履歴 (MA3 / MA6 計算用)
   - 個体ごとの `reuse_count` / `last_used_run` (cooldown 用)
   - emergency mode 直近状態 (1 run 限定の維持)
6. **T066 ArchiveCandidate 変換**:
   - T064 BCEvaluationResult + T062 MissionGapResult + T061 InvariantFlags + 個体メタ → T066 ArchiveCandidate を構築
   - T066 archive_admit に渡す入力契約整備
7. **DA admission 経路 (synthesis Round 22 改訂候補と同期)**:
   - warmstart 候補のうち DA 枠 (CA:DA = 26:12 / 19:19) は archive DA に直接 admission
   - T066 は CA admission only、 T067 が DA admission を担う設計

T067 が**触らない** (別 TODO 担当):

- archive admission/eviction 本体 — **T066**
- novelty / diversity_coverage / quality_floor_margin / margin_inf_passes_p70 計算本体 — **別 TODO** (zenigame `archives.py:compute_d_genome` / `compute_d_slack` 流用)
- calibrate-gate scope (epoch key / 凍結窓 / Δ 制限) — **T069**
- Failure handling (NaN/Inf / crash recovery) — **T068**
- A→B 乖離自動 q_force 引き上げ — **T071**
- run_ga.py 配線 — **Phase 2 別 PR (T065/T066/T067 同時)**
- observability (Run 間遷移 / warmstart entropy 等) — **T071**

       prev_archive, candidates, pop_size=pop_size,
       mode=prev_emergency.mode,
       new_dataset_epoch_id=new_dataset_epoch_id, new_run_id=run_id,
   )

3. DA admission (Round 2 [C4] eviction 含む 1 API):
   new_archive = admit_warmstart_to_da_with_eviction(
       new_archive_after_admit,
       warmstart_da_candidates=...,    # Run 開始時 selection.da_candidates
       pop_size=pop_size,
   )

4. Run 全体集計 (Round 1 [W1] SSOT、 BCEvaluationResult から直接、 admission_report ではなく):
   n_mission_pass = sum(1 for r in bc_results.values() if r.mission_pass == StagePassStatus.PASS)
   n_progress_pass = sum(1 for r in bc_results.values() if r.progress_pass == StagePassStatus.PASS)
   best_mssm = compute_best_mission_signed_margin(mission_gaps)

5. emergency state 更新:
   boost_consumed = is_boost_applicable(prev_emergency, run_id)   # 当 Run で boost 消費したか
   new_emergency = update_emergency_state(
       prev_emergency,
       new_run_id=run_id,
       n_mission_pass=n_mission_pass,
       n_progress_pass=n_progress_pass,
       best_mission_signed_margin=best_mssm,
       boost_consumed_in_this_run=boost_consumed,
   )

6. WarmstartState 更新:
   new_warmstart_state = update_warmstart_state(
       prev_warmstart_state,
       selected_genome_ids=selected_warmstart_genome_ids,
       new_run_history_index=new_run_history_index,
   )

出力:
- new_archive (T066 ArchiveState、 capacity 内)
- new_emergency_state
- new_warmstart_state
- admission_report (T066 出力)
```

注: emergency mode の判定タイミングは「Run 終了時に次 Run 用の判定」 を行う。 当 Run の mode は前 Run 終了時に確定済 (caller 引数で受け取る)。

### 5.2 EmergencyState (Round 1 [C1] / [S1] 反映、 mode + boost 2 変数分離)

```python
@dataclass(frozen=True)
class EmergencyHistoryEntry:
    """1 Run 分の emergency 判定指標.

    Round 1 [C3] / [W1] 反映: best_mission_signed_margin に名称統一、
    指標 source は Run 全体の bc_results / mission_gaps から集計済の値 (大が良).
    """
    run_id: str
    n_mission_pass: int                       # Run 全体 (T064 BCEvaluationResult.mission_pass==PASS の数)
    n_progress_pass: int                       # 同上 progress_pass==PASS
    best_mission_signed_margin: float          # = max over mission_gaps of mission_signed_margin


@dataclass(frozen=True)
class EmergencyState:
    """Emergency mode 状態 + 発動/解除判定用の履歴 (immutable).

    Round 1 [C1] / [S1] 反映: mode と boost_consumed_run_id を分離.
    - mode: 監視状態 (解除条件成立まで保持)
    - boost_consumed_run_id: 25%/1:1 boost を消費した run_id (None なら未消費)
    - boost 適用は当該 run_id 1 回限定、 mode 自体は解除条件成立まで保持.
    """
    mode: Literal["normal", "emergency"]
    activated_at_run_id: str | None             # emergency 発動 run_id
    boost_consumed_run_id: str | None           # boost (25%/1:1) を消費した run_id (1 run 限定)
    history: tuple[EmergencyHistoryEntry, ...]  # maxlen=10、 新が前


def is_boost_applicable(state: EmergencyState, current_run_id: str) -> bool:
    """当 Run で 25%/1:1 boost を適用すべきか.

    Round 1 [C1] 反映: boost は emergency mode 中の 1 run 限定 (発動直後の 1 Run のみ).
    """
    if state.mode != "emergency":
        return False
    if state.boost_consumed_run_id == current_run_id:
        return True   # 既に当 Run で boost 適用済 (= 同 run 内重複呼出時の冪等性)
    if state.boost_consumed_run_id is None:
        return True   # 未消費 → 当 Run で消費
    return False    # 別 Run で既に消費済 → boost 適用しない (mode は emergency のまま)
```

### 5.3 emergency mode 発動条件 (Round 1 [C3] / [W1] 反映)

```python
def evaluate_emergency_trigger(state: EmergencyState) -> bool:
    """発動条件: mission_pass=0 が 3 連続 AND MA3 < MA6 - 0.05.

    Round 1 [W1] 反映: n_mission_pass は Run 全体 BCEvaluationResult 集計値 (capacity 影響なし).
    Round 1 [C3] 反映: best_mission_signed_margin (大が良) で MA3/MA6 計算.
    """
    if len(state.history) < 6:
        return False    # MA6 計算不能、 sample size 不足

    last3 = state.history[:3]
    last6 = state.history[:6]

    # 1. mission_pass=0 連続 3 Run
    if not all(h.n_mission_pass == 0 for h in last3):
        return False

    # 2. MA3 < MA6 - 0.05
    ma3 = sum(h.best_mission_signed_margin for h in last3) / 3.0
    ma6 = sum(h.best_mission_signed_margin for h in last6) / 6.0
    return ma3 < ma6 - 0.05
```

### 5.4 emergency mode 解除条件

```python
def evaluate_emergency_release(state: EmergencyState) -> bool:
    """解除条件: progress_pass >= 2 OR best_mission_signed_margin >= MA6 (直近 entry のみ判定)."""
    if not state.history:
        return False
    if state.mode != "emergency":
        return False

    latest = state.history[0]
    if latest.n_progress_pass >= 2:
        return True

    if len(state.history) >= 6:
        ma6 = sum(h.best_mission_signed_margin for h in state.history[:6]) / 6.0
        return latest.best_mission_signed_margin >= ma6

    return False
```

### 5.5 emergency mode state 遷移 (Round 1 [C1] mode + boost 分離)

```python
def update_emergency_state(
    prev: EmergencyState,
    *,
    new_run_id: str,
    n_mission_pass: int,
    n_progress_pass: int,
    best_mission_signed_margin: float,
    boost_consumed_in_this_run: bool,        # 当 Run で boost を実際に消費したか (caller from is_boost_applicable)
) -> EmergencyState:
    """Run 終了時に history を append + mode 遷移 + boost_consumed_run_id 更新.

    Round 1 [C1] 反映: emergency 動作 (25%/1:1) は 1 run 限定、 mode flag は解除条件成立まで保持.
    boost_consumed_run_id は当 Run で boost 消費した場合に更新 (caller 引数).
    """
    new_entry = EmergencyHistoryEntry(
        run_id=new_run_id,
        n_mission_pass=n_mission_pass,
        n_progress_pass=n_progress_pass,
        best_mission_signed_margin=best_mission_signed_margin,
    )
    new_history = (new_entry,) + prev.history
    if len(new_history) > 10:
        new_history = new_history[:10]

    # boost_consumed_run_id 更新
    new_boost = (
        new_run_id if boost_consumed_in_this_run else prev.boost_consumed_run_id
    )
    new_state_pre = replace(prev, history=new_history, boost_consumed_run_id=new_boost)

    # mode 遷移
    if new_state_pre.mode == "normal":
        if evaluate_emergency_trigger(new_state_pre):
            return replace(
                new_state_pre,
                mode="emergency",
                activated_at_run_id=new_run_id,
                boost_consumed_run_id=None,    # 新規 emergency 発動時は未消費
            )
        return new_state_pre

    # mode == "emergency"
    if evaluate_emergency_release(new_state_pre):
        return replace(
            new_state_pre,
            mode="normal",
            activated_at_run_id=None,
            boost_consumed_run_id=None,
        )
    return new_state_pre
```

## 6. warmstart_share + CA:DA ratio 計算

### 6.1 ramp (synthesis § 8.4)

```python
RAMP_SHARES: dict[int, float] = {
    1: 0.00,
    2: 0.10,
    3: 0.15,
    # 4+: 0.20
}
WARMSTART_NORMAL_SHARE = 0.20
WARMSTART_EMERGENCY_SHARE = 0.25
WARMSTART_NORMAL_CA_RATIO = 26 / (26 + 12)   # = 26/38 ≈ 0.684
WARMSTART_EMERGENCY_CA_RATIO = 19 / (19 + 19)  # = 0.5

def compute_warmstart_ramp_share(run_no: int) -> float:
    """run_no (1-origin、 epoch 内) に応じた ramp 共有率."""
    if run_no < 1:
        raise ValueError(f"run_no must be >= 1, got {run_no}")
    if run_no in RAMP_SHARES:
        return RAMP_SHARES[run_no]
    return WARMSTART_NORMAL_SHARE   # run4+ デフォルト


def compute_warmstart_share_and_ratio(
    ramp_share: float,
    is_boost_applicable: bool,
) -> tuple[float, float]:
    """warmstart_share と CA 比率を返す (Round 1 [C1] / [S1] 反映: boost_applicable で 1 run 限定 boost 適用).

    通常 (boost 不適用): ramp_share (= 0.0/0.10/0.15/0.20)、 CA 比率 = 26/38
    boost 適用 (emergency 発動 1 run 目): 0.25 (ramp 無視)、 CA 比率 = 0.5

    is_boost_applicable は EmergencyState.is_boost_applicable() で判定.
    emergency mode が解除条件成立まで継続中でも、 boost を既に消費した run では
    通常 (ramp_share + 26:12) を返す (synthesis § 8.5 「1 run のみ動作」 厳密準拠).
    """
    if is_boost_applicable:
        return WARMSTART_EMERGENCY_SHARE, WARMSTART_EMERGENCY_CA_RATIO
    return ramp_share, WARMSTART_NORMAL_CA_RATIO
```

### 6.2 warmstart 体数の計算 (端数規約)

```python
def compute_warmstart_counts(
    pop_size: int,
    share: float,
    ca_ratio: float,
) -> tuple[int, int, int]:
    """warmstart 全体 / CA 枠 / DA 枠 の体数 (端数規約).

    - total = round(pop_size × share)
    - ca = round(total × ca_ratio)
    - da = total - ca
    """
    if pop_size not in SUPPORTED_POP_SIZES:    # T066 と共通
        raise ValueError(f"pop_size must be 192 or 256, got {pop_size}")
    if not (0.0 <= share <= 1.0):
        raise ValueError(f"share must be in [0, 1], got {share}")
    if not (0.0 <= ca_ratio <= 1.0):
        raise ValueError(f"ca_ratio must be in [0, 1], got {ca_ratio}")
    total = round(pop_size * share)
    ca = round(total * ca_ratio)
    da = total - ca
    return total, ca, da
```

### 7.3 緩和順序の擬似コード

```python
def _select_with_relaxation(
    candidates: Sequence[WarmstartCandidate],
    *,
    target: int,
    constraints_initial: dict[str, int],   # {"session_pattern": 2, "source_run": 2, "family": 2}
    relaxation_order: tuple[str, ...] = ("session_pattern", "source_run", "family"),
) -> list[WarmstartCandidate]:
    """制約緩和ループ. target 体に達するまで、 制約を順に緩和."""
    constraints = dict(constraints_initial)
    for cap_relax_round in range(len(relaxation_order) + 1):
        selected = _try_select_with_constraints(candidates, target, constraints)
        if len(selected) >= target:
            return selected[:target]
        if cap_relax_round < len(relaxation_order):
            key = relaxation_order[cap_relax_round]
            # 段階的緩和: 緩和倍率は **詳細設計で確定** (Round 1 [W4] / Round 2 [C3] / R7 残論点)
            # 概念設計では緩和順のみ確定 (session_pattern → source_run → family).
            constraints[key] = _relaxation_step(constraints[key])    # 詳細設計で実装
    # 最終: 全制約緩和でも target 未達 → 全候補から target 体 (足りなければ全部)
    return _try_select_with_constraints(candidates, target, {})[:target]


def _try_select_with_constraints(
    candidates: Sequence[WarmstartCandidate],
    target: int,
    constraints: Mapping[str, int],
) -> list[WarmstartCandidate]:
    """current 制約で target 体に達するまで貪欲選抜 (rank_score 順)."""
    selected = []
    pattern_count: Counter[str] = Counter()
    source_run_count: Counter[str] = Counter()
    family_count: Counter[str] = Counter()
    for c in candidates:    # rank_score 降順前提
        if len(selected) >= target:
            break
        # 制約チェック
        sp_cap = constraints.get("session_pattern", math.inf)
        sr_cap = constraints.get("source_run", math.inf)
        fa_cap = constraints.get("family", math.inf)
        if pattern_count[c.member.pattern_id] >= sp_cap:
            continue
        if source_run_count[c.member.run_id] >= sr_cap:
            continue
        if family_count[c.member.family_id] >= fa_cap:
            continue
        selected.append(c)
        pattern_count[c.member.pattern_id] += 1
        source_run_count[c.member.run_id] += 1
        family_count[c.member.family_id] += 1
    return selected
```

### 7.4 prev_epoch 由来 20% 上限 (caller 検証前提)

T067 では `prev_epoch_admitted_indices` (= caller が「Stage A quick recheck 通過した prev_epoch 由来 member の genome_id 集合」 を構築) を受け取り、 「該当しない prev_epoch 由来 member は除外」、 「該当する prev_epoch 由来 member の合計が warmstart_total × 20% 以下」 を保証。

```python
def _apply_epoch_filter(
    candidates: Sequence[WarmstartCandidate],
    *,
    new_dataset_epoch_id: str,
    prev_epoch_admitted_genome_ids: frozenset[str],
    warmstart_total: int,
) -> list[WarmstartCandidate]:
    """epoch_age + prev_epoch 20% 上限フィルタ."""
    prev_epoch_cap = int(warmstart_total * 0.20)
    filtered: list[WarmstartCandidate] = []
    prev_epoch_count = 0
    for c in candidates:
        # epoch_age 制限
        if c.member.dataset_epoch_id != new_dataset_epoch_id:
            # prev_epoch 由来
            if c.member.genome_id not in prev_epoch_admitted_genome_ids:
                continue    # Stage A quick recheck 不通過、 除外
            if prev_epoch_count >= prev_epoch_cap:
                continue
            prev_epoch_count += 1
        filtered.append(c)
    return filtered
```

`epoch_age >= 2` 除外は caller (T067 中の別 helper) で reuse_record 経由か archive_member.run_id の epoch 履歴で計算。 詳細設計で確定。

### 9.2 best_mission_signed_margin 計算 (emergency 判定用、 Round 1 [C3] 名称統一)

    Round 1 [C3] 反映: 名称を best_mission_signed_margin に統一 (best_mission_signed_margin は廃止).
    Round 1 [R1] 反映: T062 -inf sentinel が history に残ると MA 計算が壊れるため、
    SENTINEL_REPLACEMENT_FOR_HISTORY (= -1.0e6) で finite 化して返す.

    feasible 個体ゼロケース (全 mission_signed_margin == -inf) でも MA 計算が壊れない.
    """
    if not mission_gaps:
        return SENTINEL_REPLACEMENT_FOR_HISTORY

    finite_values = [
        g.mission_signed_margin if math.isfinite(g.mission_signed_margin) else SENTINEL_REPLACEMENT_FOR_HISTORY
        for g in mission_gaps.values()
    ]
    return max(finite_values)
```

### 10.1 admit_warmstart_to_da_with_eviction

```python
def admit_warmstart_to_da_with_eviction(
    archive: ArchiveState,
    warmstart_da_candidates: Sequence[WarmstartCandidate],
    *,
    pop_size: int,
) -> ArchiveState:
    """warmstart 由来 DA candidates を archive DA に注入 + DA eviction まで 1 API で完結.

    Round 1 [C4] / [S4] 反映: 戻り値が常に capacity 内 (不正状態の中間 ArchiveState を露出しない).

    手順:
    1. warmstart_da_candidates の各 ArchiveMember を archive_target="DA" に書換 (既存 upsert)
    2. genome_id 一意制約維持 (T066 § 10)
    3. T066 archive_evict_da で DA capacity 内に収める

    手順 1 で archive 既存 member の archive_target を移動するだけ (新規 ArchiveMember を作らない).
    これにより同一 genome を CA / DA 同時保持しない invariant が維持される.
    """
    if not warmstart_da_candidates:
        return archive

    # 1-2. archive_target = "DA" 書換 + upsert
    existing_by_id: dict[str, ArchiveMember] = {m.genome_id: m for m in archive.members}
    for c in warmstart_da_candidates:
        m = c.member
        if m.archive_target != "DA":
            existing_by_id[m.genome_id] = replace(m, archive_target="DA")
        else:
            existing_by_id[m.genome_id] = m
    intermediate = replace(archive, members=tuple(existing_by_id.values()))

    # 3. DA eviction (T066) で capacity 内に
    _, _, da_capacity = compute_archive_capacities(pop_size)   # T066 export
    return archive_evict_da(intermediate, target_size=da_capacity)
```

注: T066 archive_evict_da は既に実装済 (T066 § 9.2)、 T067 では呼び出すだけ。 これにより T067 戻り値は常に T066 ArchiveState 不変条件 (capacity 内) を満たす。

T066 概念設計 § R8 (Round 22 改訂候補) で「3 層流入は CA admission、 DA admission は warmstart 経路」 を synthesis に明文化することを T067 PR と同時に提案。 T067 詳細設計では Round 22 改訂を前提に implementation 確定。
