```

- mission_gaps: Mapping[str, MissionGapResult]    # T062 出力
- invariant_flags: Mapping[str, InvariantFlags]   # T061 出力

           invariant_flags[genome_id], genome_metadata[genome_id],

           margin_inf_passes_p70=margin_inf_passes_p70[genome_id],

       prev_archive, candidates,

       new_dataset_epoch_id=new_dataset_epoch_id,
       new_run_id=run_id,

       prev_emergency,

### 5.3 emergency mode 発動条件

```python
def evaluate_emergency_trigger(state: EmergencyState) -> bool:
    """発動条件: mission_pass=0 が 3 連続 AND MA3 < MA6 - 0.05."""
    if len(state.history) < 6:
        return False    # MA6 計算不能、 sample size 不足

    last3 = state.history[:3]
    last6 = state.history[:6]

    # 1. mission_pass=0 連続 3 Run
    if not all(h.n_mission_pass == 0 for h in last3):
        return False

    # 2. MA3(best_margin_inf) < MA6(best_margin_inf) - 0.05
    ma3 = sum(h.best_margin_inf for h in last3) / 3.0
    ma6 = sum(h.best_margin_inf for h in last6) / 6.0
    return ma3 < ma6 - 0.05
```

### 5.4 emergency mode 解除条件

```python
def evaluate_emergency_release(state: EmergencyState) -> bool:
    """解除条件: progress_pass >= 2 OR best_margin_inf >= MA6."""
    if not state.history:
        return False
    if state.mode != "emergency":
        return False    # already normal

    latest = state.history[0]
    if latest.n_progress_pass >= 2:
        return True

    if len(state.history) >= 6:
        ma6 = sum(h.best_margin_inf for h in state.history[:6]) / 6.0
        return latest.best_margin_inf >= ma6

    return False
```

### 5.5 emergency mode state 遷移 (1 run 限定維持)

```python
def update_emergency_state(
    prev: EmergencyState,
    *,
    new_run_id: str,
    n_mission_pass: int,
    n_progress_pass: int,
    best_margin_inf: float,
) -> EmergencyState:
    """1 Run 終了時に history を append + mode 遷移を判定.

    emergency 動作は 1 run 限定 (synthesis § 8.5)、 すなわち発動した次 Run で:
    - 解除条件成立: normal に戻る
    - 解除条件未成立: 「emergency 1 run 限定」 を厳格適用するなら自動 normal に戻る
    - 設計判断: 解除条件成立まで emergency を維持 (= 「1 run のみ動作」 は warmstart_share/CA:DA
      の動作話、 mode flag は条件成立まで保持)
    """
    new_entry = EmergencyHistoryEntry(
        run_id=new_run_id,
        n_mission_pass=n_mission_pass,
        n_progress_pass=n_progress_pass,
        best_margin_inf=best_margin_inf,
    )
    new_history = (new_entry,) + prev.history
    if len(new_history) > 10:
        new_history = new_history[:10]

    new_state_pre = replace(prev, history=new_history)

    # mode 遷移 (順序: 発動 → 解除)
    if new_state_pre.mode == "normal":
        if evaluate_emergency_trigger(new_state_pre):
            return replace(new_state_pre, mode="emergency", activated_at_run_id=new_run_id)
        return new_state_pre

    # mode == "emergency"
    if evaluate_emergency_release(new_state_pre):
        return replace(new_state_pre, mode="normal", activated_at_run_id=None)
    return new_state_pre
```

## 6. warmstart_share + CA:DA ratio 計算

### 6.1 ramp (synthesis § 8.4)

```python
RAMP_SHARES: dict[int, float] = {
    1: 0.00,
    2: 0.10,
    3: 0.15,
    # 4+: 0.20
}
WARMSTART_NORMAL_SHARE = 0.20
WARMSTART_EMERGENCY_SHARE = 0.25
WARMSTART_NORMAL_CA_RATIO = 26 / (26 + 12)   # = 26/38 ≈ 0.684
WARMSTART_EMERGENCY_CA_RATIO = 19 / (19 + 19)  # = 0.5

def compute_warmstart_ramp_share(run_no: int) -> float:
    """run_no (1-origin、 epoch 内) に応じた ramp 共有率."""
    if run_no < 1:
        raise ValueError(f"run_no must be >= 1, got {run_no}")
    if run_no in RAMP_SHARES:
        return RAMP_SHARES[run_no]
    return WARMSTART_NORMAL_SHARE   # run4+ デフォルト


def compute_warmstart_share_and_ratio(
    ramp_share: float,
    is_emergency: bool,
) -> tuple[float, float]:
    """warmstart_share と CA 比率を返す.

    通常: ramp_share (= 0.0/0.10/0.15/0.20)、 CA 比率 = 26/38
    emergency: 0.25 (固定、 ramp 無視)、 CA 比率 = 0.5
    """
    if is_emergency:
        return WARMSTART_EMERGENCY_SHARE, WARMSTART_EMERGENCY_CA_RATIO
    return ramp_share, WARMSTART_NORMAL_CA_RATIO
```

### 6.2 warmstart 体数の計算 (端数規約)

```python
def compute_warmstart_counts(
    pop_size: int,
    share: float,
    ca_ratio: float,
) -> tuple[int, int]:
    """warmstart 全体 / CA 枠 / DA 枠 の体数 (端数規約).

    - total = round(pop_size × share)
    - ca = round(total × ca_ratio)
    - da = total - ca
    """
    if pop_size not in SUPPORTED_POP_SIZES:    # T066 と共通
        raise ValueError(f"pop_size must be 192 or 256, got {pop_size}")
    if not (0.0 <= share <= 1.0):
        raise ValueError(f"share must be in [0, 1], got {share}")
    if not (0.0 <= ca_ratio <= 1.0):
        raise ValueError(f"ca_ratio must be in [0, 1], got {ca_ratio}")
    total = round(pop_size * share)
    ca = round(total * ca_ratio)
    da = total - ca
    return total, ca, da
```

### 7.3 緩和順序の擬似コード

```python
def _select_with_relaxation(
    candidates: Sequence[WarmstartCandidate],
    *,
    target: int,
    constraints_initial: dict[str, int],   # {"session_pattern": 2, "source_run": 2, "family": 2}
    relaxation_order: tuple[str, ...] = ("session_pattern", "source_run", "family"),
) -> list[WarmstartCandidate]:
    """制約緩和ループ. target 体に達するまで、 制約を順に緩和."""
    constraints = dict(constraints_initial)
    for cap_relax_round in range(len(relaxation_order) + 1):
        selected = _try_select_with_constraints(candidates, target, constraints)
        if len(selected) >= target:
            return selected[:target]
        if cap_relax_round < len(relaxation_order):
            key = relaxation_order[cap_relax_round]
            constraints[key] = constraints[key] * 2    # 段階的緩和 (例: 2 → 4)
    # 最終: 全制約緩和でも target 未達 → 全候補から target 体 (足りなければ全部)
    return _try_select_with_constraints(candidates, target, {})[:target]


def _try_select_with_constraints(
    candidates: Sequence[WarmstartCandidate],
    target: int,
    constraints: Mapping[str, int],
) -> list[WarmstartCandidate]:
    """current 制約で target 体に達するまで貪欲選抜 (rank_score 順)."""
    selected = []
    pattern_count: Counter[str] = Counter()
    source_run_count: Counter[str] = Counter()
    family_count: Counter[str] = Counter()
    for c in candidates:    # rank_score 降順前提
        if len(selected) >= target:
            break
        # 制約チェック
        sp_cap = constraints.get("session_pattern", math.inf)
        sr_cap = constraints.get("source_run", math.inf)
        fa_cap = constraints.get("family", math.inf)
        if pattern_count[c.member.pattern_id] >= sp_cap:
            continue
        if source_run_count[c.member.run_id] >= sr_cap:
            continue
        if family_count[c.member.family_id] >= fa_cap:
            continue
        selected.append(c)
        pattern_count[c.member.pattern_id] += 1
        source_run_count[c.member.run_id] += 1
        family_count[c.member.family_id] += 1
    return selected
```

### 7.4 prev_epoch 由来 20% 上限 (caller 検証前提)

T067 では `prev_epoch_admitted_indices` (= caller が「Stage A quick recheck 通過した prev_epoch 由来 member の genome_id 集合」 を構築) を受け取り、 「該当しない prev_epoch 由来 member は除外」、 「該当する prev_epoch 由来 member の合計が warmstart_total × 20% 以下」 を保証。

```python
def _apply_epoch_filter(
    candidates: Sequence[WarmstartCandidate],
    *,
    new_dataset_epoch_id: str,
    prev_epoch_admitted_genome_ids: frozenset[str],
    warmstart_total: int,
) -> list[WarmstartCandidate]:
    """epoch_age + prev_epoch 20% 上限フィルタ."""
    prev_epoch_cap = int(warmstart_total * 0.20)
    filtered: list[WarmstartCandidate] = []
    prev_epoch_count = 0
    for c in candidates:
        # epoch_age 制限
        if c.member.dataset_epoch_id != new_dataset_epoch_id:
            # prev_epoch 由来
            if c.member.genome_id not in prev_epoch_admitted_genome_ids:
                continue    # Stage A quick recheck 不通過、 除外
            if prev_epoch_count >= prev_epoch_cap:
                continue
            prev_epoch_count += 1
        filtered.append(c)
    return filtered
```

`epoch_age >= 2` 除外は caller (T067 中の別 helper) で reuse_record 経由か archive_member.run_id の epoch 履歴で計算。 詳細設計で確定。

## 10. DA admission 経路 (T066 連携)

### 10.1 admit_warmstart_to_da

```python
def admit_warmstart_to_da(
    archive: ArchiveState,
    warmstart_da_candidates: Sequence[WarmstartCandidate],
    *,
    new_run_id: str,
    new_dataset_epoch_id: str,
) -> ArchiveState:
    """warmstart 由来 DA candidates を archive DA に直接注入.

    Phase 1 では:
    - warmstart_da_candidates は WarmstartCandidate.member (= 既存 ArchiveMember) を持つ
    - 既存 member の archive_target が "DA" でない場合 (CA → DA 移動) は upsert で archive_target="DA" に書換
    - genome_id 一意制約維持 (T066 ArchiveState 契約)
    - DA capacity 超過分は T066 archive_evict_da で別途処理 (T067 内では実施しない)
    """
    if not warmstart_da_candidates:
        return archive
    existing_by_id: dict[str, ArchiveMember] = {m.genome_id: m for m in archive.members}
    for c in warmstart_da_candidates:
        m = c.member
        # archive_target を "DA" に書換、 run_id 等は維持 (warmstart 由来でも origin run_id 保持)
        if m.archive_target != "DA":
            existing_by_id[m.genome_id] = replace(m, archive_target="DA")
        else:
            existing_by_id[m.genome_id] = m
    new_members = tuple(existing_by_id.values())
    return replace(archive, members=new_members)
```

注: warmstart 由来の DA admission では、 archive 既存 member の archive_target を移動するだけ (新規 ArchiveMember を作らない)。 これにより同一 genome を CA / DA 同時保持しない invariant (T066 § 10) が維持される。

## 13. 残論点 / Decision Pending

### R1: best_margin_inf の sentinel 処理

- mission_signed_margin は T062 で `feasible=False → -inf` の sentinel
- emergency 判定の MA3 / MA6 計算で -inf が混入すると壊れる
- 案 A: -inf を finite な大きな負値 (-1e6 等) に置換
- 案 B: feasible 個体のみで MA を計算、 全個体 infeasible なら history に -inf を記録
- 案 C: feasible 個体 1 体未満なら emergency 自動発動 (mission_pass=0 だが、 ma 計算は skip)
- 詳細設計で案 A or B を確定 (smoke 観測 R1)

### R2: emergency 1 run 限定の解釈

- synthesis § 8.5 「1 run のみ動作」 の意味が 2 解釈:
  - 解釈 1: warmstart_share 25% / CA:DA 1:1 は 1 run 限定、 mode flag は解除条件成立まで保持
  - 解釈 2: emergency mode 自体が 1 run 限定、 解除条件未成立でも自動 normal に戻る
- 採用案: **解釈 1** (synthesis 全体整合性、 解除条件の存在意義から)
- 詳細設計で確定、 synthesis 改訂候補としては明文化

### R3: prev_epoch_admitted_genome_ids の caller 構築

- T067 では引数で受け取る (Stage A quick recheck 通過の判定は別経路)
- caller (Phase 2 run_ga.py) で T063 stage_a_evaluator の結果から構築
- 詳細設計でこの責務分担を確定

### R4: cooldown / max_reuse の状態継承

- WarmstartState.reuse_records は archive member 全員分必須か、 利用済 member のみか?
- 案 A: 全 member 分 (capacity と一致、 reuse_count=0 含む) — メモリ overhead
- 案 B: 利用履歴ある member のみ — null 比較が必要
- 採用案: **案 B**、 reuse_record は warmstart で「利用された member」 のみ記録、 default は reuse_count=0 + last_used_run_id=None
- 詳細設計で確定

### R5: rank_score の計算源

- WarmstartCandidate.rank_score は CA / DA で別計算が必要:
  - CA 寄り: mission_signed_margin 降順 (T062)
  - DA 寄り: novelty 降順 (caller 計算)
- 詳細設計で計算 helper を内蔵 (caller 計算済 score を引数で受ける案も検討)

### R6: synthesis Round 22 改訂候補との同期 PR タイミング

- synthesis § 8.2 「3 層流入」 の CA / DA 解釈を Round 22 で改訂候補
- T067 PR と同時に synthesis 改訂 PR を出すか、 T067 PR merge 後に出すか
- 詳細設計で synthesis 改訂 PR の鳴動条件を確定

### R7: relaxation 段階の倍率 (× 2 vs 別係数)

- synthesis § 8.4 「緩和順 session_pattern → source_run → family」 のみ明記、 緩和倍率は不明
- 仮: × 2 (例: 2 → 4)、 INCONCLUSIVE
- smoke 後再校正候補

### R8: T064 BCEvaluationResult.c_pass_depth field の依存

- T066 / T067 共通 Phase 0
- T067 詳細設計より先に T064 follow-up PR が必要
