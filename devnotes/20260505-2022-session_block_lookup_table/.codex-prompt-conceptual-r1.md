# 概念設計: `compute_bucket_for_bar` の hour-indexed O(1) lookup table 化

## 背景・課題
profile (`profile_20260505_201359` cycle 1/3 後 baseline):
- `compute_bucket_for_bar` line 304: tottime **0.703s / 1,777,180 calls / 0.40 μs/call** (eval 内 3.5%)
- 本番投影 ×295.9 = 208s = 3.5 分

現実装 (line 322-329) は `BLOCK_BUCKET_RANGES_UTC.items()` を 24h ループで bucket 判定。

## 改善アイデア
import レベルで 24 要素 tuple `_HOUR_TO_BUCKET` を構築 → `_HOUR_TO_BUCKET[bar_time.hour]` で O(1) lookup。

```python
_HOUR_TO_BUCKET: Final[tuple[SessionBlockBucket, ...]] = _build_hour_to_bucket()

def compute_bucket_for_bar(bar_time: datetime) -> SessionBlockBucket:
    if bar_time.tzinfo is None: raise ValueError(...)
    if bar_time.utcoffset() != timedelta(0): raise ValueError(...)
    return _HOUR_TO_BUCKET[bar_time.hour]
```

`_build_hour_to_bucket()` は import 時に partition violation 検出 (per-call check 不要)。

## 期待効果
- per-call 0.40 → 0.05-0.1 μs (75-87% 削減)
- profile 0.703s → 0.1-0.18s (~80%)
- 本番 RUN -3 分 = -3% 削減

## 実装方針
- 1 ファイル (`src/backtest/session_block.py`) に lookup table + builder 追加
- `compute_bucket_for_bar` 本体を index 参照に置換、 validation は維持
- partition violation 検出が per-call → startup 化 (改善)

## 数値同値性
- 同 hour → 同 bucket (SSOT 不変)
- tzinfo/UTC offset validation 完全維持
- 既存 test 全 pass

## 制約・前提
- FX 絶対制約に影響なし
- メモリ 24 要素 tuple ~200 bytes
- BLOCK_BUCKET_RANGES_UTC SSOT 維持
- import 副作用は循環 import の懸念検証要

## スコープ外
- broker mock Decimal、 DSL composite kernel、 per-bar logging、 aggregate_session_blocks 等
