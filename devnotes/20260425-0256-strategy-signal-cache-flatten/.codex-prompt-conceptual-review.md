## 背景・課題

### Cycle 1 の経緯

`zenigame-fx-profile-optimize` Cycle 1 で MockBroker `_snapshot_at` を per-bar cache 化した (T028, merged `0095910`)。baseline 5.303s → 4.573s (-13.8%)、`_snapshot_at` cumtime -60.0% を達成。

Cycle 1 完了後の baseline profile (`profile_20260425_025427`, T028 merged, 5.181s) で hotspot を再測定した結果、**`DslStrategy._signal_cache_key` + `_lookup_signal` の合計で profile の 10.4%** を占めることが判明した。

### 根本原因

Cycle 1 で導入した prepare() / on_bar の実装が、**bar ごとに `sorted(sig.params.items())` を再計算**している:

```python
# src/dsl/strategy.py (現状)
def _signal_cache_key(sig):
    return (sig.name, tuple(sorted(sig.params.items())))  # <- 毎回 sorted

def _lookup_signal(self, sig, idx):
    key = _signal_cache_key(sig)                          # <- 732k 回
    arr = self._precomputed[key]                          # <- dict lookup
    ...

def on_bar(self, bar, snapshot):
    ...
    for clause in clauses:
        for sig in clause.directional:
            vals[sig.name] = self._lookup_signal(sig, idx)  # <- per-bar, per-sig
```

`SignalConfig.params` は frozen dataclass の dict（immutable contents だが dict 自体の items order は不定）なので、**prepare() 時に 1 回計算して cache すれば再計算不要**な値が per-bar per-sig で計算されている。これは sig.params の中身が backtest 中に変わらないことから純粋な無駄仕事。

### プロファイル証拠（Facts）

| 関数 | ncalls | tottime | cumtime | 全体比率 |
|---|---|---|---|---|
| `strategy._signal_cache_key` | 731952 | 0.184s | 0.316s | 3.5% (tottime) |
| `strategy._lookup_signal` | 731901 | 0.357s | 0.733s | 6.9% (tottime) |
| **合計** | — | **0.541s** | — | **10.4%** |

731901 ≈ 731952 = 258318 bars × ~2.83 signals/bar = genome の平均 clause×sig 数の展開。

### 本番外挿（pop=40 gen=15 180 日窓、scale ~348×）

- `_signal_cache_key` + `_lookup_signal` 合計: 0.541s × 348 ≈ **188 秒/RUN (3.1 分)**
- 期待削減 70-80%: **130-150 秒/RUN**

## 改善アイデア

### 本質の観察

1. `sig.params` は GA random_gen で生成された後、mutate / crossover 段階を経ても backtest 実行中は**不変**（SignalConfig は frozen dataclass + params dict は defensive copy 済み）
2. prepare() の時点で全 signal の list が確定しているため、そこで key を先に計算し、clause-indexed flat list に展開すれば bar loop で再計算不要
3. consumer (`compute_composite`) は `values_per_clause: list[dict[str, float]]` を受け取るだけ、その生成経路は自由

### 戦略: prepare-time signal flattening

**A. prepare() で flat list を構築**

```python
def prepare(self, bars):
    if not hasattr(self._evaluator, "evaluate_all_bars"):
        return
    # (name, params_key) -> ndarray の dict を維持（重複 signal の共有）
    arrays: dict[tuple[str, tuple[tuple[str, float|int], ...]], np.ndarray] = {}
    # clause index -> (directional_list, gate_list) の flat 構造
    # 各 list は (sig.name, arr) の tuple を index 順に保持
    self._precomputed_clauses: list[tuple[
        list[tuple[str, np.ndarray]],  # directional
        list[tuple[str, np.ndarray]],  # local_gate
    ]] = []
    for clause in self._genome.clauses:
        dir_list = []
        for sig in clause.directional:
            key = (sig.name, tuple(sorted(sig.params.items())))  # ← prepare 内のみ
            if key not in arrays:
                arrays[key] = self._evaluator.evaluate_all_bars(bars, sig)
            dir_list.append((sig.name, arrays[key]))
        gate_list = []
        for sig in clause.local_gate:
            key = (sig.name, tuple(sorted(sig.params.items())))
            if key not in arrays:
                arrays[key] = self._evaluator.evaluate_all_bars(bars, sig)
            gate_list.append((sig.name, arrays[key]))
        self._precomputed_clauses.append((dir_list, gate_list))
    self._precomputed = arrays  # backward compat (既存 test で参照)
    self._bar_count = 0
```

**B. on_bar() で flat list を直接 iterate**

```python
def on_bar(self, bar, snapshot):
    if self._precomputed is not None:
        idx = self._bar_count
        self._bar_count += 1
        if idx < self._warmup:
            return []
    else:
        # 従来 path（live feed 互換）
        ...

    values_per_clause = []
    if self._precomputed is not None:
        # flat list path (fast): 732k calls の sorted() + dict lookup を排除
        for dir_list, gate_list in self._precomputed_clauses:
            vals = {}
            for name, arr in dir_list:
                v = float(arr[idx]) if 0 <= idx < len(arr) else 0.0
                vals[name] = 0.0 if not math.isfinite(v) else v
            for name, arr in gate_list:
                v = float(arr[idx]) if 0 <= idx < len(arr) else 0.0
                vals[name] = 0.0 if not math.isfinite(v) else v
            values_per_clause.append(vals)
    else:
        # 従来 path（prepare 未呼出）
        for clause in self._genome.clauses:
            vals = {}
            for sig in clause.directional:
                vals[sig.name] = self._evaluator.evaluate(self._bars, idx, sig)
            for sig in clause.local_gate:
                vals[sig.name] = self._evaluator.evaluate(self._bars, idx, sig)
            values_per_clause.append(vals)

    composite = compute_composite(self._genome.clauses, values_per_clause)
    ...
```

**C. `_signal_cache_key` / `_lookup_signal` の扱い**

- `_signal_cache_key` は prepare() 内ローカルに直接埋め込み（module-level 関数として残すか、helper を引っ込めるかは detailed design で判断）
- `_lookup_signal` は on_bar 内で inline 化 → method としては削除（または private helper として残すが hot path から排除）

## 制約・前提

### FX 絶対制約（不変）
- イントラデイ / long-short / swap・spread: **全て broker + engine 側のロジックで担保**（本変更は影響なし）

### Selection invariance（最優先成功基準）
- prepare() で作られる `arrays[key]` は既存の `self._precomputed[key]` と同じ ndarray
- on_bar の prepared path は「cache lookup → `arr[idx]`」という処理を**同じ arr object / 同じ idx で行う**ため、float 値は bit-identical
- `vals` dict の構造・key は不変

### live feed 互換
- prepare() を呼ばない path（paper_trading / LiveBarFeed）は `self._precomputed` も `self._precomputed_clauses` も None のまま
- `on_bar` の非 prepared branch は従来通り `self._evaluator.evaluate` を呼ぶ

### メモリ制約
- flat list の追加 memory: clause 数 × sig 数 × 16 bytes (tuple) ≈ 数 KB 以下/broker
- 負担は事実上ゼロ

### Look-ahead bias
- ndarray 参照は変わらない。idx も変わらない → 該当なし
