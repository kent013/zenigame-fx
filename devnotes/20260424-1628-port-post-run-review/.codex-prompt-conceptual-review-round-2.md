## 主要差分 (修正後 §2.3a / §2.6 / §2.8 抜粋)

### §2.3a 新規: review-theme → TODO theme マッピング

| review-theme (post-run-review 引数) | 対応 TODO theme (`todo-add` の `--theme`) | 補足 |
|---|---|---|
| `signal-quality` | `primitives` | プリミティブ予測力・ルックアヘッド・新規プリミティブ |
| `regime-awareness` | `cross-pair` | アンカー / ii-lite / common factor / regime gate |
| `cost-efficiency` | `ga-architecture` | spread / slippage / swap / session_close は GA 評価関数側 |
| `robustness` | `statistics` | DSR / PBO / Sieve / WF |
| `risk-management` | `stage-gate` | live_criteria 達成パスを左右する gate / max_pos / time_stop |

post-run-review 内では引数として `signal-quality` 等を受け取り、`todo-add` 呼び出し時に上表の TODO theme へ変換する。

`has-open-theme` 等価判定:
```bash
# Open TODO のうち summary が "[review:{review-theme}]" prefix を持つものを 1 件以上検出すれば skip
uv run python scripts/alpha_factory/todo_manager.py list  | jq '[.open[] | select(.summary | startswith("[review:signal-quality]"))] | length'
```
post-run-review 経由で追加する TODO は summary 先頭に `[review:{review-theme}]` prefix を付与する規約とする (todo_manager 改修不要、概要 30 文字制約に注意 → 実装時に調整)。

### §2.6 重複チェックと TODO 追加の atomic 化代替

- post-run-review 単一セッション内では **Phase 3 で 1 案ずつ /zenigame-fx-todo-add を順次実行**。並列実行しない。
- 異なるテーマの 5 並列 Agent 間で同タイミングに `next-id` を引いた場合の race を以下で吸収:
  - improve-cycle (launcher) は **5 Agent を逐次起動** (run_in_background でも 1 秒ずつずらして起動)。完全並列ではなく micro-stagger で衝突確率を下げる
  - 各 Agent は `next-id` 取得直後に `todo_manager.py add` を呼び、衝突時 (重複 ID error) は最大 3 回リトライ
  - 万が一の重複行は次 cycle 1-2 重複チェックで検出 → obsolete で吸収
- todo_manager.py に lock 付き `add-auto` を追加する案は **別 TODO** に切り出す (本 TODO は md only)

### §2.8 hook owner 単一化

- **Launch owner = `zenigame-fx-improve-cycle` Phase 1 末尾のみ**
- `zenigame-fx-analyze-run` SKILL.md は「改善案 hook の標準起動点はここではなく improve-cycle Phase 1 末尾」と注記のみ復活させ、**起動コードは追加しない**
- 同一 run_id 再起動禁止: improve-cycle が起動前に `.cache/alpha_factory/post-run-review-launched-{run_id}.json` を書き、既存なら skip
- run 単位サマリ: 各 Agent 完了時に `.cache/alpha_factory/post-run-review-summary-{run_id}.md` に追記 (launched / failed / skipped 1 行)
- 接続点コメント書き換えは improve-cycle / analyze-run 双方で行うが、**実起動ブロックは improve-cycle のみ**
