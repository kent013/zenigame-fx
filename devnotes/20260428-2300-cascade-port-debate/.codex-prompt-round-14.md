## Claude の反論・突き詰めポイント

### 反論 1: CA/DA 進化母集団分割の具体形

Round 11 では `pop=256` を CA/DA 分割すると提案。 ただし CA と DA の役割分担と分割比率が要決定:

**CA (Convergence Archive)**: feasible region に近い個体 (= mission_inf_gap 小) を保護
**DA (Diversity Archive)**: phenotype/genotype 多様性個体を保護

進化母集団分割の選択肢:
- (a) **pop 256 = CA 128 + DA 128** (均等)
- (b) **pop 256 = CA 160 + DA 96** (push 期は均等寄り、 pull 期は CA 寄り)
- (c) **pop 256 = CA 96 + DA 160** (探索重視)
- (d) **pop 256 単一** (CA/DA 区別なし、 外部 archive のみ分離)

zenigame T509 の動作: Push phase は両方均等、 Pull phase は CA 寄り。 fx で同じ logic で良いか。

**Claude の主張**: (b) を Push/Pull で動的調整。 Push 期: CA 128 + DA 128、 Pull 期: CA 160 + DA 96 (動的シフト)。

Codex の見解は？ 進化母集団分割の biology (どの個体を CA に置き、 どれを DA に置くかの判定基準) を明確化してほしい。

### 反論 2: Push/Pull 切替条件の具体式

Round 11 提案: `feasible_ratio_ema >= 0.15` で push→pull、 安全弁 `gen >= 10` (旧 pop=40 用)

pop=256, gen=64 では:
- gen=64 / 4 phase ≈ 16 gen/phase で multi-state も viable
- ただし one-switch (push→pull のみ) で十分か、 multi-state (push → bridge → pull → refine) が要るか

**Claude の主張**: 4-state FSM を提案:
1. **explore** (gen 0-15): infeasible 領域も許す push、 diversity 重視
2. **bridge** (gen 16-30): feasible 近傍に寄せ始める、 CA/DA 均等
3. **converge** (gen 31-50): pull、 feasible 領域内 fine-tune、 CA 寄り
4. **refine** (gen 51-64): mission_inf_gap = 0 個体の局所探索、 CA 重視

切替条件:
- explore → bridge: `feasible_ratio_ema >= 0.05` AND `gen >= 12`
- bridge → converge: `feasible_ratio_ema >= 0.15` AND `gen >= 24`
- converge → refine: `n_mission_pass >= 4` AND `gen >= 40`

各 state の最低滞在世代を確保 (state 推定の安定性)。

Codex の見解は？ 多状態 FSM の数 (4 state vs 3 state vs 2 state)、 切替条件の robust 性。

### 反論 3: Pareto 3 軸の crowding distance 計算と diversity 維持

NSGA-II crowding distance は標準では各 objective の正規化距離の sum。 fx の Pareto 3 軸 (net_pnl, max_dd, mission_inf_gap) で:

(i) 標準 crowding distance (各 objective の boundary distance sum)
(ii) **session bucket aware crowding**: 個体の session_bucket pattern に応じて DA で diversity 計算
(iii) **family aware crowding**: family_key 距離も crowding に組み込む

zenigame T509 では どこまで extension しているか (おそらく標準)。

**Claude の主張**: (i) 標準で start、 ablation で (ii)(iii) を試す。 ただし DA archive 内では family/session diversity を明示的に評価 (= eviction で多様性確保) するので、 進化母集団 crowding は標準で良い。

Codex の見解は？

### 反論 4: 新規生成個体 (offspring) の CA/DA 振り分け

NSGA-II + CA/DA で offspring が生成されたとき:
- (α) 全 offspring を pool して、 rank+crowding で上位 256 を選び、 CA/DA に振り分け (parent選択時に決定)
- (β) parent から family を継承、 CA parent からの offspring は CA、 DA parent からは DA
- (γ) random 振り分け
- (δ) margin_inf 改善方向で動的判定 (CA: mission_inf_gap 改善、 DA: phenotype 距離 max)

**Claude の主張**: (δ) が原理的に正しいが計算重い。 (α) が NSGA-II 標準互換。

### 反論 5: archive total=160 と pop=256 の比率再考

Round 11 提案: archive total = 160 (CA 96 + DA 64)、 = pop の 0.625 倍。

これに対する考察:
- pop=256 / archive=160 = 0.625
- target_inflow=10 / archive=160 = 0.0625 (16 Run で archive 全更新)
- per_run_max=16 / archive=160 = 0.1 (10% / Run)

これは zenigame (pop=192, archive=100) の 0.52 倍と比べて archive 比率が高い。 fx は単一通貨ペアで feasible region が薄いから archive を厚くする、 という Codex Round 11 の logic は理解できる。

ただし epoch-rolling 24m (max_runs/epoch=6) の中で:
- 6 Run × 10 inflow = 60 entries / epoch
- archive 160 のうち 60 が新 epoch 由来、 100 が前 epoch 由来
- 前 epoch 個体は新 dataset で評価しないが warmstart で使われる
- これで「stale individuals が warmstart に注入される」 ことにならないか

**Claude の主張**: epoch 切替時に archive を **clear or partial reset** する必要がある。 もしくは archive entry に dataset_epoch_id を持たせて epoch mismatch 時 warmstart 候補から除外。

### 反論 6: lexicographic eviction の具体順序

Round 11 提案:
```
mission_pass > progress_pass > score_bypass > C-pass-depth > mission_margin > shadow_robustness > novelty > recency
```

意図確認:
- `mission_pass`: mission_inf_gap = 0 の個体を最優先で残す (= eviction 最後尾)
- `progress_pass`: C-lite 2/3 windows pass の個体を次優先
- `score_bypass`: bypass 経由で archive に入った個体は明示的に下位 (= eviction 候補上位)
- `C-pass-depth`: Stage C 通過の度合い (= live_criteria 全項目達成度)
- `mission_margin`: -mission_inf_gap (signed slack の大きさ、 mission を超えてどれだけ余裕があるか)
- `shadow_robustness`: cross-pair shadow 通過率 (validation 強さ)
- `novelty`: phenotype/genotype 距離
- `recency`: 直近 Run 由来か

profit_factor は最末尾 tie-break (Round 13 確定)。

**Claude の質問**: この lexicographic 順序は **CA archive 用** か **CA + DA 共通** か。 DA archive は diversity 軸で eviction するはずなので、 順序が違うはず。

提案: 別々の lexicographic:
- CA: mission_pass > progress_pass > C-pass-depth > mission_margin > shadow_robustness > recency > profit_factor
- DA: novelty > diversity_coverage > progress_pass > C-pass-depth > recency > profit_factor

つまり CA は mission 達成寄り、 DA は多様性寄り。

Codex の見解は？
