# Round 20 — 最終 consensus + synthesis 確定

Round 19 で以下の重大修正が判明。 これを反映して synthesis 最終確定する。

## Round 19 で確定した修正

### 修正 1: Push/Pull FSM = 2-state (zenigame 実装同等)
zenigame `push_pull_fsm.py:45` 確認、 multi-state ではなく **push/pull の 2-state**。 fx でも 2-state に統一、 「multi-state FSM」 「explore/bridge/pull/refine」 等の Round 14 提案は撤回。 3-state 以上を使うなら明示的に「fx 拡張」 とラベリング (今回は不採用)。

### 修正 2: 主選抜 = B-pooled 統一 (A-proxy は撤回)
zenigame `optimize.py:2125, 2141` 確認、 主選抜は B-pooled 値。 A-fail は当世代の Pareto 圧計算からも除外、 親選択母集団からも除外。 fx の Round 17 確定「A-proxy で search 圧」 は zenigame と非整合のため**撤回**。

新方針:
- 全個体 Stage A で canonical 5 worst gate_score 評価
- Stage A pass = top q_force% 抽出 (hard gate)
- A-pass のみ Stage B で 5 fold pooled 評価
- **GA selection 圧 = Stage B pooled で計算した Pareto 3 軸** (A-fail は除外)
- crossover/mutation parent も A-pass 母集団から
- archive 流入も Stage B 評価済個体のみ

### 修正 3: PBO/SPA 未実装、 DSR 先行
zenigame `_dsr.py:126` と `fitness.py:553` で DSR 実装確認、 PBO/SPA は未実装。 fx でも DSR 先行実装、 PBO/SPA は schema scaffold のみ + 「未実装」 タグで段階追加 (smoke 後)。

### 修正 4: Stage B fold = 5 で確定
62w で train 36 + emb 1 + test 5 + step 5 → 5 folds。 6 folds 表記は誤り。

### 修正 5: dataset_epoch_id schema は fx 新設
zenigame `genome_archive.py:540` の GENOMES_SCHEMA に dataset_epoch_id 不在。 fx の schema_version=2 で新設、 zenigame に逆輸入候補。

### 修正 6: factor_shadow は縮退保持 (削除でなく metadata)
cross-pair 監視で使うため最小機能で残す。 削除対象から除外。

### 修正 7: A→B 乖離は warn-only + q_force 自動引き上げ
hard fail でなく soft 対応、 監視中心。

### 修正 8: CA/DA 再スケール端数処理規約
pop=192 のとき CA/DA 比率を再スケールする際の round/floor 規約を定義。 例: explore 比率 (CA 0.4375, DA 0.5625) を pop=192 に適用すると CA=84, DA=108 (整数化)。 zenigame T509 の `archives.py` 端数処理を fx で踏襲。

## 修正反映後の最終 design

### A. 計算リソース
- lane=1 (EUR_JPY anchor、 archive 単一)
- pop=192 baseline / 256 promotion
- gen=64 baseline / 48 fallback (FSM 再校正不要、 2-state なので shift 量だけ調整)
- max_workers=clamp(floor(0.75*physical), 4, 16) + RAM 制約
- shadow 5 通貨 = validation のみ
- graduation = batch (graduates>=24 + 3 epoch + mission 連続)

### B. Dataset/Partition
- 24m primary (104w)、 epoch-rolling stride=4w, max_runs/epoch=6
- partition: `[B 62w][A 8w][emb 1w][C-lite 6w][emb 1w][C-lite 6w][emb 1w][C-lite 6w][emb 1w][C 12w]`
- Stage B fold = train 36w + emb 1w + test 5w + step 5w → **5 folds**
- 5 fold pooled 主判定 + fold fail-fast 補助
- calibrate-gate scope = dataset_epoch_id

### C. Metric (gate / search 完全分離)
- canonical 5 (gate worst): SR_session_worst (HAC Bartlett q=5), net_pnl_after_cost, max_dd, trade_count, session_block_win_rate_worst (trade=0 → 0.5)
- Pareto 3 軸 (search): max net_pnl, min max_dd, min mission_inf_gap (4 指標 inf-norm: gap_sharpe, gap_pnl, gap_dd, gap_tc, slack_to_range で trade_count range 評価)
- log_pf_clip(-2, 2) = archive lexicographic 末端 tie-break
- spread_consumption_ratio = tie-break + monitor
- session_close_drop > 0 / negative_equity_drop_open > 0 = invariant fail-fast
- cross-pair shadow = validation axis + archive metadata (validation 軸のみ、 selection 圧から除外)

### D. GA 構造
- NSGA-II + 純 CPPS (fallback flag なし、 2-state push/pull)
- objectives: (max net_pnl, min max_dd, min mission_inf_gap)
- selection: standard NSGA-II rank + crowding (3 軸正規化)
- **主選抜評価値 = Stage B pooled** (A-pass 母集団のみ)
- 2-state FSM: push (infeasible 領域許容) → pull (feasible 領域収束)
- 切替: feasible_ratio_ema >= threshold で push→pull (切替値は zenigame 実装参照、 仮固定後 smoke 再校正)
- CA/DA 進化母集団分割 動的比率 (pop=192 用、 端数 round 規約):
  - push: CA 84 / DA 108
  - pull: CA 120 / DA 72
- archive epoch-aware (dataset_epoch_id、 prev_epoch 20% only via Stage A quick recheck、 epoch_age>=2 purge)
- offspring 振り分け: NSGA-II rank+crowding 標準で survivor、 state 依存 CA/DA 再配分
- eviction CA/DA 別 lexicographic
- 旧 exec_floor 不採用

### E. Loop Closure (pop=192 baseline)
- archive=120 (CA 72 / DA 48)、 記憶半減期 ≈ 10.4 Run
- inflow=8 / per_run_max=12 (pop 0.04/0.06 比例)
- 3 層流入: mission_pass + progress_pass (C-lite 2/3 windows pass) + score_bypass
- score_bypass = Stage B 評価済個体のみ + invariant_feasible + margin_inf percentile <= 70 (品質床)
- bypass K: 通常 clamp(8-nm-np, 2, 6)、 emergency clamp(10-nm-np, 4, 8)
- warmstart_share=20% (38 体)、 ramp (run1=0% → run4+=20%)
- warmstart 通常 CA:DA = 26:12、 emergency 19:19
- 緊急モード warmstart_share = 25% (1 run のみ、 35% 不採用、 prev_epoch 20% 維持)
- max_per_source_run=2、 max_per_session_pattern=2、 max_family=2、 max_reuse=3、 cooldown=2 Run
- vol/aux = archive metadata 保持
- cross_pair_pass = `shadow_robustness_score` 連続 + per-pair 生値

### F. P2 Regime
- session_bucket 3 (Tokyo/London/NY) 固定
- 6 bucket 不採用 (C-lite 15/bucket で C7 違反)
- spectral weight = support-aware clip [0.25, 0.45]、 development span のみ計算
- volatility / aux / period = archive metadata、 P2 主軸外
- regime_pass_pattern = archive diversity 軸 (P2 禁止)

### G. Cross-cutting
- **A-pass のみ B 評価** (compute 節約 + 主選抜 B-based)
- 主選抜評価値 = B-pooled (A-fail は当世代 Pareto 圧計算から除外)
- 緊急モード 25% (35% 不採用)
- score_bypass = B 評価済 + 品質床
- dataset_epoch_id 全経路必須 (schema lint で fail-closed)
- A→B 乖離は warn-only + q_force 自動引き上げ (hard fail なし)

### H. 削除対象 (big-bang clean up)
- one-switch / fallback flag 系すべて
- 「A 指標と B 指標を混在させて主選抜」 経路 (= A-proxy 主選抜)
- multi-state FSM 系 (3-state 以上の遷移ロジック、 refine フラグ等の拡張は不採用)
- schema v1 archive read/write 分岐 (v2 一本化)
- `swim_lane.tier1.population_size=30` (lane=1 で意味消失)
- `swim_lane.graduation.seed_strategy: "union_of_tier1_graduates"` (graduation Phase 4 で別設計)
- `ga.feasibility.{entry_count_min, apply_from_generation, enable_fallback_when_all_infeasible}` (bypass 品質床に置換)
- `improve_cycle.{plateau_cycles, plateau_mutation_bump, mutation_rate_max}` (新 GA で再設計)
- `stage_gate.stage_a.{target_pass_rate, alpha, threshold, min_exposure_trade_count, calibrate.*}` (動的 q_force に置換)
- `stage_gate.stage_b.{wf_*, median_oos_sharpe_min, positive_fold_min, dsr_min, fold_trade_count_min}` (新 fold 仕様に置換)
- `stage_gate.stage_c.{spread_stress_*, feasibility_apply}` (新 Stage C 仕様に置換)
- 旧 `scripts/alpha_factory/run_alpha_sieve.py` (post-RUN MD-only 廃止、 archive 連動に置換)
- 旧 `scripts/alpha_factory/calibrate_gate.py` (3 Run freeze + epoch scope 仕様に置換)

### 縮退保持対象 (削除しない)
- `factor_shadow` (T036): metadata 最小機能で残す、 cross-pair 監視に使用、 enabled=false
- aux 関連 config (T057): preflight 整合性のため維持
- `dataset.{instrument, start, end}`: 24m epoch-rolling で動的更新
- `backtest.{initial_cash, leverage, units, max_spread_bps, holding_cost_per_day_bps}`: 維持
- `live_criteria.*`: Stage C mission gate として維持
