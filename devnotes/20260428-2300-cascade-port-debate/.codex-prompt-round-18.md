# Round 18 — Synthesis fresh 最終版

論点 A〜G + cross-cutting 全て確定。 これが最終ラウンド。 fresh design の synthesis を最終形にまとめる。

## 確定構成 (Round 11-17 統合)

### A. 計算リソース
- lane_parallelism = 1, tier1 = EUR_JPY single lane, archive 単一
- pop = 192 baseline / 256 promotion (front1_card<20 連続 等)
- gen = 64 baseline / 48 fallback (FSM 再校正必須)
- max_workers = clamp(floor(0.75 × physical_cores), 4, 16) + RAM 制約
- compute budget: baseline 12,288 / expanded 16,384 eval/Run
- graduation lane = batch (graduates>=24 + 3 epoch + mission_pass 連続)
- shadow 5 通貨 = validation のみ

### B. Dataset + Partition
- dataset = 24m (104w) primary、 35m は graduation audit へ
- epoch-rolling: window=104w, stride=4w, max_runs/epoch=6
- calibrate-gate history は dataset_epoch_id でスコープ分離
- partition: `[B 62w][A 8w][emb 1w][C-lite 6w][emb 1w][C-lite 6w][emb 1w][C-lite 6w][emb 1w][C 12w]`
- Stage A は時間軸で B より後 (recent proxy)、 overlap=0
- Stage B fold: train 36w + emb 1w + test 5w + step 5w → 5 folds
- 5 fold pooled が主判定、 fold 単位 fail-fast 補助
- Stage A は trade_rate 中心 (絶対 trade_count なし)
- Stage C 明示 rotation 不採用 (epoch-rolling で実質回転)

### C. Objective Taxonomy
- **canonical 5 (gate)**: SR_session_worst, net_pnl_after_cost, max_dd, trade_count, session_block_win_rate_worst
  - SR_session: HAC (Bartlett) 補正 Sharpe、 q=5、 3 bucket worst
  - session_block_win_rate: 1 営業日 × 1 bucket、 trade=0 block は 0.5 neutral、 3 bucket worst
- **Pareto 3 軸 (search)**: max net_pnl_after_cost, min max_dd, min mission_inf_gap
  - mission_inf_gap = max(gap_sharpe, gap_pnl, gap_dd, gap_tc)、 live_criteria 4 指標のみ
  - gap_tc は slack_to_range で range 両側評価
- **profit_factor → log_pf_clip(-2, 2)** = archive lexicographic 末端 tie-break のみ
- spread_consumption_ratio = tie-break + monitor
- session_close_drop / negative_equity_drop > 0 = invariant fail-fast
- cross-pair shadow = validation axis + archive metadata
- gate (canonical 5 worst) と search (Pareto 3 軸) 完全分離

### D. GA 構造
- NSGA-II + 軽量 CPPS (3-state FSM: explore → bridge → pull、 Pull 内 refine フラグ)
- 遷移条件 (pop=256 用): explore→bridge `feasible_ratio_ema>=0.03 AND gen>=12` (or gen>=24 強制)、 bridge→pull `>=0.12 AND gen>=24` (or gen>=44)、 refine ON `n_mission_pass>=4 AND gen>=48`
- pop=192 用 CA/DA 比率 (再スケール): explore 84/108、 bridge 96/96、 pull 120/72、 refine 132/60
- pop=256 用 CA/DA 比率: explore 112/144、 bridge 128/128、 pull 160/96、 refine 176/80
- 標準 crowding distance (3 軸正規化)
- offspring 振り分け: NSGA-II rank+crowding で survivor、 state 依存 CA/DA 再配分
- archive epoch aware (dataset_epoch_id、 prev_epoch 20% only via Stage A quick recheck、 epoch_age>=2 purge)
- eviction CA/DA 別 lexicographic
- 旧 exec_floor 不採用

### E. Loop Closure (pop=192 baseline)
- archive=120 (CA 72 + DA 48)、 記憶半減期 ≈ 10.4 Run
- inflow=8/per_run_max=12 (pop 比例 0.04/0.06)
- 3 層流入: mission_pass + progress_pass (C-lite 2/3 windows pass) + score_bypass
- score_bypass は Stage B 評価済個体のみ対象 (cross-cutting 検査 1 修正)
- bypass K: 通常 clamp(8-nm-np, 2, 6)、 emergency clamp(10-nm-np, 4, 8)
- warmstart_share=20% (38 体)、 ramp (run1=0% → run4+=20%)
- 通常 CA:DA = 26:12、 emergency CA:DA = 19:19
- 緊急モード warmstart_share = 25% (1 run のみ、 35% は不採用、 prev_epoch 20% 維持)
- max_per_source_run=2、 max_per_session_pattern=2、 max_family=2
- max_reuse=3、 cooldown=2 Run、 rolling=10 Run
- vol/aux は archive metadata 保持
- cross_pair_pass = `shadow_robustness_score` (連続) + per-pair 生値
- log_pf_clip = log((GP+1e-6)/(GL+1e-6)) clip(-2, 2) (eviction tie-break 用)

### F. P2 Regime
- session 3 bucket (Tokyo/London/NY) 固定
- 6 bucket 不採用 (C-lite 15/bucket で C7 違反)
- spectral weight = support-aware clip [0.25, 0.45] (development span のみ計算、 holdout 除外)
- regime_pass_pattern = archive diversity 軸 (P2 禁止)

### Cascade selection 圧 / archive admission の分離 (cross-cutting 検査 3 修正)
- **GA selection 圧 source = Stage A proxy** (全個体、 全世代の Pareto 3 軸計算に使用)
- **archive admission source = Stage B pooled** (A 通過候補のみ)
- **gate / search の評価値を直接混ぜない**(逆ピラミッド回避)

### 緊急モード
- 発動: mission_pass=0 が 3 連続 AND `MA3(best_margin_inf) < MA6 - 0.05`
- 動作: warmstart_share 20%→25% を 1 run のみ、 CA:DA を 1:1 寄り
- 解除: progress_pass>=2 OR best_margin_inf >= MA6

### calibrate-gate
- 凍結 3 Run、 4 Run 目更新、 |Δ|<=0.03
- スコープキー: dataset_epoch_id (epoch 跨ぎ再利用禁止)

### 全経路 dataset_epoch_id 必須 (検査 6 修正)
- archive entry / calibrate-gate history JSONL / warmstart filter / monitor / report
- 禁止事項 8 (伝搬漏れ) の最重要ポイント

## Risk Top 5
1. A-proxy / B-pooled 乖離で探索誤誘導 → A→B 乖離メトリクス記録 + q_force 自動引き上げ
2. epoch_id 伝搬漏れで cross-epoch 汚染 → schema lint で必須フィールド欠落 fail
3. 緊急時 warmstart 供給不足 → 35% 廃止、 25% 固定で ramp 整合
4. archive bypass 偏重で品質低下 → bypass = B 評価済 + 品質床必須
5. DA 多様性形骸化 → DA eviction に novelty/coverage 主キー化、 entropy 週次監視
