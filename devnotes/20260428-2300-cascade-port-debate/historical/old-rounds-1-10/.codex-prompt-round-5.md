# Round 5 — 論点 3 deep dive (CPPS scope: フル / 中間 / 軽量 の選択)

論点 1, 2, 4 確定済み。 残るは論点 3 (CPPS scope) と 論点 5 (Loop closure)。 まず論点 3 から。

## Round 1 の Codex 暫定整理

- **軽量案**: single working population + external archive + (net, dd, margin_inf) の 3 軸 Pareto
- **中間案**: 上記に one-switch push→pull と単純 exec_floor を足す
- **フル案**: CA/DA + Push/Pull FSM + exec_floor warmup→ramp→hard

Codex 暫定: **中間案 > 軽量案 > フル案**

## 論点 1, 2, 4 確定後の前提変化

確定済み:
1. dataset 24 ヶ月先行 (pop=40, gen=15 → 600 evaluations / Run)
2. canonical 5 = sharpe / net_return / max_dd / trade_count / **profit_factor** (win_rate 降格)
3. session_close_drop_count > 0 / negative_equity_drop_open_count > 0 = **invariant fail-fast**
4. spread_consumption_ratio = tie-break + monitor
5. cross-pair shadow = validation axis + archive metadata (selection 圧から除外)
6. P2 = session 3 bucket 主軸、 support-aware clip
7. Stage B = WF-OOS gate (train 45 + embargo 1 + test 20)、 fold-median worst gap

これにより論点 3 の前提が大きく変わる:
- **margin_inf の定義が確定**: canonical 5 の signed worst slack (profit_factor を含む 5 指標)
- **exec_floor の対象が消える可能性**: spread_consumption は tie-break、 session_close / negative_equity は invariant fail-fast。 exec_score 軸を Pareto に乗せる必要が**そもそも無くなる**

zenigame の CPPS は exec_score を Pareto から外して制約化する設計だったが、 fx ではそもそも exec metric を Pareto に乗せる動機が薄い。

## Claude の反論・突き詰めポイント

### 反論 1: そもそも 3 軸 Pareto が必要か

論点 2 で canonical 5 を **worst** で集約することが確定した。 canonical 5 の **worst gap** だけで pass/fail が決まるなら、 「3 軸 Pareto」 自体が必要か疑わしい。

zenigame の CPPS が 3 軸 (net, dd, margin_inf) を残している理由:
- net と dd は「進化圧の方向性」 を明示する (= profit を増やし、 risk を減らす)
- margin_inf は 5 指標 worst の signed slack で、 mission gate との距離を表す
- 3 軸 Pareto + crowding distance で diversity 確保

しかし fx で:
- pop=40 と小さく、 Pareto front の size はそもそも小さい (front rank 1 が 5-10 体程度)
- 3 軸の Pareto rank は実質的に「margin_inf の連続値」 に支配される (net と dd は margin_inf の構成要素)
- 実質単目的 (margin_inf 最小化) で十分かもしれない

**Claude の主張**: fx では **(E) 単目的 margin_inf 最小化 + crowding (or 他の diversity 指標)** が現実的かもしれない。 これは Codex Round 1 の軽量案よりさらに簡素。 3 軸 Pareto を維持する意味が pop=40 で本当にあるか、 反論を求める。

候補再列挙:
- (E) 単目的 margin_inf 最小化 + crowding (新規最軽量案)
- (B') 軽量案: 単一 archive + 3 軸 Pareto (net, dd, margin_inf) + crowding
- (B'') 中間案: 軽量案 + one-switch push→pull
- (A') フル案: CA/DA + Push/Pull FSM (exec_floor は不要に)

Codex の見解は？ pop=40, gen=15 で 3 軸 Pareto と単目的 + crowding に有意差があるか。

### 反論 2: CA/DA Two-Archive を fx に持ち込む価値

Li, Chen, Fu, Yao (2019) の TAEA は **constrained MOEA で feasible region が狭い** 状況で CA/DA 分離が有効。 fx の場合:
- canonical 5 worst gap = 0 (全指標達成) の feasible region は **mission gate そのもの**
- これに到達する個体は run-26 のように **0 体** か少数で、 まさに 「small feasible region」

つまり Li et al. の前提と fx の状況は整合する。 CA (feasible 寄り) と DA (diversity 重視) を分離する利益はある可能性。

**Claude の主張**: feasible region が狭い fx では **CA/DA は本来効くべき**。 ただし:
- pop=40 で CA 20 + DA 20 に分割すると各 archive のサンプル数が薄い
- DA の diversity metric は何にするか (P2 = session bucket での pass 経験? family_key? 個体間 phenotype distance?)

具体案を求める:
- (i) pop=40 のまま CA/DA 分離 (各 archive 推奨 sample size を出す)
- (ii) pop=60 に増やして CA 30 + DA 30 (compute cost 1.5 倍)
- (iii) external archive を pop と分離して使う (archive=100 程度を CA/DA に割る)

Codex の見解は？ Li et al. の small feasible region の知見は fx でどう実装すべきか。

### 反論 3: Push/Pull FSM の必要性

Fan et al. (2019) の PPS は infeasible region を push で横断、 feasible 近傍で pull に切替。 fx の状況:
- 初期世代では多くの個体が canonical 5 worst > 0 (infeasible)
- 後期世代で worst gap が縮小 (feasible 近傍へ)
- 期間 dataset=24 ヶ月で gen=15 だと、 infeasible→feasible の移行が gen 8-10 あたりで起きる

**Claude の主張**: gen=15 でも push→pull 切替は**意味がある**。 ただし FSM (multiple states) より **one-switch (binary)** が pop=40 では十分。 切替条件:
- (a) `feasible_ratio > threshold` (例: 0.2 で切替)
- (b) `gen >= G_threshold` (例: gen 10 で固定切替)
- (c) `margin_inf_best < threshold` (例: best margin_inf < 0.5)

Codex の見解は？ どの switch condition が pop=40, gen=15 で堅牢か。

### 反論 4: exec_floor 制約は本当に不要か

論点 2 で session_close_drop / negative_equity_drop は invariant fail-fast、 spread_consumption は tie-break と確定。 これで exec_floor が必要な fx 固有 execution metric は **selection 圧から完全に消えた**。

ただし zenigame の exec_floor 概念 (warmup→ramp→hard) を fx で別の用途に転用する余地:
- (i) `feasible_ratio` 自体が低すぎる世代で、 任意の指標に floor を緩く設定して selection 維持
- (ii) Stage A の `top 15% 強制` の比率を gen 進行で動的化 (warmup で広め、 後半で絞る)
- (iii) trade_count の下限 floor を gen 進行で段階的に引き上げる (= 取引密度の漸進的強化)

**Claude の主張**: (ii) と (iii) は zenigame の exec_floor 思想を **selection ratio に転用** したもの。 これは Push/Pull の補助機構として有効かもしれない。

Codex の見解は？

### 反論 5: warmstart CA/DA 分離注入

zenigame の T509 は warmstart で CA seed と DA seed を別系統で注入。 fx では:
- CA = canonical 5 worst gap が小さい個体 (mission に近い)
- DA = session bucket の少数派 regime で pass している個体 (diversity)

**Claude の主張**: warmstart で 2 系統分離は意味あり。 ただし pop=40 で warmstart_share=0.2 (= 8 体) を CA 4 + DA 4 に分けるか、 単一系統で 8 体注入するかは検討余地。

## Round 5 で Codex に求めるもの

論点 3 (CPPS scope) を確定させる。 以下を出してほしい:
