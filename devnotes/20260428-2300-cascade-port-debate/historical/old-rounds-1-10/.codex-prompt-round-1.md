# zenigame 最新 cascade の核 (T508/T509/T511/T513)

1. **原則 4**: canonical 5 指標 (sharpe / net_return / max_dd / trade_count / win_rate) の **worst aggregation** で pass/fail 判定。 mean / RMS / spectral / weighted sum は同ランク内 tie-break / 順位補助のみ
2. **Stage A → 世代内 top 15% 強制**: `gate_score = 1 / (1 + worst_gap_5metrics)`、 絶対 floor は破綻排除のみ
3. **Stage B → C-lite**: NSGA-II 3 軸 → **CPPS (net / dd / margin_inf) + CA/DA Two-Archive + Push/Pull FSM + exec_floor 制約**
4. **Stage C-lite → C**: 5 指標 × 3 窓 = 15 セル worst gap + top 30% 強制通過
5. **Stage C → AS**: adaptive_pass + adaptive_progress + transition_pass + score_bypass の 4 層流入
6. **AS → Archive**: 5 指標 × 6 regime regime-内-worst sieve_score + run_quota + per_seed_min=8
7. **Archive → Warmstart**: sieve_share=0.33 で次 Run に逆注入 + family/run/seed 多様性制約
8. **役割分担 (T513)**: worst (pass/fail) / majority (プリフィルタ) / spectral (順位補助) を明示分離

zenigame の Event 1-15 (R79 TNV Lookahead 崩壊から CPPS audit 13 件 fix まで) の経験から確立された 4 原則 (絶対閾値=破綻排除のみ / 難易度次元正規化 / サイクル全滅防止強制流入 / canonical 5 指標 worst aggregation) を fx に持ち込む。

# 議論する 5 論点

## 論点 1: Stage 構造の根本設計 — 時間軸スライス × 判定軸の組み合わせ

fx は時間軸スライス (A=末尾60d / B=全期間 / C=後続60d holdout)、 zenigame は判定基準セット + universe sampling。 fx で「A → B → C-lite → C → AS → recheck → A」 のクローズドループを成立させるには:

(a) 時間軸構造はそのまま、 各 stage の判定軸だけ canonical 5 指標 worst に置換
(b) C-lite を新設 (候補プリフィルタ + top-30% 強制通過)
(c) Stage B IS monitor 撤廃 (逆ピラミッド是正、 ~260k bars/個体削減)
(d) dataset 期間延長 (6ヶ月 → 18-24ヶ月) を前提にするか

**論点**: dataset 延長を前提にする vs 既存 6 ヶ月で WF fold を増やす方向で凌ぐ vs 期間 sliding rotation で同じ 6 ヶ月を多様化する。 各案の trade-off を反証込みで議論。 Stage B の意味 (full IS monitor の存在意義) を含めて。

## 論点 2: canonical 5 指標 worst aggregation の fx 適用

zenigame の 5 指標 `(sharpe / net_return / max_dd / trade_count / win_rate)` を fx でそのまま使うか、 fx 固有の指標を加える/置換するか。

候補:
- spread_consumption_ratio: max_spread_bps を使い切った割合 (FX 特有のコスト指標)
- session_close_drop_count: session_close_utc_hours で drop した割合 (overnight 持ち越し試行のシグナル)
- negative_equity_drop_open_count: equity_at_entry < 0 で drop した割合 (Run-26 の病巣)

**論点**: これら fx 固有指標を worst に含めるか、 順位補助 (tie-break) に留めるか、 そもそも canonical 5 指標を増やすべきか。 「使命達成 = live_criteria 全達成」 の AND 性を維持しつつ fx 固有の execution risk をどう selection 圧化するか。

## 論点 3: CPPS フルポート vs 軽量 margin_inf 軸追加

zenigame: pop=192、 fx: pop=40 (≈ 1/5 規模)。 CA (Convergence Archive) + DA (Diversity Archive) Two-Archive、 Push/Pull FSM、 exec_floor 制約まで持ち込むか。

軽量案: 単一 archive + margin_inf 軸 (= 5 指標 signed worst slack) を Pareto 軸に追加するだけで原則 4 整合。 CA/DA 分離・FSM はスキップ。

**論点**: pop=40 で CA + DA を分離する diversity 余地はあるか。 Push/Pull の探索/収束自動切替は世代数 15 で意味があるか。 exec_floor 制約 (warmup → ramp → hard) は fx で必要か (FX の execution metric は zenigame の exec_score より単純な気がする)。 fx 用の現実的な落とし所はどこか。

## 論点 4: P2 次元 (難易度正規化軸) の fx 文脈での再定義

universe seed が無い fx で多様性軸候補:
- (a) volatility regime (ATR / realized vol で 3 bucket: high_vol / normal / low_vol)
- (b) session bucket (Tokyo / London / NY)
- (c) aux factor regime (VIX 水準, DXY 方向, Gold trend 等で複合 bucket)
- (d) cross-pair shadow (T016 で枠あり: EUR_USD/USD_JPY/AUD_JPY/USD_CAD/USD_ZAR から anchor 2-3)
- (e) period bucket (dataset を sliding window で複数生成)
- (f) regime_pass_pattern (各個体がどの regime で pass したかのパターン自体を多様性軸に)

**論点**: いくつ採用するか (3 vs 6)、 直交か入れ子か、 計算量との trade-off。 zenigame の 6 regime spectral [0.35, 0.25, 0.15, 0.10, 0.10, 0.05] に相当する fx 用 weight 設計。 「regime 難易度を認識した相対正規化」 が原則 2 の核なので、 ここを軽くしすぎると原則違反になる。 重くしすぎると pop=40 で各 regime あたりサンプル数 < 7 になり統計的に評価不能。

## 論点 5: Sieve→Archive→Warmstart ループ閉じの fx 実装範囲

zenigame の family/run/seed 制約のうち何を持ち込むか:
- source_run_id 由来の多様性 (max_per_source_run=3 相当)
- family_key (Clause 構造の hash) 由来 (max_family=2)
- effective_dataset_period 由来 (period rotation の場合)
- regime_pass_pattern 由来 (どの regime で pass したかのパターン)
- per_seed_min 相当を fx で何に置換するか

**論点**: pop=40, archive=100 cap (zenigame と同じか?) として何 entries 確保すべきか。 score_bypass top-K の K, transition_pass の必要性 (zenigame では W3 mixing 由来、 fx には対応するものが無い)。 warmstart 注入の sieve_share (zenigame=0.33) は fx で何が適切か。 Run ごとに何体 archive に流入させ、 何体 warmstart 注入するか。

6. **C1-C9 discipline チェック**: 議論の中で陥りやすい誤読 (Collider bias, X-no-bug 禁止, sample size 不足) を先回りで identify
