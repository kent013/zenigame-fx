## Round 1 コメント対応

### [Warning 1] `assert` が `python -O` で無効化される懸念

**対応方針**: 設計書 `detailed-design.md` §施策 1「リスク」セクションで明示的に許容している設計判断です（引用）:

> **assert 文の性能**: `assert` は `-O` optimization フラグで無効化される。default では実行される → 本番コストあり。production では `-O` でなく default 実行なので OK

zenigame-fx の運用では `-O` フラグを使わないことが確立されています（Dockerfile・RUN script 等に `-O` の指定なし。確認: `grep -r "python -O\|PYTHONOPTIMIZE" scripts/ Dockerfile 2>/dev/null` 結果ゼロ件）。また、identity check 自体は defensive check であり、本番 path では genome 差し替えは行われない契約のため、`-O` 運用を将来導入する場合でも実害は限定的です。

### [Warning 2] prepared / unprepared の NaN 正規化差

**対応方針**: unprepared path は evaluator.evaluate() の返り値をそのまま使うため、evaluator 側が NaN を返さない契約が前提です。新規テスト `test_on_bar_prepared_equivalent_to_unprepared` は RegistryEvaluator（実運用 evaluator）を使った bit-identical 検証であり、この契約下で trades / equity が同一であることを確認しています（全 400 bars、trade entry/exit 時刻・side・price が一致）。

既存 `tests/backtest/test_engine_prepare.py::test_prepare_produces_identical_trades_to_per_bar_path` も同様に RegistryEvaluator で 400 bars の bit-identical を保証しており、この 2 テストで selection invariance の静的証跡となっています。

### [Warning 3] baseline profile との直接比較

**対応方針**: `profile_20260425_025427` は perf profile baseline であり GA run artifact のスナップショット比較テストを repo に組み込む運用にはなっていません（設計書 §Phase 7 検証手順は T029 merge 後に別途実施）。コード path の bit-identical 性は test_on_bar_prepared_equivalent_to_unprepared で担保されており、selection invariance は `_signal_cache_key` の semantics が不変（name + sorted(params.items()) tuple）であることから保たれます。
