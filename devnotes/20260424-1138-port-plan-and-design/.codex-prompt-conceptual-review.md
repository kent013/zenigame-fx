# 概念設計: skill port — zenigame-fx-plan-and-design

## 背景・課題

zenigame には改善計画策定スキル `zenigame-plan-and-design` が存在し、analyze-run の出力（`analysis-claude.md`, `analysis-codex.md`）を起点に、

1. TODO 選定（Codex 合議含む）
2. Claude/Codex 分析のマージ
3. 改善策の Codex 合議
4. 詳細設計書作成
5. 詳細設計の Codex レビュー合議

までを自動化していた。

zenigame-fx 側ではこのフェーズが未整備で、autopilot / improve-cycle が「分析 → run」を回すのみ。**改善計画策定 + Codex 合議 + 詳細設計レビュー + TODO 選定** を統合する skill が無いと、`zenigame-fx-improve-cycle` の「Phase 2 calibrate → Phase 3 implement」の間が経験則ベースになり、Codex 合議による品質ゲートが入らない。

T020（`zenigame-fx-analyze-run`）/ T021（`zenigame-fx-run-report`）が完了し、analyze-run の出力 SSoT が揃った今、計画策定 skill の port を行うことで improve-cycle / autopilot が完結に近づく。
