### 反証 1: Stage A 判定式は仕様通り、 bug なし

`src/alpha_factory/stage_gate.py:837-839` の Stage A 判定 SSOT:
```python
fitness_raw = sharpe_raw   # = trade_sharpe_raw
fitness_pen = fitness_raw - stage_config.stage_a_alpha * size_norm_val
if fitness_pen <= stage_config.stage_a_threshold:
    reasons.append("below_threshold")
```

= 判定指標は `fitness_pen` (= `trade_sharpe_raw - alpha * size_norm`)、 **`trade_sharpe_raw` 単独ではない**。

config (`config/alpha_factory/default.yaml`):
- `stage_a.alpha = 0.03`
- `stage_a.threshold = 0.0`

run-27 best 個体 g11_i3 の数値検算:
- `trade_sharpe_raw = 0.001134`
- 観察 `fitness_pen = -0.007866`
- 逆算 `size_norm_val = (0.001134 - (-0.007866)) / 0.03 = 0.300` ← n_nodes=2 / max=4 で size norm が 0.3 = 妥当
- `fitness_pen = 0.001134 - 0.03 * 0.300 = -0.007866` ✓ (= 計算合致)

= **Stage A 判定契約は SSOT 設計通り正常動作**。 「max(trade_sharpe_raw)=0.001 > threshold=0 なのに pass=0」 という Round 1 矛盾は **判定指標を取り違えた誤読** (= Claude も Codex も同じ誤読、 C5 並列独立性違反)。
