## 6. evaluator wrapper (T061 / T062 / T064 を degraded 化)

### 6.1 evaluate_canonical_five_safe (T061 wrap)

```python
def evaluate_canonical_five_safe(
    *,
    genome_id: str,
    run_id: str,
    generation_no: int,
    stage: str,
    evaluate_fn: Callable[..., CanonicalFiveResult],
    **evaluate_kwargs: Any,
) -> tuple[CanonicalFiveResult, FailureRecord | None]:
    """T061 evaluate_canonical_five を例外 catch + finite check で wrap.

    例外 / NaN / Inf 検出時は **degraded result (is_feasible=False、 全 slack=-inf 等)**
    を返し、 FailureRecord で原因記録.
    """
    try:
        result = evaluate_fn(**evaluate_kwargs)
    except KeyboardInterrupt:
        raise   # signal は通す
    except Exception as exc:
        record = FailureRecord(
            genome_id=genome_id, run_id=run_id, generation_no=generation_no, stage=stage,
            failure_reason="exception_raised",
            exception_class=type(exc).__name__,
            exception_message=str(exc)[:500],   # 切詰め
            detected_field=None, detected_value=None,
        )
        return build_degraded_canonical_five(), record

    # NaN/Inf check
    finite_check = validate_finite_canonical_five(result)
    if finite_check is not None:
        record = FailureRecord(
            genome_id=genome_id, run_id=run_id, generation_no=generation_no, stage=stage,
            failure_reason="non_finite_detected",
            exception_class=None, exception_message=None,
            detected_field=finite_check[0],
            detected_value=finite_check[1],
        )
        return build_degraded_canonical_five(), record

    return result, None
```

## 8. NaN/Inf 検出 (post-validation、 defense-in-depth)

### 8.1 validate_finite_canonical_five

```python
def validate_finite_canonical_five(
    result: CanonicalFiveResult,
) -> tuple[str, float] | None:
    """CanonicalFiveResult の全 numeric field を finite check.

    検出時は (field_name, value) を返す、 全 finite なら None.
    対象 field: net_pnl_after_cost / max_dd / sr_session_worst / session_block_win_rate_worst /
    trade_count / log_pf_clip / gate_worst_gap / 各 slack_*
    """
    candidates = [
        ("net_pnl_after_cost", result.net_pnl_after_cost),
        ("max_dd", result.max_dd),
        ("sr_session_worst", result.sr_session_worst),
        ("session_block_win_rate_worst", result.session_block_win_rate_worst),
        ("log_pf_clip", result.log_pf_clip),
        ("gate_worst_gap", result.gate_worst_gap),
        ("slack_sharpe", result.slack_sharpe),
        ("slack_pnl", result.slack_pnl),
        ("slack_dd", result.slack_dd),
        ("slack_tc", result.slack_tc),
        ("slack_wr", result.slack_wr),
    ]
    for name, value in candidates:
        if not math.isfinite(value):
            return (name, value)
    return None
```

## 9. aggregate_failures + decide_run_abort

### 9.1 aggregate_failures

```python
def aggregate_failures(
    records: Sequence[FailureRecord],
    *,
    total_individuals: int,
) -> FailureSummary:
    """per-Run 失敗集計.

    - failed_genome_ids は genome_id 昇順 (deterministic).
    - failures_by_stage / failures_by_reason は MappingProxyType (immutable).
    """
    if total_individuals < 0:
        raise ValueError(f"total_individuals must be >= 0, got {total_individuals}")
    n_failed = len(records)
    if n_failed > total_individuals:
        raise ValueError(
            f"n_failed ({n_failed}) exceeds total_individuals ({total_individuals})"
        )
    failed_ids = tuple(sorted({r.genome_id for r in records}))
    by_stage = Counter(r.stage for r in records)
    by_reason = Counter(r.failure_reason for r in records)
    return FailureSummary(
        total_individuals=total_individuals,
        n_failed=n_failed,
        n_succeeded=total_individuals - n_failed,
        failed_genome_ids=failed_ids,
        failures_by_stage=types.MappingProxyType(dict(by_stage)),
        failures_by_reason=types.MappingProxyType(dict(by_reason)),
        failure_rate=n_failed / max(total_individuals, 1),
    )
```

### 9.2 decide_run_abort

```python
def decide_run_abort(summary: FailureSummary) -> bool:
    """全個体 fail で True (synthesis § 7.7 silent degrade 禁止).

    部分 fail (n_failed < total_individuals) は False (warning + 続行は caller 責務).

    return summary.n_failed == summary.total_individuals and summary.total_individuals > 0
```

## 10. 重要な設計判断

### 10.1 KeyboardInterrupt は通す

evaluator wrapper では `except Exception` で catch し、 `KeyboardInterrupt` は通す (Ctrl-C で abort 可能)。

### 10.2 例外メッセージの切詰め

`exception_message` は 500 文字に切詰め (構造化ログでの肥大化防止)。

### 10.3 sentinel -inf 許容ルール (T062 整合)

`mission_signed_margin = -inf` は T062 の正規 sentinel (infeasible 個体)。 validate_finite_mission_gap では:
- `is_feasible=True` かつ `mission_signed_margin = -inf` → state inconsistency → failure
- `is_feasible=False` かつ `mission_signed_margin = -inf` → 許容 (T062 sentinel 規約)
- `is_feasible=*` かつ NaN → failure (T062 既に NaN は raise だが defense-in-depth)

詳細設計で完全 truth table。

### 10.4 degraded result の T065 / T066 / T067 への伝搬

degraded result (build_degraded_canonical_five etc.) は upstream evaluator が返す前提で、 downstream (T065/T066/T067) は通常通り処理。 例:
- T065: degraded MissionGapResult.constraint_violation=+inf → T065 入口で ValueError raise (T065 は finite domain 必須)
- ↑ これだと degraded がそのまま T065 へ流すと ValueError chain
- → T068 wrap は **upstream evaluator の wrap のみ**、 T065/T066/T067 は呼出 caller 側で判定 (= bc_result / mission_gap が degraded なら T065 に渡さず除外、 T067 build_archive_candidate でも同様)

詳細設計で「degraded の伝搬規約」 を確定 (caller 責務で degraded 個体を T065 から除外、 T068 は record だけ提供).

### 10.5 全 fail RuntimeError の caller 責務

## 13. 残論点 / Decision Pending

### R1: degraded result の T065/T066/T067 への伝搬規約

- 案 A: caller (Phase 2 run_loop) で degraded 個体を T065/T066/T067 入力から除外 (= excluded_genome_ids として渡す)
- 案 B: degraded result を T065/T066/T067 に渡し、 各入口契約 (finite domain) で ValueError raise → caller 上位で abort
- 採用案: **案 A** (caller 責務、 T068 は failure record 提供のみ、 詳細設計で確定)

### R2: sentinel 許容 truth table

mission_signed_margin = -inf / mission_inf_gap = +inf / constraint_violation = +inf の各 sentinel が is_feasible=True/False とどう整合すべきか。 詳細設計で完全 truth table 化。

### R3: KeyboardInterrupt 以外の signal の扱い

SystemExit / 子プロセス kill 時の例外も通すか。 詳細設計で確定。

### R4: T065/T066/T067 自身の例外 handling

T065/T066/T067 は pure function なので入口契約違反のみ ValueError。 T068 はこれらを wrap しない (caller が直接呼出、 ValueError は契約違反 indicator として上位 abort)。

### R5: 部分 fail の許容率閾値

N% 以上の部分 fail で run abort するか。 採用: 閾値なし (synthesis § 7.7 「全 fail のみ abort」 厳密準拠)、 部分 fail は warning + 続行。 INCONCLUSIVE (smoke 後 R5 検討候補、 例えば 50% 超で警告強化)。
