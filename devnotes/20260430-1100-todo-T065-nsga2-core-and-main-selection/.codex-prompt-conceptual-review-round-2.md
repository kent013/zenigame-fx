## 1. 背景・課題

synthesis § 7 で確定した **NSGA-II + 純 CPPS** の core 部分を zenigame-fx に big-bang 移植する。 既存実装 (絶対閾値直列フィルタ + 単純 fitness ranking) はベースラインにせず全廃。

T065 が提供する責務 (Phase 1 = 単体 module + テストのみ、 既存 ga loop に未配線):

1. **constrained-domination (Deb 2000)**: feasible vs infeasible は feasible 優先、 infeasible 同士は constraint_violation 小さい方優先、 feasible 同士は Pareto 3 軸 dominance
2. **non-dominated sorting (NSGA-II rank)**: 候補集合を Pareto front に分解
3. **crowding distance**: 3 軸正規化、 標準 NSGA-II (Deb et al. 2002)
4. **deterministic tie-break**: rank 同値 → crowding 同値 → `genome_hash` 昇順
5. **survivor selection**: rank + crowding で 親+子 (2*pop) から **pop 体抽出**
6. **binary tournament**: parent pair 抽出 (CA:DA 配分は T066 で確定、 T065 は配分関係なく候補から 2 体抽出)
7. **B-pooled 主選抜の axis 確定**: T064 BCEvaluationResult を Pareto 軸 source として使う唯一の経路 (synthesis § 3「主選抜評価値 = Stage B pooled」)
8. **A-fail / B-invariant-fail 個体除外**: T063 default-deny + T064 pareto_axis_usable を消費し、 Pareto 候補集合から両者を除外

T065 が**触らない** (別 TODO 担当):

- CPPS Push/Pull FSM (push/pull state 切替) — **T066**
- CA / DA 別 archive admission / eviction — **T066**
- archive 流入 (mission_pass / progress_pass / score_bypass) — **T067**
- crossover / mutation 実装 (genome operator) — **既存 + Phase 2 別 TODO**
- run_ga.py 配線 — **Phase 2 別 PR (T065-T067 統合と同時)**
- warmstart 注入 / Run 初期化 — **T067 (Loop closure)**
- observability (A→B 乖離 / entropy / front1 cardinality) — **T071**

### 1.3 T062 申し送り (T065 で確定する事項)

T062 詳細設計 line 181-187 から:

> 現仕様では `constraint_violation` は 4 slack 由来のみ。 `is_feasible=False` の原因が slack 外 (例: synthesis § 6.6 の `session_close_drop_count > 0` / `negative_equity_drop_open_count > 0` のみで slack は問題なし) の場合、 constraint_violation は 4 slack 計算値 (potentially 0 or 小さい値) になる。 T065 (constrained-domination) では「invariant violation の有無を Deb 2000 比較にどう組込むか」 を明文化する必要 (例: `constraint_violation + invariant_violation_penalty × Σ(strategic_* counts)` 等)

T065 での確定 (Round 1 [C2] 反映):

- T062 `MissionGapResult.constraint_violation` (slack 由来) と T061 `InvariantFlags` (`session_close_drop_count`, `negative_equity_drop_open_count`) を **合成した finite violation スカラー** を constrained-domination 用に新規定義
- **採用案**: `effective_constraint_violation = constraint_violation + INVARIANT_VIOLATION_PENALTY × invariant_count` (sum 合成、 Deb 2000 純準拠)
- **finite domain 制約 (Round 1 [C2])**: T062 `constraint_violation` が `+inf` (slack=-inf 由来) の場合、 T065 入口 `compute_effective_constraint_violation` で **ValueError raise** (運用 bug indicator)。 +inf 個体は upstream (T061 / T062) で fail-fast すべきという defense-in-depth 規約
- **不採用案 (lex 最高 priority key として invariant 独立扱い)**: scalar 単一前提 (Deb 2000) を破る。 archive eviction (T066) で別途 invariant 独立扱いは可だが、 NSGA-II constrained-domination 内では single scalar が純準拠

## 4. データフロー (per generation)

### 4.1 入力

```
population: dict[int, IndividualEvaluation]   # index -> 評価結果
pop_size: int                                  # 192 baseline / 256 promotion
rng: random.Random                             # deterministic seed (run_id + gen_no)
```

各 `IndividualEvaluation`:

```python
@dataclass(frozen=True)
class IndividualEvaluation:
    """T063/T064/T062/T061 の結果を統合した世代単位の個体評価."""
    index: int
    genome_hash: str                       # SHA-256 hex32 等、 deterministic tie-break
    stage_a_pass: bool                     # T063 a_pass_indices 由来
    bc_result: BCEvaluationResult | None   # T064 出力 (a_pass のみ非 None)
    mission_gap: MissionGapResult          # T062 出力 (全個体)
    invariant_flags: InvariantFlags        # T061 出力 (全個体)
```

### 4.2 処理ステップ

```
1. Pareto 候補集合の決定 (Round 1 [W1] 反映: stage_a_pass=True なら bc_result non-None 必須)
   for idx, eval in population.items():
       if eval.stage_a_pass and eval.bc_result is None:
           raise ValueError("T064 contract violation: a_pass=True but bc_result is None")
   eligible = {idx for idx, eval in population.items()
               if eval.stage_a_pass
               and eval.bc_result is not None
               and eval.bc_result.pareto_axis_usable}
   excluded = set(population) - eligible

2. Pareto 軸の抽出 (eligible のみ、 Round 1 [C3] 反映: finite check)
   axes[idx] = extract_pareto_axis(eval.bc_result, eval.mission_gap)
              = ParetoAxis(
                  net_pnl=bc_result.b_pooled_cf.net_pnl_after_cost,
                  max_dd=bc_result.pooled_dd_per_fold_max,         # synthesis § 5.2
                  mission_inf_gap=mission_gap.mission_inf_gap,
                )
   # extract_pareto_axis 内で 3 軸全て math.isfinite を assert
   # non-finite なら ValueError raise (運用 bug indicator、 T061/T062 が finite 保証すべき)

3. effective_constraint_violation 計算 (eligible のみ、 Round 1 [C2] 反映)
   violations[idx] = compute_effective_constraint_violation(
                       eval.mission_gap,
                       eval.invariant_flags,
                     )
   # constraint_violation が +inf なら ValueError raise (T062 fail-fast 失敗 indicator)

4. Non-dominated sorting (eligible のみ)
   front_no[idx] = non_dominated_sort(eligible, axes, violations, feasibility)
                   # constrained-domination 適用、 1=最優、 2=次優、 ...

5. Crowding distance (front 内 per-front、 Round 1 [W5] 反映)
   crowding[idx] = crowding_distance(front_indices, axes)
                   # 3 軸正規化、 端は +inf
                   # front_size <= 2 なら全員 +inf (Round 1 [W5])
                   # 軸範囲 0 (max==min) なら当該軸 0 寄与

6. Survivor 抽出 (target_size = pop_size、 Round 1 [W3] 反映: rng 不要)
   sorted by (front_no, -crowding, genome_hash)        # crowded-comparison operator
   excluded individuals (A-fail, B-invariant-fail) は survivor に含めない
   survivors = top pop_size of sorted

7. Parent pair 抽出 (binary tournament、 Round 1 [W2] 反映: pop_size ペア固定)
   pairs = []
   for _ in range(pop_size):
       p1 = binary_tournament(survivors, evaluations, rng=rng)
       p2 = binary_tournament(survivors, evaluations, rng=rng)
       # 自己交配回避: p1==p2 同一 hash の場合 max_retry=3 までリトライ (synthesis § 7.5)
       pairs.append((p1, p2))   # max_retry 超過は (p1, p1) で mutation only fallback
```

### 4.3 出力

```python

class GenerationSelectionResult:
```

## 5. constrained-domination (Deb 2000) の確定

### 5.1 数式 (Deb 2000)

```
constrained_dominates(p, q):
    # Step 1: feasibility-first
    if p.is_feasible AND NOT q.is_feasible:
        return True
    if NOT p.is_feasible AND q.is_feasible:
        return False
    # Step 2: both infeasible → smaller violation wins
    if NOT p.is_feasible:   # both infeasible
        return p.effective_constraint_violation < q.effective_constraint_violation
    # Step 3: both feasible → Pareto 3 軸 dominance
    return p.pareto_dominates(q)
```

### 5.2 effective_constraint_violation の確定 (T062 申し送り [W2] 解決、 Round 1 [C2] 反映)

T062 line 181-187 の申し送りに対する T065 の確定回答:

```
effective_constraint_violation =
    mission_gap.constraint_violation                      # 4 slack 由来 (T062)、 finite domain 必須
    + INVARIANT_VIOLATION_PENALTY × invariant_count       # invariant 違反加算
where:
    invariant_count = (
        invariant_flags.session_close_drop_count +
        invariant_flags.negative_equity_drop_open_count
    )
    INVARIANT_VIOLATION_PENALTY = 1.0e6                   # 4 slack の通常スケール (≤ 数十) を圧倒する大値
```

**finite domain 制約 (Round 1 [C2] 反映)**:

```python
def compute_effective_constraint_violation(mission_gap, invariant_flags) -> float:
    cv = mission_gap.constraint_violation
    if not math.isfinite(cv):
        raise ValueError(
            f"T062 constraint_violation must be finite, got {cv!r}. "
            f"+inf 由来 (slack=-inf) は upstream T061/T062 で fail-fast すべき。 T065 は finite 入力のみ受理"
        )
    inv_count = (
        invariant_flags.session_close_drop_count
        + invariant_flags.negative_equity_drop_open_count
    )
    if inv_count < 0:
        raise ValueError(f"invariant_count must be non-negative, got {inv_count}")
    return cv + INVARIANT_VIOLATION_PENALTY * inv_count
```

**根拠**:
- Deb 2000 は「single scalar violation」 を仮定。 fx では 2 種類の violation 源 (slack-based + invariant-based) があるため、 加算合成で single scalar 化
- `INVARIANT_VIOLATION_PENALTY = 1.0e6` は invariant 1 件で slack 由来 violation を支配する大値。 「invariant 違反 1 件 = どんな slack 不足個体より悪」 を実現
- count=0 (invariant violation なし) なら effective_constraint_violation == constraint_violation で T062 と整合
- pure function、 副作用なし、 deterministic
- **+inf 受理しない**: T062 の slack=-inf 由来 +inf は upstream で fail-fast すべき (defense-in-depth)、 T065 は finite domain でのみ動作

**代替案 (Round 1 議論候補、 不採用)**:
- 案 A: invariant_violation を独立 lex 最高 priority key にする → constrained-domination の 1 scalar 仮定を破る、 Deb 2000 純準拠崩れ
- 案 C: penalty を adaptive に (世代依存) → smoke 前は固定値が安全

**Decision Pending (smoke 後再校正候補、 § 13 残論点、 Round 1 [S2] 反映)**:
- INVARIANT_VIOLATION_PENALTY=1.0e6 は仮固定、 smoke 観測 DoD:
  - invariant violation 個体が rank 末尾に確実に行く (mass 配分検証)
  - all-infeasible front でも数値安定 (oscillation / overflow なし)
  - finite violation 域で penalty による monotone ordering が崩れない (slack 1 / invariant 1 比較等)

### 5.3 is_feasible の判定

```
is_feasible(individual) ⟺
    mission_gap.is_feasible                       # T062 (slack 4 指標すべて feasible)
    AND invariant_flags.is_feasible               # T061 (session_close_drop=0 AND negative_equity_drop_open=0)
```

両方 True で全体 feasible。 どちらか False で infeasible (= effective_constraint_violation > 0)。

### 5.4 Pareto 3 軸 dominance (feasible 同士)

```
p.pareto_dominates(q):
    # f1 maximize, f2 minimize, f3 minimize
    not_worse = (
        p.net_pnl >= q.net_pnl
        AND p.max_dd <= q.max_dd
        AND p.mission_inf_gap <= q.mission_inf_gap
    )
    strictly_better = (
        p.net_pnl > q.net_pnl
        OR p.max_dd < q.max_dd
        OR p.mission_inf_gap < q.mission_inf_gap
    )
    return not_worse AND strictly_better
```

NaN / Inf 防御:
- net_pnl: 通常 finite、 +inf/-inf 出現は T064 / T061 fail-fast でキャッチ済 (T065 では検証のみ)
- max_dd: T064 pooled_dd_per_fold_max (per-fold max)、 値域 [0, +inf)、 NaN は T064 で fail-fast
- mission_inf_gap: T062 で値域 [0, +inf)、 NaN は T062 fail-fast

→ T065 では NaN check は assertion レベル、 通常運用で発生しない (caller 責務)

## 8. tie-break (rank → crowding → genome_hash)

### 8.1 sort key 定義

```python
def sort_key(idx: int) -> tuple[int, float, str]:
    return (
        front_assignments[idx],          # 1, 2, ... 昇順 (front 番号、 小さい=優)
        -crowding_distances[idx],        # 大きい=優、 マイナスで昇順 sort
        evaluations[idx].genome_hash,    # 文字列昇順 (deterministic)
    )

survivor_sorted = sorted(eligible, key=sort_key)
```

### 8.2 genome_hash の生成方針

- SHA-256 hex digest (固定長 64 文字)
- 入力: genome の deterministic JSON 表現 (key 順固定、 float 精度規約)
- T065 では genome_hash は `IndividualEvaluation.genome_hash` で受け取り、 計算は caller 責務 (T058 schema v2 contract で確定済)

### 8.3 crowding +inf 端規約 (zenigame `sorting.py` 同等、 Round 1 [W5] / [C3] 反映)

front 内で各軸 sort 時:
- 端 2 個 (最小 / 最大) の crowding に `+inf` を加算 (端は常に保持)
- 中間個体は `(next - prev) / (max - min)` を 3 軸合計
- **front_size <= 2 (front 内 1 体 or 2 体) の場合、 全員 `+inf` (Round 1 [W5] 明文化)**

軸範囲ゼロ (max == min):
- 軸範囲 0 の場合、 当該軸の crowding 寄与は 0 (zenigame `sorting.py:97-104` 同等)

NaN / non-finite 防御 (Round 1 [C3]):
- axes 抽出時に `math.isfinite` assert 済 (§ 6 finite check、 `extract_pareto_axis`)
- non-finite が混入した場合は upstream の bug、 T065 入口で ValueError raise
- crowding 内では `inf - inf = NaN` の発生経路は断たれる (finite 軸保証下で)

### 8.4 ε 厚 fallback (zenigame `selection.py:140-159` 同等)

zenigame では crowding 中央値 ε ≈ 1e-12 で「ほぼ同値の crowding」 を tie-break する。 fx 流用方針:

- **Phase 1 では採用しない**。 単純に `(rank, -crowding, genome_hash)` の lex で確定的に解決
- ε 厚 tie-break は INCONCLUSIVE Decision (smoke 後 selection 多様性が低い場合に検討)

## 9. binary tournament (parent selection)

### 9.1 数式 (Round 1 [S1] 反映: crowded-comparison operator 直接使用)

```python
def binary_tournament(survivors, evaluations, sort_keys, *, rng):
    """survivor 抽出済集団から crowded-comparison operator で 1 体抽出.

    crowded-comparison operator (NSGA-II 標準、 Deb et al. 2002):
        i ≺_n j ⟺ (rank_i < rank_j)
                  OR (rank_i == rank_j AND crowding_i > crowding_j)
                  OR (rank_i == rank_j AND crowding_i == crowding_j AND genome_hash_i < genome_hash_j)

    sort_keys: dict[int, tuple[int, float, str]] = {idx: (rank, -crowding, genome_hash)}
    で事前計算 (run_generation_selection 内で 1 回計算、 tournament 毎の再計算回避)
    """
    a, b = rng.sample(survivors, k=2)
    return a if sort_keys[a] < sort_keys[b] else b   # tuple lex 比較で十分
```

constrained-domination は **survivor 抽出時 (non_dominated_sort) のみで使用**、 tournament 内では crowded-comparison operator (rank → -crowding → genome_hash) の lex 比較で簡潔に解決。 これにより tournament 計算量が `O(1)` per tournament call、 全 pop_size tournament で `O(pop_size)` (rank/crowding 事前計算は別途)。

### 9.2 自己交配回避 (synthesis § 7.5)

```python
def select_parent_pair(survivors, evaluations, *, rng, max_retry=3):
    p1 = binary_tournament(survivors, evaluations, rng=rng)
    for _ in range(max_retry):
        p2 = binary_tournament(survivors, evaluations, rng=rng)
        if evaluations[p2].genome_hash != evaluations[p1].genome_hash:
            return (p1, p2)
    # max_retry 超過 → mutation only fallback (caller 責務、 T065 では (p1, p1) で返す)
    return (p1, p1)
```

T065 内で `(p1, p1)` を返すと caller (Phase 2 breeding) で「mutation only」 経路に入る合意。 詳細設計時に caller 責務範囲を確定。

### 9.3 CA:DA 配分は T066 確定

- T065 では survivors 全体から binary tournament で抽出するのみ
- T066 で push/pull state に応じて「CA partition から N 体、 DA partition から M 体」 と source partition 分割
- T065 API は `survivors` を引数で受け取るので、 CA 用 / DA 用に partition して別々に呼ぶことで T066 が利用可能

import hashlib
def make_selection_seed(run_id: str, gen_no: int) -> int:
    """run 跨ぎ deterministic な seed を blake2b で生成."""
    payload = f"{run_id}|{gen_no}|selection".encode("utf-8")

## 13. 残論点 / Decision Pending

### 13.1 INVARIANT_VIOLATION_PENALTY 値の確定

### 13.2 effective_constraint_violation の Decomposition

T065 内では加算合成で single scalar 化。 archive eviction (T066) で「invariant 違反個体は CA に入れない」 等の lex 順序を別途定義することは T066 の責務。 T065 の constrained-domination 単体では single scalar で十分。

### 13.3 binary tournament k=2 vs k=3

synthesis § 7.1 で「binary tournament」 と確定。 k=2 で固定、 k=3 は INCONCLUSIVE (smoke 後 selection 多様性低下なら検討、 採用しない)。

### 13.4 crowding ε 厚 tie-break

zenigame `selection.py:140-159` の ε 厚 tie-break を fx でも採用するか。 Phase 1 では採用しない (genome_hash で十分)、 INCONCLUSIVE。

### 13.5 RNG seed 規約 (Round 1 [C1] 確定)

caller (T067) が `seed = int.from_bytes(blake2b(f"{run_id}|{gen_no}|selection", digest_size=8).digest(), "big")` で生成、 `random.Random(seed)` を T065 に渡す。 T065 は受け取るのみ、 `random.Random` API のみ使用 (`numpy.random` 等は不使用、 std lib のみ)。 詳細設計で seed 規約 + helper `make_selection_seed(run_id, gen_no)` を明文化 (T058 schema v2 contract と整合、 run_id は schema で確定済)。

**不採用 (Python `hash()` は process salt で run 跨ぎ非決定的)**: PYTHONHASHSEED=0 で固定する依存も unsafe (環境に依存)。 `blake2b` の cryptographic hash で完全 deterministic。

### 13.6 Survivor 抽出時の eligible 体数判定

eligible < pop_size で「全 eligible を survivor に」 する場合、 caller (Phase 2) は不足分を warmstart や fresh で補う必要。 T065 の sample_size_warnings で通知、 caller 責務の明文化は T067 で。

### 13.7 zenigame `optimize.py:2125,2141` の主選抜実装

handoff § 4.2 で zenigame 主選抜は `optimize.py:2125,2141` 同等とある。 詳細設計時に当該箇所を実 grep で確認、 fx 側 implementation の差分明示。
