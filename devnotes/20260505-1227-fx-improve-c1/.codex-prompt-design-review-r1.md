## 入力: 詳細設計

### C1: Stage partition/holdout 実測監査

**target_metric**: データ境界の正当性

**failure_mode**: `bars_stage_a=86400 / bars_stage_b=183403 / bars_holdout=20457` で stage_b が stage_a 含む可能性、 holdout=20457 (≈14日) は holdout_days=60 と乖離

**causal_path**: `stage_partition_guard.validate_stage_partition` が pass しているのに summary 表示の `bars_stage_b` が contract と異なる経路、 もしくは guard 自体に bug

**調査手順**:
1. `src/alpha_factory/stage_partition_guard.py` の `validate_stage_partition` を Read、 guard log 確認
2. dataset 実測 (Stage A 末尾 60 日、 Stage B = `[start, end - stage_a_window)` の重複検査)
3. summary `bars_*` の出処確認 (bars_stage_b が partition 後 vs dataset 全 bars どちらか contract と照合)
4. holdout 期間の乖離 (holdout_days=60 vs holdout bars=20457 ≈14日相当) の理由実測

**修正方針 (Case 分類)**:
- A: guard 健全 + summary 表記誤解 → docs 修正のみ
- B: guard 健全 + holdout 期間 DB 未提供 → fail-closed 不動作 → guard 強化
- C: guard 自体 bug → 実装修正 + テスト追加
- D: 全部問題なし → docs 説明追加

**波及変更**: docs/alpha_factory/stage-gates.md, runbook.md §4-1, AGENTS.md T087 節

**テスト**: `tests/alpha_factory/test_stage_partition_guard.py` 走破 + 修正時再現テスト追加

### C2: total_pnl=0.0 計測経路チェック

**target_metric**: total_pnl_min=50000 判定の正当性

**failure_mode**: best 個体 g54_i35 で trade_count=67, sharpe=0.24, total_pnl=0.0 の矛盾

**causal_path**: trade-level Sharpe (sharpe_calc_version=v2_trade_level) → summary 集約で PnL 合算経路に bug or 単位欠陥

**調査手順**:
1. best_genome.json から g54_i35 の genome_json 取得
2. Stage A 期間で local 再評価 → trade ledger 出力
3. trade ledger 集計 (Σ pnl_per_trade、 Sharpe 再計算で 0.24 と一致確認)
4. canonical_metrics 経路 / archive.py / diagnostics_collector.py で total_pnl 経路特定
5. trade-level Sharpe 設計確認 (PnL を normalize して計算する場合 total_pnl が常に 0 になる可能性)

**修正方針 (Case 分類)**:
- A: trade ledger positive で summary 0 → recording bug 修正
- B: trade-level Sharpe 設計上 total_pnl 常に 0 → live_criteria の total_pnl_min 判定再設計 (`大きな変更`、 cycle 2 持ち越し検討)
- C: trade ledger も 0 → 戦略実 PnL 0、 cycle 2 別問題

**Case B のリスク**: live_criteria 再設計は cycle 1 「最小変更」原則を逸脱、 cycle 2 持ち越し可能性あり

### W3: per_generation observability 整備

**target_metric**: 観測性 (null 率 < 10%、 dsr 計算 working、 archive_role/source_stage/fsp_* non-null)

**failure_mode**: per_generation の median_fitness_pen / stage_X_pass_count / population_diversity ほぼ全行 null。 dsr 全 NaN、 archive_role/source_stage/fsp_* 全空

**調査手順**:
1. run_ga.py の per_generation summary writer 経路特定
2. canonical_metrics.py の dsr 計算経路確認
3. archive.py の archive_role / source_stage / fsp_* writer 確認
4. null fallback の特定 (writer が None を渡しているか、 collector で None 上書きしているか)

**修正方針**:
- 観測経路欠陥のみ修正 (writer / collector のフィールド渡し)
- 計測ロジック不変 (mission 逸脱防止)
- dsr 計算 disable / sample size 不足が design なら docs に明記
