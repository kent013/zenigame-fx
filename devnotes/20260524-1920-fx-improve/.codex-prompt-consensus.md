# 背景と North Star
North Star = live_criteria 全達成個体を見つけ、達成後は閾値を引き上げる (緩和禁止)。live_criteria は mission の最終 gate。

# これまでの確定事実
1. **70k = validated frontier (3 seed 再現)**: total_pnl_min=70000 で R95(seedX) 378個体, R96(seed68) 209個体, R98(seed70) 634個体 が全 live_criteria (sharpe1.5∧pnl70k∧dd20%∧trade50-5000) を達成。
2. **pnl 引き上げ 70k→74k は in-loop で構造崩壊**: R97(seed70,74k) StageC=0。同一 seed70 の反実仮想 R98(70k) は StageC=634。→ 74k は GA 探索 funnel を崩壊 (低holdout-pnl + cross-pair basin へ移動)。cycle13 の trade_count_min=100 構造的到達不能と同型。74k 正式棄却。
3. **3 閾値 (sharpe_min/total_pnl_min/max_drawdown_max) は全て in-loop に作用**: Stage A 評価器 (window-scaled hard gate) + selection_score 連続値 (axis 正規化の target/lower) + mission gate boolean。→ どれを引き上げても pnl 74k と同型の funnel 崩壊リスク。「事後フィルタ安全」は in-loop 安全を保証しない (74k の教訓: 74k は R96 max80520 以下で post-hoc には安全に見えたが in-loop で崩壊)。
4. **R98 達成 StageC 分布 (n=634) は gate を大きく上回る**:
   - ann_sharpe: p10 4.70 / median 5.20 / p90 6.10 (gate sharpe_min=1.5 は極端に hollow)
   - max_dd_pct: median 1.48% / max 2.68% (gate dd_max=20% は極端に hollow)
   - total_pnl: p10 71270 / median 82420 / p90 92430
   全 634 個体が sharpe≥4.70・dd≤2.68%。
5. cross-pair (ii_lite) は holdout 品質と逆相関 (74k で ii_lite=188 だが StageC=0、70k で ii_lite=0/StageC=634) = 現フレームで mission 両立不可。

# 論点
「意味ある閾値引き上げ」(pnl) が in-loop 壁に当たった。達成品質 (sharpe5.2/dd1.5%/pnl82k) は優秀だが gate を意味ある幅で上げると探索が壊れる。次の一手の候補:

- (A) sharpe_min 1.5→3.0 or 4.0: 最も hollow (p10 4.70 で全個体クリア)。sharpe は GA primary fitness で自然に最大化されるため funnel 崩壊リスク最小の見込み。但し hollow=情報価値低。
- (B) max_drawdown_max 20%→5% or 3%: 達成 dd max 2.68% で margin 大、robustness 直結。dd_lower が selection に入るため中リスク。
- (C) pnl 小刻み増分 (72k): in-loop 天井を二分探索。但し 70→74 崩壊済で 72k も崩壊しうる + 7h コスト/run。
- (D) 非 selection-gate の新品質次元を additive に追加 (例: fold 一貫性要件強化 / 新 robustness metric)。funnel 非干渉だが実装コスト。
- (E) 70k/1.5/20% を frontier と認め、達成分布が gate を大きく超える事実を mission robust 達成として確定し、別改善 (探索効率/cross-pair別framework) へ方針転換。
