# 設計意図
F15(MTF構造手段)が holdout 非汎化で REJECTED。失敗様式「A/B 適合過多が holdout に汎化しない」を、
新 primitive でなく **fold-CV 安定性を連続値 selection key に織り込む**ことで抑制する。
holdout 情報は一切不使用 (Stage B fold 統計のみ)。default OFF で完全 bit-exact、ON 時のみ選択順序変化。

# robust_score 定義
```
robust_score = clip( w_pfre*positive_fold_ratio_effective
                   + w_sign*(1 - fold_sign_ratio)
                   + w_disp*(1 - norm_iqr), 0, 1 )
norm_iqr = clip( oos_total_pnl_iqr / (|median_oos_total_pnl| + 1e-9), 0, 1 )
```
pfre / fold_sign_ratio 欠損 → None (selection 上 -inf)。IQR/median 欠損 → disp_term=0.5 中立。

  (OFF でも算出するが _selection_key が無視)。CLI --robust-selection + 重み 3 flag。

# 重点レビュー観点 (high reasoning)
1. **bit-exact (最重要)**: robust_selection_enabled=False (default) で GA の RNG 消費・個体評価・
   selection 順序・archive 書込が cycle25 以前と完全一致するか。新列 oos_total_pnl_iqr が常に算出・
   永続化されるが、これが OFF run の決定論に影響しないか (並列 spawn worker 含む)。
2. **holdout リーク不在**: robust_score は Stage B fold 統計のみで、Stage C(holdout) 情報を一切
   使っていないか。median_oos_total_pnl / oos_total_pnl_iqr / pfre / fold_sign_ratio の出所確認。
3. **schema 後方互換**: GENOME_ENTRY_SCHEMA_VERSION を bump せず列追加した判断は妥当か。warmstart で
   旧 v2 archive (oos_total_pnl_iqr 欠損) を読む際に壊れないか。_detect_archive_schema_version への影響。
4. **robust_score 設計**: IQR 正規化 (|median|+eps)、欠損時 disp_term=0.5 中立補完、None→-inf 扱いは
   anti-overfit の意図 (fold 安定個体を優遇) に整合するか。selection key 下位 tie-break (feasibility/
   stage 通過の後) 配置で「生存集合は不変・順序のみ変化」という主張は正しいか。
5. **崩壊耐性の見込み**: この圧で pnl74k in-loop 崩壊 (R97: stage_c=0) を緩和できる因果が妥当か。
   逆に nsga2 のような median 退行を招くリスクと、Gate1 (stage_c>=650 & ann>=5.4) で検出可能か。
