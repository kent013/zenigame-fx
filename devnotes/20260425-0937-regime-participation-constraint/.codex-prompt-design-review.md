## 主要変更コード

施策 3 (IndividualCacheEntry):
```python
@dataclass(frozen=True)
class IndividualCacheEntry:
    generation: int
    fitness_pen: float
    stage_a_pass: bool
    stage_b_pass: bool
    stage_c_pass: bool
    feasible: bool = True
    violation_magnitude: float = 0.0

    @property
    def selection_score(self) -> tuple[int, float, int, int, int, float]:
        return (
            int(self.feasible),
            -float(self.violation_magnitude),
            int(self.stage_c_pass),
            int(self.stage_b_pass),
            int(self.stage_a_pass),
            float(self.fitness_pen),
        )
```

施策 4 (_update_cache):

施策 5 (summary.json):

## 依頼

上記詳細設計について、以下を厳しくチェックしてレビューしてください:
- (a) `IndividualCacheEntry` の dataclass で `feasible: bool = True` の default と既存 archive 不在 fallback (`fitness_pen=-math.inf`) との整合性
- (b) `selection_score` の `-violation_magnitude` で float NaN/inf 伝播がないか
- (c) Fallback ロジックが全個体 feasible=False かつ tournament 局所抽出時にも正しく動くか (sample 内に 1 体も feasible がない可能性)
- (d) archive `trade_count` 列の存在前提が現行 schema (genome_archive.py) と一致するか
- (e) summary.json schema バージョニングの方針 (v2_feasibility) で下流 (post-run-review/analyze-run) が壊れないか
- (f) ga.feasibility config validation の漏れ (entry_count_min が極端に大きい場合等)
- (g) frozen dataclass で `field(default_factory=...)` の相互作用 (Python 3.13)
