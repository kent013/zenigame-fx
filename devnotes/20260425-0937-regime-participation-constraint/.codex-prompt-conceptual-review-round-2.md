## 概念設計 (Round 2)

# 概念設計: regime-participation-constraint (RPC) — Phase 1 minimal

## 背景・課題 (観察事実)

直近 3 Run (Run 7/8/9) で確認された構造的問題:

- Run 9 (Fact): best 個体 g0_i1 は trade_count=0、Stage A pass 0/120、全120個体で total_pnl=0.0、90/120 個体で trade_count=0
- Run 8/7 (Fact): best は trade_count=1〜2 で sharpe>9.6
- Codex 独立分析の仮説1 (Interpretation): `trade_count=0` 個体の `fitness_pen=0` が、取引する個体 (負 Sharpe) より相対優位
- Codex 独立分析の仮説2 (Fact 候補): `trade_count>0 ∧ total_pnl=0` の整合性疑義

**根本原因 (Interpretation)**: 現行 fitness は「取引した結果の損益」のみを評価し、「取引しなかったこと」自体を評価していない。

**現行選抜の事実 (Fact)**: `scripts/alpha_factory/run_ga.py` L111-117 において、選抜は NSGA-II ではなく辞書式タプル `selection_score = (stage_c_pass, stage_b_pass, stage_a_pass, fitness_pen)` の tournament。

## 改善アイデア (Phase 1 最小版)

**Regime Participation Constraint (RPC) Phase 1**: 「`trade_count=0` 個体を構造的に下位化する feasibility 制約」を現行 `selection_score` の先頭に追加する最小変更。

- 各個体に `feasible: bool` (= `trade_count >= entry_count_min`、初期 `entry_count_min=1`) と `violation_magnitude: float` (= `max(0, entry_count_min - trade_count)`) を計算
- `selection_score` を 6 タプルに拡張:
  `(feasible_int, -violation_magnitude, stage_c_pass, stage_b_pass, stage_a_pass, fitness_pen)`
- 既存 fitness 関数・Stage 通過判定・archive 構造は変更しない

**Phase 2 (本 TODO スコープ外、別 TODO に分離)**:
- 9 セル regime 分類 (時間帯 × ボラ) に拡張
- archive へ participation 列永続化
- セル別エントリー回数最低保証 + min_cell_bars ノイズ対策

## 期待効果 (反証可能仮説のみ列挙)

- H1 (主目的): Run 10 の archive で `trade_count=0` 個体比率 (90/120 = 75%) が有意に低下する (例: 50% 未満)
- H2: best 個体が `trade_count=0` になる事象の頻度低下
- H3: Stage A pass 数の増加可能性 (副次効果として観察に留める)

**期待しない (検証仮説に降格)**: `trade_count=45/50` に直接到達。

**trade_count 影響予測: 増 (H1 が真なら確実)**

## 実装方針

1. **trade_count 取得**: `BacktestResult.trades` (List[Trade]) から `len(trades)`、archive 読み込み箇所 (L444-475) で feasibility 計算
2. **selection_score 拡張**: `_GenomeMetrics.selection_score` プロパティ (L111-117) に feasibility/violation を先頭追加
3. **config 追加**: `config/alpha_factory/default.yaml` に `ga.feasibility.entry_count_min` (初期値 1) と `ga.feasibility.apply_from_generation` (初期値 0) を追加
4. **診断ログ**: `summary.json` に「全個体 trade_count=0 比率」「feasible 個体数 per-generation」を追加 (archive Parquet schema 変更なし)
5. **Phase 2 への接続**: extension point を抽象化

## 制約・前提

### Fact
- 現行 GA 選抜実体は `scripts/alpha_factory/run_ga.py` (NSGA-II 化されていない)
- `selection_score = (C_pass, B_pass, A_pass, fitness_pen)` 辞書式 tuple
- `BacktestResult.trades` のみで trade_count 計算可能
- 既存 T016/T017/T025/T027 と直接重複なし

### Interpretation
- `tc=0` 優位の主因は selection_score の `fitness_pen=0.0` 同値構造
- selection_score 先頭への feasibility 追加で勾配を保ったまま `tc=0` を構造的に下位化
- Stage A pass 通過率分布は副次的に変化し得る

### 前提制約
- メモリ: float×2 追加のみ
- 並列性: GIL 影響なし
- 後方互換: 古い summary 読み込み時は default `feasible_int=1, violation=0` で復元
