# 概念設計: regime-participation-constraint (RPC)

## 背景・課題

直近 3 Run (Run 7/8/9) で確認された構造的問題:

- Run 9: best 個体 g0_i1 は trade_count=0、Stage A pass 0/120、全120個体で total_pnl=0.0、90/120 個体で trade_count=0。 GA は「無取引」へ収束した
- Run 8/7: best は trade_count=1〜2 で sharpe>9.6 と高数値だが、live_criteria.trade_count_min=50 から大きく乖離 (n=1〜2 では Sharpe の有意性自体疑わしい / C7 sample size 違反)
- Codex 独立分析の仮説1: `trade_count=0` 個体の `fitness_pen=0` が、取引する個体 (負 Sharpe) より相対優位になり、選抜圧が「無取引方向」に働いている
- Codex 仮説3: 評価関数の形が「取引しないほど有利」を生み、構造的に禁止事項 #6 (取引回数削減で見かけ成績) を再発させている

**根本原因**: 現行 fitness は「取引した結果の損益」のみを評価し、**「取引しなかったこと」自体を評価していない**。
そのため `tc=0` 個体は損益ゼロで安全 (fitness_pen=0)、取引する個体は失敗時に大きな負 fitness を被るため、選抜は「取引しない」を学習してしまう。

これは単純な penalty 追加では解決できない (penalty_threshold を超える `tc>0` 個体が一向に出現しない場合、勾配が消失するため)。

## 改善アイデア

**Regime Participation Constraint (RPC)** を **GA の実行可能性 (feasibility) 制約**として導入:

- Bar 系列を「時間帯 × ボラ regime セル」(例: 東京前場 × 低ボラ / ロンドン × 中ボラ / NY オーバーラップ × 高ボラ等、最大 N=9 セル) に分類
- 各個体について、各セルにおける **参加率 (participation rate = 該当セル内で 1bar 以上取引した個体ありの bar 比率)** を計測
- どのセルでも `min_participation_rate` (例: 0.05) を下回る個体は **`infeasible` フラグ立て** → 選抜では feasible 個体を優先 (NSGA-II constraint dominance に準拠)
- すべての個体が infeasible な世代では feasibility violation が小さい順に選抜 (gradient 維持)

これは既存の penalty 追加 (T027 calibrate-gate のような hard threshold 調整) とは異なり、**評価軸そのものに「regime 横断で動くこと」を組み込む**構造改善。

## 期待効果

- live_criteria.trade_count_min=50 達成への直接寄与: 9 セル × 各セル 5 trade 以上で trade_count=45 ペースに底上げされる
- 「特定時間帯だけ動いて他は寝る」個体の淘汰 → cross-pair / regime-aware の前提条件確立
- ATRRegimeGate を「通す/止める」設計から「**どの regime で参加するか**」を表現する gate へ意味再定義
- Sharpe 高値・trade_count 低値というサンプル過小バイアス (C7) の構造的解消
- **trade_count 影響: 増 (確実)**

## 実装方針（概要）

1. **Regime セル分類器の新設**:
   - `src/alpha_factory/regime/participation.py` (新規)
   - 入力: bars DataFrame (timestamp + ohlc) → 出力: 各 bar の `regime_cell_id` (0-8)
   - 軸: 時間帯 (Tokyo / London / NY-overlap, 3 区分) × ATR z-score (low / mid / high, 3 区分)
   - 当該 bar 時点までの rolling window から因果的に算出 (look-ahead 厳禁)

2. **Participation 計測モジュール**:
   - 既存 backtest result (trades / position 系列) から、各個体ごとに 9 セルの participation_rate を算出
   - `min_participation_rate` (config 値、初期 0.05) との比較 → feasibility flag

3. **GA selection への統合**:
   - `src/alpha_factory/ga/operators.py` または `runner.py` で NSGA-II 選抜時に **constraint dominance** を導入
   - feasible 同士 → 通常 Pareto 比較
   - feasible vs infeasible → feasible 勝ち
   - infeasible 同士 → violation magnitude 小さい方勝ち

4. **archive schema 拡張**:
   - `participation_cells` (List[float] of length 9), `feasibility_flag` (bool), `violation_magnitude` (float) を Parquet schema に追加

5. **config / live_criteria 整合**:
   - `config/alpha_factory/default.yaml` に `regime.participation` section を追加 (cells 定義 / min_rate / 適用世代範囲)
   - 既存 live_criteria.trade_count_min とは独立 (RPC は探索段階の制約、live_criteria は卒業条件)

## 制約・前提

- **Phase 2 architecture (Stage A/B/C / GenomeArchive / cross-pair shadow / swim-lane / 32 primitive) と整合**: 既存 Stage gate より上流 (GA 選抜時) に挿入するため、Stage 通過率の閾値変更は不要
- **既存 fitness 関数を変更しない**: penalty 追加 = sub-optimal local minimum 形成リスク。RPC は constraint dominance で gradient を保つ
- **Single instrument RUN でも有効**: 時間帯 × ボラの 2 軸は通貨ペア数に依存しない
- **メモリ制約**: 24GB × 6 ワーカー。1 個体あたり 9 cells × 4 bytes = 36 bytes 追加のみ
- **既存 T016 (cross-pair shadow), T017 (swim-lane), T025 (sieve), T027 (calibrate-gate) との重複なし**: それらは「卒業判定 / OOS / Stage A 閾値」を扱うが、RPC は「**選抜時の feasibility 制約**」という独立した層
