# 概念設計: `_bars_cache._compute` Python loop 軽量化 (bid/ask local 化)

## 背景
profile (`profile_20260505_211017` cycle 2/3 後 baseline):
- `_compute` line 59: tottime **1.160s / 15 calls / 77ms each** (eval 内 5%)
- 本番投影 ×295.9 = 343s = 5.7 分

現実装 (line 59-84):
```python
for i, b in enumerate(bars):
    bo = float(b.bid.open); bh = float(b.bid.high); bl = float(b.bid.low); bc = float(b.bid.close)
    ao = float(b.ask.open); ah = float(b.ask.high); al = float(b.ask.low); ac = float(b.ask.close)
    o[i] = (bo + ao) * 0.5
    ...
```

`b.bid` / `b.ask` attribute access が 1 bar あたり 8 回 (= 86400 × 8 × 15 = 10.4M access)。

## 改善
bid/ask を 1 bar あたり 1 回ずつローカル化:
```python
for i, b in enumerate(bars):
    bid = b.bid  # 1 access
    ask = b.ask  # 1 access
    o[i] = (float(bid.open) + float(ask.open)) * 0.5
    h[i] = (float(bid.high) + float(ask.high)) * 0.5
    low[i] = (float(bid.low) + float(ask.low)) * 0.5
    c[i] = (float(bid.close) + float(ask.close)) * 0.5
```

attribute access 8→2 per bar、 中間変数削減 (bo/bh/bl/bc/ao/ah/al/ac 不要)。

## 期待効果
- per-call 77ms → 50-60ms (20-35% 削減 first hypothesis)
- 本番 RUN 削減 1.5-3% (target 3% は upside)
- microbenchmark で相対比較 15%+ 高速確認 (cycle 2/3 T089 と同じ pattern)

## 実装方針
- 1 ファイル (`_bars_cache.py:59-84`) の `_compute` 本体修正
- Numba 不可 (Decimal、 cycle 1 broker mock 同様)
- 純 Python の attribute access 削減のみ

## 数値同値性
- 演算順序完全同一 (bid 先 ask 後、 mid 計算 (a+b)*0.5)
- 出力 ndarray bit-identical (`np.array_equal`)
- 既存 test 全 pass

## 制約・前提
- FX 絶対制約に影響なし (signal 値計算用)
- メモリ: stack 軽量化のみ
- T030 read-only 契約維持
- microbenchmark で相対比較 ratio<0.85 確認必須

## スコープ外
- broker mock Decimal → float64 (大規模型変更)
- DSL composite (前 reject)
- per-bar logging (profile 上 hot path 外)
