## 入力: 詳細設計

(`devnotes/20260505-2121-bars_cache_compute_local_var/detailed-design.md` 参照)

擬似コード:

```python
def _compute(bars):
    length = len(bars)
    o = np.empty(length, dtype=np.float64)
    h = np.empty(length, dtype=np.float64)
    low = np.empty(length, dtype=np.float64)
    c = np.empty(length, dtype=np.float64)
    for i, b in enumerate(bars):
        bid = b.bid  # was: b.bid.open等で 4 回 LOAD_ATTR
        ask = b.ask  # was: 4 回
        o[i] = (float(bid.open) + float(ask.open)) * 0.5
        h[i] = (float(bid.high) + float(ask.high)) * 0.5
        low[i] = (float(bid.low) + float(ask.low)) * 0.5
        c[i] = (float(bid.close) + float(ask.close)) * 0.5
    return o, h, low, c
```

テスト計画:
- `test_compute_local_var_refactor_numerically_identical`: oracle (現行実装) との完全一致
  cases: 通常 / 1 bar edge / 異なる bid/ask 値 / NaN 含む bar
- `test_compute_microbenchmark_non_regression`: 軽量版 ≤ oracle × 1.10 (非退行)、 必須 gate ではない
- profile 再計測: `_compute` tottime が 1.160s → 1.05s 以下 (10% 削減 first hypothesis)

期待効果:
- per-call 77ms → 65-73ms (5-15%、 反証可能仮説: 主因 float(Decimal) で削減限定的)
- 本番 RUN 削減 0.5-1.5%
