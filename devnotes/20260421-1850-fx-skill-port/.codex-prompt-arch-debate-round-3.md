## Q10. 有効サンプルサイズの再検証（Q5 の前提）

## Q11. DSR/PBO/Reality Check 実装コストの現実性（Q7 の含意）
Round 2 で「DSR/PBO/RC/SPA を計算器として持つ」と推奨されたが、これらは新規インフラで Phase 2-4 のスコープを大きく増やす。

1. **DSR (Deflated Sharpe Ratio)** の最小実装コスト:
   - 必要なのは `n_trials, n_observations, sk, kt, mean_sr, max_sr, std_sr` 程度
   - GA 1 Run で計算可能か? 候補数 N_trials は population × stages か Run 全体か?
2. **PBO (Probability of Backtest Overfitting)** の CSCV 計算コスト:
   - S=8 で C(8,4)=70 組合せ。各組合せで in/out 入れ替えて Sharpe 比較
   - 1 ゲノムあたり 70 回再評価が必要か? それとも全候補 × 70 か?
   - 計算量見積: pop=40 × gen=15 × 6 pairs × 70 CSCV = 252,000 評価/Run。実用範囲か?
3. **Reality Check / SPA** ブートストラップ:
   - B=1000 として、何のメトリクスをブートストラップするか? trade レベル PnL?
   - 計算量と統計検出力のトレードオフで、現実的な妥協点は?
4. **代替案 — 簡易版で十分か?**:
   - Hansen-Lunde adjusted Sharpe（個別 Sharpe を試行回数で割引）など、軽量近似で代用可能か?
   - 簡易版で false positive 率がどれくらい上がるか
5. **反証**: フル実装が現実的でなければ、`shadow 評価のみ → hard gate 化を断念` という再修正が必要か?

## Q12. max_clause=1 開始は実質フラット化のリスク（Q9 I2 への深堀り）
Q9 I2 で「max_clause=1 で開始しても gate と重み機構は初日から実装すべき」と指摘あり。
だが max_clause=1 のとき、`composite = clause_weight × clause_score = clause_weight × dir_score × gate` であり、
clause_weight はスケール因子に過ぎず、本質的に `dir_score × gate` の単一式。
これは現フラット 4 式（entry_long/short, exit_long/short）と何が違うのか?

1. **max_clause=1 でも残す価値のある構造要素**:
   - directional / local_gate の分離（zenigame 流の signal カテゴリ）
   - signal 加重和の正規化 (Σ|w|)
   - gate sigmoid の steepness 学習
   - これらが実装されていれば max_clause=2 への昇格は smooth か?
2. **max_clause=1 と現フラット式の本当の違い**:
   - フラット式は entry / exit を別 Expr で持つが、Clause は composite > entry_threshold で statefully 制御
   - 後者は exit 条件の扱いが本質的に異なる（exit は composite < exit_threshold？保有期間 time_stop？）
3. **max_clause=2 への昇格テスト**:
   - Q5 で「max_clause=3 が 2 に対して同計算予算で OOS DSR を有意改善できなければ棄却」とあった
   - ではどう「同計算予算」を保つか? max_clause を増やすと探索空間が広がるが世代数を減らすか?
4. **反証**: max_clause=1 で十分な性能が出てしまったら、Clause 構造への移行は無意味化するか?

## Q13. (ii-lite) shadow → hard gate 化の判定基準（Q9 残存課題）
Q9 で「shadow Phase 2 → hard gate Phase 4」と提言されたが、shadow 期間で何を測れば「hard 化してよい」と判定できるか不明。

   - shadow 通過率（per-instrument champion のうち何 % が ii-lite を通過するか）の分布が安定すべき
2. **hard 化判定基準**:
   - shadow 通過率の median が 30-70% 範囲に入るか?（極端に通る/落ちるなら gate 機能していない）
   - shadow 不通過 champion の事後 OOS 性能が、shadow 通過 champion より統計的に劣るか? (= shadow が真に予測力がある証拠)
3. **hard 化失敗時の rollback 手順**:

   - rollback 履歴の管理
4. **反証**: shadow 期間でいくら走らせても判定不能なら、hard 化は永久 shadow になるか?
