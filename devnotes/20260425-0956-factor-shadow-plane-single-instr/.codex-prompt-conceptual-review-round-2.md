# 概念設計: factor-shadow-plane (FSP) — single instrument 専用 diagnostic layer

## Dispatch matrix

| RUN 形態 | factor data | 動作 |
|---------|--------------|------|
| multi-pair RUN | available | 既存 ii-lite (T016)、FSP skip |
| multi-pair RUN | unavailable | ii-lite のみ、FSP skip |
| single instrument RUN | available | **FSP active** |
| single instrument RUN | unavailable | `skipped_no_factor_data` |

## Sampling granularity (日次のみ)
- DXY daily 系列 + daily PnL 集計
- M1 補間なし、`factor_asof_lag=1`
- `fsp_sampling_mode = "daily"`

## Conditioning set 固定
- 全 bar grid (ポジション無し日含む)
- 全個体 (survivor フィルタ禁止)
- 列名: `fsp_explained_variance`, `fsp_partial_corr`

## 計測内容
- daily PnL × DXY daily return の rolling 60 日 Spearman + 全期間 OLS R²
- archive 新列: fsp_runtime_mode (enum), fsp_sampling_mode, fsp_factor_set, fsp_rolling_corr_60d, fsp_explained_variance, fsp_idio_ratio

## Falsifiable criteria

H1: `fsp_runtime_mode="active"` 比率 > 90%
H2: factor-heavy fixture 個体を `idio_ratio < 0.2` と判定
H3: 異 seed 3 RUN で best 個体の idio_ratio std < 0.1

K1: active 比率 < 50% → 設計欠陥
K2: factor-heavy fixture を idio_ratio > 0.5 と誤判定 → 識別性なし
K3: RUN 時間 2 倍 → unacceptable

## trade_count 不変の必須条件 5 つ
1. archive immutable 確定後の別 task
2. GA worker 内では計算しない
3. 失敗時 graceful degradation
4. factor 系列は run ごと 1 回構築
5. 統計は streaming/vectorized

## 依頼

以下を確認願う:
- (1) 4 つの主要修正 (dispatch / sampling / conditioning / criteria) で Round 1 Critical はすべてカバーされたか
- (2) daily granularity への変更は使命寄与を保てるか (M1 RUN との関連性は十分か)
- (3) 全 bar grid + 全個体の conditioning set は collider bias を本当に回避できるか
- (4) Phase 1 success criteria (H1/H2/H3) と kill criteria (K1/K2/K3) は実装可能で falsifiable か
- (5) post-RUN 独立 task の運用設計は GA RUN との競合を起こさないか
- (6) trade_count 不変の 5 条件は十分か

残存 Critical があれば修正案、なければ APPROVED 判定願う。
