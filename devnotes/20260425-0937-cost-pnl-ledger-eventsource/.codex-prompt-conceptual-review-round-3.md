## 改訂版 概念設計 (Round 3)

# 概念設計: cost-pnl-ledger-eventsource (Stage A 記録整合性監査 — sidecar 版)

> **改訂履歴**
> - Round 1 → Round 2: PnL ledger SSOT 化を棄却、Stage A 投影仕様問題に焦点化
> - Round 2 → Round 3: archive Parquet schema extension を棄却、sidecar diagnostics に変更 (28 カラム fixed schema との整合性確保)。優先度を Critical → Medium (observability task) に修正。Phase B/C は将来 TODO 化。

## 背景・課題

Run 9 (run_20260425_002330) の Codex 独立分析で `trade_count > 0 ∧ archive.total_pnl == 0.0` が観測された。

**前提検証 (verified)**:
- 現行 backtest 側では `total_pnl = sum(Trade.pnl)` で正しく集計されている (`src/backtest/metrics.py#L85-L89`)
- `Trade.pnl` には closing 時点で `raw_pnl - holding_cost` の net_pnl が入る (`src/broker/mock.py#L327-L353`)
- Stage A の payload は `trade_count` と `sharpe_raw` のみで `total_pnl` を持たない (`src/alpha_factory/stage_gate.py#L268-L333`)
- archive への Stage A collect も `trade_count / sharpe` のみで `total_pnl` を書かない (`src/alpha_factory/archive.py#L322-L346`)
- 設計文書もこの仕様を明示 (`docs/alpha_factory/clause-architecture.md#L356-L365`)
- **archive schema は 28 カラム固定** (`src/alpha_factory/archive.py#L51-L101` `GENOMES_SCHEMA`、import-time assert)
- 既存合意は「Run 10 では監査のみ、挙動非変更」

**真の課題 (observability gap)**:
Stage A 段階で archive に `total_pnl` が転記されない設計のため、Stage A で落ちた個体は archive 上 `total_pnl=0.0` のように見える。これが「PnL 集計バグ」「Stage A 落ち個体」「コスト過大計上」のいずれによる 0 なのか、post-run 分析で切り分けが困難。
**Run 10 blocker ではない observability task** として位置付ける。

## 改善アイデア (sidecar diagnostics 版)

### Phase A (本 TODO スコープのみ): Stage A 記録整合性監査 (sidecar, audit-only, fail-open)

**archive Parquet schema は touch しない** (28 カラム fixed schema 厳守)。

代わりに `reports/run-reports/run-{N}/diagnostics/stage_a_provenance.parquet` を **sidecar ファイル**として出力する。

1. **Stage A backtest 結果の補足記録 (sidecar)**:
   - 各個体行: `genome_id / metric_stage / trade_count / total_pnl_stage_a / sharpe_stage_a`
   - `metric_stage` ∈ {"stage_a_only", "stage_b_evaluated", "stage_c_evaluated"}
   - 既存 archive 列は不変、archive consumer は影響を受けない
2. **Stage A backtest 結果の payload 補足**:
   - `stage_gate.py` の Stage A payload に `total_pnl` / `metric_stage` を追加 (in-memory のみ、archive には書かない)
   - sidecar writer がこの payload を読んで sidecar parquet に出力
3. **既存の `summary.json` schema は最小限のみ拡張**:
   - 新規 optional field `diagnostics_sidecar` (path 文字列のみ)
   - consumer は missing field を無視できる
4. **run-report skill での可視化**:
   - run-report がこの sidecar を optional で読み、「Stage A 落ち個体の total_pnl 分布」セクションを追加
   - sidecar 不在時は section 省略 (後方互換)

### Phase B (将来 TODO, 本スコープ外)
コスト taxonomy + sidecar 拡張。Phase A の sidecar 観測結果を踏まえて再判定。

### Phase C (将来 TODO, 本スコープ外)
CI invariant ハーネス。`summary.diagnostics.invariant_violations` 追加は別 TODO で扱う。

## 期待効果

- **直接効果**: Run report で「Stage A 落ち個体の total_pnl 分布」が可視化され、Run 9 の謎 (`trade_count>0 ∧ archive.total_pnl=0`) の正体が即座に切り分け可能になる
- **副次効果**: Phase B/C 着手前のベースラインデータ蓄積、後続 cost-efficiency 改善 (5 件) の効果測定基準点

## 実装方針 (Phase A 最小変更)

- `src/alpha_factory/stage_gate.py`: Stage A payload に `total_pnl` / `metric_stage` を追加 (in-memory のみ)
- 新規: `src/alpha_factory/diagnostics_sidecar.py` (sidecar writer、純粋関数)
- `scripts/alpha_factory/run_ga.py`: GA 完了後に sidecar writer を呼び出し
- `.claude/skills/zenigame-fx-run-report/SKILL.md`: optional セクション追加 (sidecar 不在時 skip)
- 新規テスト: `tests/alpha_factory/test_diagnostics_sidecar.py`

### CI invariant のみ (production fail-open)

- I1: sidecar 行数 == backtest 評価された個体数
- I2: `metric_stage` の値が enum 内
- I3: `total_pnl_stage_a` が finite

production GA では fail-open: sidecar 書き込みエラーは warning ログのみ、GA 自体は止めない。

## 制約・前提

- **archive Parquet schema は完全に touch しない**: 28 カラム fixed schema 厳守
- **summary.json schema 拡張は最小限**: optional field `diagnostics_sidecar` (path) のみ

- **既存 Stage A/B/C ゲートロジックは touch しない**
