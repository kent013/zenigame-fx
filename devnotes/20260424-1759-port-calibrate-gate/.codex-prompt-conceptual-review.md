# 概念設計: calibrate-gate port + Stage A threshold 動的調整

## 1. 目的

GA Run 終了後に **archive Parquet** から Stage A の実通過率を計算し、
`config/alpha_factory/default.yaml::stage_gate.stage_a.threshold` を
次 Run 用に自動調整する skill / scripts を実装する。これにより
`stage_gate.stage_a.target_pass_rate: 0.15` が設計目標として機能し、
exploration / exploitation のバランスが Run 間で自己整合する。

## 2. 背景

- T014 で Stage A 評価関数は実装済み (`evaluate_stage_a`、`fitness_pen >= threshold` で pass)
- T015 で archive に `stage_a_pass: bool` を 1 行 / 個体で記録
- T018 で run_ga.py が swim_lane × Stage A/B/C を archive に書き出すフロー完成
- 現状 threshold は `0.0` 固定。実 Run の pass 率がどうなるかは Run しないとわからず、
  毎 Run 手動チューニングは現実的でない
- zenigame 版は `stage_b_ratio` (Stage A → B 進出個体率) を LLM で調整しているが、
  zenigame-fx は **Stage A 自体の閾値** を動かす設計（より直接的な制御点）

### 名前に立ち返る (`機能の名前に立ち返れ` 原則)

- `stage_a.threshold`: 「fitness_pen の最低水準」。
  下げれば pass 増、上げれば pass 減。
- `stage_a.target_pass_rate`: 「全 Run / 全世代を均すと、結果として何割が
  Stage B に進むことを設計目標とするか」。**実 pass 率は世代ごとにブレるので
  target は中央値ベースで判断する**（target ± tolerance 帯で判断）。

## 4. アルゴリズム設計

### 4.1 入力

- archive Parquet: `.cache/alpha_factory/runs/genomes_{run_id}.parquet`
- 集計対象: **Stage A まで到達した全行** (= Parquet 全行、Stage A は最初の関門)
- pass rate: `stage_a_pass=True` の行数 / 全行数

### 4.2 deterministic 調整ロジック (PID-like の P 項のみ + dead-band + clamp)

```
target = config.stage_gate.stage_a.target_pass_rate    # 例 0.15
tol    = 0.05  # ±5pt の dead-band（target=15% → 10〜20% は変更なし）
actual = stage_a_pass_count / total_count
prev   = config.stage_gate.stage_a.threshold

# fitness_pen の現実的レンジを推定（量子的な絶対値ではなく分位差で動かす）
q_target = quantile(fitness_pen_all, 1 - target)   # 「target 通過率を達成する仮想 threshold」
q_prev_pass = quantile(fitness_pen_all, 1 - actual) ≒ prev (整合確認用)

if abs(actual - target) <= tol:
    # 目標範囲内 → 変更なし
    new = prev
    decision = "in_band"
elif actual > target + tol:
    # 通り過ぎ → threshold を上げる
    # 新 threshold = q_target にスナップ。ただし変更幅 <= max_step
    new_raw = q_target
    decision = "tighten"
elif actual < target - tol:
    # 通らなさすぎ → threshold を下げる
    new_raw = q_target
    decision = "loosen"

# 変更幅クランプ（暴走防止）: 1 Run あたり Δ <= max_delta_abs かつ Δ <= max_delta_relative * |prev|
delta = new_raw - prev
delta = clamp(delta, -max_delta, +max_delta)
new = prev + delta

# 絶対値クランプ（極端な値の防御）
new = clamp(new, threshold_floor, threshold_ceiling)

# 小数桁丸め
new = round(new, 4)
```

#### パラメータ既定値（SSOT は yaml の `stage_gate.stage_a.calibrate` セクション）

| パラメータ | 既定 | 意味 |
|-----------|------|------|
| `tolerance_band` | 0.05 | actual と target の差が ±tol 以内なら無変更 |
| `max_delta` | 0.50 | 1 Run の絶対変更幅上限 (fitness_pen の単位) |
| `threshold_floor` | -100.0 | 下限（Run 1 のように全 fail でも下限はある） |
| `threshold_ceiling` | 100.0 | 上限 |

これらは `config/alpha_factory/default.yaml::stage_gate.stage_a.calibrate.*` に置く。

### 4.3 LLM 判断 vs deterministic の比較

| 観点 | deterministic (本 TODO) | LLM (将来 TODO) |
|------|----------------------|----------------|
| 再現性 | 完全に再現可（input → output 一意） | seed/prompt 依存で variance |
| 説明性 | 数式 / dead-band で明示 | 自然言語で根拠説明、ただし post-hoc |
| 失敗モード | 数値 outlier に脆弱 (quantile 計算) | hallucination, 過剰チューニング |
| 拡張性 | 追加 metric を入れる度に式の再設計 | 新変数を context に足すだけで対応 |
| API コスト | ゼロ | Codex/LLM 呼び出し費 |
| 監査ログ | 全式・全クランプを構造化ログ出力 | LLM 出力 + reasoning |
| 適用フェーズ | Phase 2 (現状) | Phase 4 以降、cross-pair / DSR / regime も併合判断するとき |

**結論**: Phase 2 の責務は「target_pass_rate を成立させる」だけで、判断の自由度を上げる必要は無い。
deterministic で十分。LLM 判断は別 TODO で導入余地を残す（同じ scripts に
`--judge=llm` モードを追加する形を想定）。

### 4.4 dead-band 必須の理由

「数値を見て即座に閾値を弄るな」原則。世代数 = 15、population = 30 の
Tier1 lane を 6 ペア張ると、1 Run の総評価数は最大 ~2700。target=0.15 で
±5pt は ±135 個体程度の幅。これより小さい変動はノイズと見なし、無変更。

## 7. 失敗モードと対処

| 失敗 | 検出 | 対処 |
|-----|-----|------|
| archive Parquet 0 件 | n_rows == 0 | スキップ + 報告（exit 3） |
| stage_a_pass フィールドが全 False かつ n < 10 | sample size guard (C7) | 提案出力のみ、yaml 不変 + WARN |
| `calibrate.enabled: false` | yaml 読み込み | exit 4 + 報告 |
| yaml 編集失敗 (Permission, parse error) | 例外 | exit 5 + ロールバック |

## 8. テスト方針

- **mock archive で pass rate 計算**: pass 件数 0 / 50% / 100% / 中間値で classification 確認
- **dead-band**: target±tol 内 → no change
- **過剰高 (actual > target+tol)**: 新 threshold > prev (tighten)
- **過剰低 (actual < target-tol)**: 新 threshold < prev (loosen)
- **max_delta clamp**: quantile が極端な値でも Δ <= max_delta
- **floor/ceiling clamp**: 極端な fitness_pen でも new in [floor, ceiling]
- **dry-run**: yaml の SHA256 が前後で一致
- **disabled**: `calibrate.enabled=false` → exit 4 + 不変
- **archive 0 件**: skip + exit 3

## 9. リスク

1. **fitness_pen の単位想定が外れる**: Stage A は backtest sharpe ベース。
   絶対値が大きい / 負方向に振れる傾向がある。floor/ceiling の既定 ±100 は
   現状の sample (Run 3 で fitness_pen ≈ -47〜-65) を覆うが、
   将来 fitness_metric を変えたら再調整が必要 → SSOT で yaml に出している
2. **target_pass_rate の単一スカラーで全 lane を縛るリスク**:
   Tier1 ペアごとに難易度が違う場合、single threshold では不公平。
   Phase 4 で per-lane 化 (calibrate-gate-v2 TODO) を予定
3. **GA の generation 横断で actual を計算する**:
   後半世代ほど selection pressure で pass 率が上がる（survivor bias）。
   現状は全世代平均だが、終盤世代だけで判断するオプションも残せる
   (`--window=last_n_generations N`)。**本 TODO では未実装**
