## 概念設計

# 概念設計: Stage B 統計可観測性ハード契約 (Metric Completeness Gate)

## 背景・課題

直近 Run 7-9 の archive 集計で以下の構造的問題が観測された:

- `fold_sign_ratio: n=0` (全 120 個体で集計値なし)
- `dsr: n=0` (全 120 個体で DSR が記録されない)
- Stage B pass: 0/120 (連続 3 Run で完全 0)
- Stage A pass: 0-66/120 と大きくばらつく

`src/alpha_factory/stage_gate.py` の `evaluate_stage_b` を確認すると、`dsr` フィールドは hard-coded で `None` (L460: `"dsr": None,  # Phase 4 で hard 化`)、`fold_sign_ratio` は metric envelope に含まれていない。fold が `oos_sharpe=None` を返した場合、現行は「`0.0` に impute して母数に含める」処理 (L420-421) のみで、欠損自体を Stage 通過判定に反映する経路がない。

つまり「統計が取れていない」状態と「統計が取れた上で弱い」状態が区別できず、過学習判定が空洞化している。`stats_unavailable` を `pass=True` の暗黙余地に流す現行設計は **C8 INCONCLUSIVE を pass 扱いに混入** させる点で過学習耐性を毀損する。

## 改善アイデア

Stage B の `metrics.payload` に **必須計測フィールド** を定義し、欠損 (`None` / `n=0` / 全 fold unavailable) なら `passed=False` を **強制** する契約層を導入する。

具体:

1. `fold_sign_ratio` (= 正 fold 数 / 有効 fold 数) を Stage B metrics に標準で記録
2. 必須フィールド集合 `{n_fold, n_fold_unavailable, fold_sign_ratio, median_oos_sharpe}` の **欠損** または **有効 fold 数 < 閾値 (例: 3)** で `reason_code=stats_unavailable` を強制追加
3. archive parquet 書き込み時 (genome_archive 経由) に `fold_sign_ratio` / `n_fold_effective` を columnar で永続化
4. run-report 側で「Stage B 計測欠損率」を世代別に表示 (監査性向上)

**重要**: 本提案は Stage B 通過率を「弱さで落とす」のではなく **「測定不能で落とす」** 経路を新設する点が核。落ちた個体は `stats_unavailable` 理由で識別され、原因が「シグナルが弱い」のか「fold 評価が機能していない」のかを分離できる。

## 期待効果

- live_criteria 達成への貢献:
  - Stage B = 0 連続の根本原因 (弱さ vs 測定不能) を診断可能化 → 改善ターゲットを正確に絞れる
  - 「単発 1-2 trade の Sharpe 9.66」が Stage A を抜けて Stage B に到達した時、fold 評価不能を理由に確実に落ち、過学習候補が live_criteria 評価系に流入しなくなる
- 統計検定の hard 適用前提 (`dsr` / `pbo` の今後の hard 化) に必要な土台を先に固める
- 過学習耐性: fail-open → fail-closed 反転で「測れていない」優位を構造的に排除

## 実装方針 (概要)

変更コンポーネント:

- `src/alpha_factory/stage_gate.py`:
  - `StageGateConfig` に `stage_b_min_effective_folds: int = 3` を追加
  - `evaluate_stage_b` で `fold_sign_ratio` を計算し metrics.payload に格納
  - 有効 fold 数 (`n_fold - n_fold_unavailable`) が閾値未満なら `stats_unavailable` reason 追加 → `passed=False`
  - `all_folds_unavailable` を `stats_unavailable` に統合 (上位概念で吸収)
- `src/alpha_factory/genome_archive.py` (or schema 定義箇所):
  - archive Parquet schema に `fold_sign_ratio: float?` と `n_fold_effective: int?` を追加
  - 既存行は `null` で前方互換
- `scripts/alpha_factory/generate_run_report.py`:
  - Stage B セクションに「fold 計測欠損率」「`fold_sign_ratio` 分布」を追記
- テスト: `tests/alpha_factory/test_stage_gate.py` に契約テスト追加

## 制約・前提

- 既存 `evaluate_stage_b` のシグネチャ・戻り値型 (`StageResult`) は変更しない (downstream 安全)
- archive schema 拡張は **追加のみ** (削除・型変更なし)、Parquet 互換性維持
- `stage_b_min_effective_folds=3` は既存 `wf_test_days` / `wf_step_days` から逆算される最大 fold 数 (現行 default で typically 6-12 fold) より十分小さく、現実的に取れる個体は落とさない
- メモリ: 追加メトリクスは個体あたり数バイト (float / int 2 個)、120 個体 × 6 lane でも < 10KB、問題なし

## スコープ外

- DSR / PBO の値そのものを hard gate 化する (本提案は「測定可能性」のみを担保。値の hard 化は別 TODO)
- Stage A / C への同等契約導入 (Stage B が現状最大のブラックボックスなので B に絞る)
- WF fold 設計の改善 (regime stratification 等) は別 TODO
- Sieve OOS 期間動的化は別 TODO
