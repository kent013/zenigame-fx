【思考原則 — 全議論に適用】
まず仮説を立てろ。何を検証したいのか、なぜそう考えるのか、どうなれば成功と判断するのかを明確にしてから手を動かせ。

データに真摯に向き合え。数値を見て即座に閾値を弄るな。何が起きているのかを理解し、なぜそうなったのかを考え、どの方向に進むべきかを判断してから手を動かせ。

先人の知恵を探せ。学術論文・実務文献の引用を歓迎する（著者・年・タイトルを明記。記憶が曖昧なら「要確認」と明記）。

機能の名前に立ち返れ。名前はその機能が果たすべき役割を示している。

仕組みが機能していない段階で値を弄るな。設計の方向性が正しいと確認できてから値を弄れ。

因果ループを切断するな。「XはYに影響しない」という主張に出会ったら、間接経路を含む因果ループ全体を追え。

【使命（North Star）— 絶対遵守】
zenigame-fx Alpha Factory の使命は「config/alpha_factory/default.yaml → live_criteria を全て満たす FX イントラデイ戦略ゲノム個体を 1 つ見つけ出すこと」。
Stage C 通過は最低条件。使命達成 = live_criteria の全指標（Sharpe, Total PnL, Max Drawdown, Trade Count 範囲）を同時に満たし、Cross-pair (ii-lite) 評価も通過した個体の出現。

## 検証観点

### A. epoch_manager.py の正しさ (= 詳細設計 行 50-619 の意図充足)

A1. **`EpochWindow` identity 契約**: frozen + (start, end) のみで identity、 ``__post_init__`` で end > start 強制。 `make_epoch_id` の出力が (start, end) のみで決まることをコードレベルで確認。

A2. **`make_epoch_id` grammar 整合**: T058 の `DATASET_EPOCH_ID_PATTERN = ^[a-z0-9_]+$` に常に適合。 `strftime("%Y%m%d")` の出力 (8 桁数字) が pattern の `[a-z0-9_]+` に含まれることを確認。

A3. **window 計算の deterministic 性**: `_compute_window(epoch_index)` が `anchor_origin + STRIDE_DAYS * epoch_index` を end に、 `end - WINDOW_LENGTH_WEEKS` を start にする。 同 epoch_index で常に同 window。

A4. **reserve_run_slot の atomic 性**: file lock (fcntl LOCK_EX) で全工程を保護、 lock 内で load → verify → advance check → duplicate check → save の順序が崩れていないか。

A5. **fingerprint の `Z` vs `+00:00` 偽不一致回避**: state file から読んだ anchor_origin を `_normalize_dt(... → astimezone(UTC).isoformat())` に揃えてから比較。 Round 1 [Suggestion] の意図充足。

A6. **全 epoch run_id 一意性 (Round 1 [Critical] 1)**: `for past_epoch_key, past_records in state["run_records"].items(): if run_id in past_records:` で全 epoch 走査。 同 epoch 内 / 他 epoch どちらでも同 run_id を弾く。

A7. **reset の破損対応 (Round 1 [Critical] 2)**: `_load_state_no_init` が `EpochStateCorruptError` を raise した時、 `try/except` で捕捉し audit に `{"corrupt": True, "error": ...}` を記録、 reset 自体は完遂。

A8. **reset の lock 競合防止 (Round 1 [Warning] 1)**: `with self._file_lock():` で全体保護。 別 process が lock 保持中は `EpochLockTimeout` を raise。

A9. **`_init_state` instrument 照合 (Round 1 [Warning] 4)**: state file 不在時の初期化経路でも `dataset_cfg.instrument != self.instrument` で `EpochStateIncompatible`。

A10. **fcntl lock の Linux/macOS 前提**: Windows 非対応であることを docstring / 設計で明示。

### B. test_epoch_manager.py の網羅性

B1. **詳細設計 行 627-690 の test 計画**: 全項目が test 関数として実装されているか (Window identity 6 / Grammar 1 / Reservation 4 / Advance 2 / Mismatch 1 / Fingerprint 4 / Corruption 2 / Duplicate 3 / Lock 2 / Status 4 / Reset 7 / Atomic save 2 = 38)。

B2. **multiprocess test の安定性**: `mp.get_context("spawn")` を使い、 `pytest.skip` で worker 起動失敗を救済、 `proc.join(timeout=...)` + `terminate` でクリーンアップ。 fcntl は spawn 前 process でのみ holds、 child 終了で確実に解放される。

B3. **Round 1 [Critical] 反映の verifying test**:
- [Critical] 1 (全 epoch run_id 一意): `test_reserve_raises_duplicate_run_id_error_when_same_id_in_other_epoch` / `test_run_id_uniqueness_enforced_globally_across_epochs`
- [Critical] 2 (reset 破損対応): `test_reset_recovers_even_when_state_json_is_corrupt` / `test_reset_records_corrupt_flag_in_audit_log_when_state_was_corrupt`

B4. **テスト命名規則 (AGENTS.md)**: 振る舞いを説明する汎用的な名前か。 日付・セッション固有 NG。

B5. **isolation**: `tmp_path` fixture を使い、 永続化 path に書き込まない。 monkeypatch で ClassVar (LOCK_TIMEOUT_SECONDS 等) を一時切替。

### C. run_ga.py の stub 置換の妥当性

C1. **backward compat 維持**: try/except で fallback。 EpochWindow 構築 / make_epoch_id 呼出が想定外の例外を投げた場合も `generate_epoch_id_stub(cfg.dataset)` で従来通り `epoch_legacy` を返し、 RunContext / threshold 解決の下流が壊れない。

C2. **deterministic 性**: 同じ `cfg.dataset.start/end` から常に同 dataset_epoch_id (smoke fixture 2026-01-01 / 2026-01-08 → `epoch_20260101_20260108`)。

C3. **logger 整合**: `run_ga.epoch_id_deterministic_fallback` warning を fallback 時のみ発火、 主経路 (deterministic 成功時) は既存の `ga.run.start` log で `dataset_epoch_id` を引き続き出力。

C4. **caller signature 影響なし**: `dataset_epoch_id` は単一 `str` で、 既存 `_resolve_stage_a_threshold` / `RunContext` / `archive`/etc. への引渡しは値だけ変わる (= `"epoch_legacy"` から `"epoch_20260101_20260108"` 等の deterministic 値)。 signature / 型は完全に維持。

C5. **Phase 2 申し送り**: `EpochManager.reserve_run_slot` の runtime 組込 / `default.yaml` の 24m 切替 / `--reset-epoch-state` 3-flag は 別 PR (= Phase 2)、 T059 PR 1 では deterministic 生成までで止まっていることをコメントで明示。
