## 詳細設計の内容 (要点)

### C1: Stage B gate `profit_safe_pfr` opt-in mode

#### 1. config 変更 (StageGateConfig)

```python
stage_b_gate_kind: Literal["legacy", "profit_safe_pfr"] = "legacy"
profit_safe_pfr_threshold: float = 0.4
profit_safe_pfr_min_n_fold: int = 20
```

#### 2. evaluate_stage_b 変更 (stage_gate.py)

fold loop で `fold_total_pnl` を集計し、集計時に `median_oos_total_pnl` を計算。判定分岐:

```python
if stage_config.stage_b_gate_kind == "legacy":
    # 完全不変
    if median_oos < stage_config.stage_b_median_oos_sharpe_min:
        reasons.append("median_oos_sharpe<min")
    if positive_ratio < stage_config.stage_b_positive_fold_min:
        reasons.append("positive_fold_ratio<min")
elif stage_config.stage_b_gate_kind == "profit_safe_pfr":
    # cycle 22 T099 MODIFY: profit_safe_pfr
    if positive_ratio_effective is None or positive_ratio_effective < stage_config.profit_safe_pfr_threshold:
        reasons.append("positive_fold_ratio_effective<min")
    if median_oos_total_pnl is None or median_oos_total_pnl < 0:
        reasons.append("median_oos_total_pnl<min")
    if n_fold_effective < stage_config.profit_safe_pfr_min_n_fold:
        reasons.append("n_fold_effective_below_profit_safe_min")
else:
    raise ValueError(f"unknown stage_b_gate_kind: {stage_config.stage_b_gate_kind}")
```

#### 3. payload 拡張

`stage_b_gate_kind`, `median_oos_total_pnl`, `oos_total_pnls`, `profit_safe_pfr_threshold`, `profit_safe_pfr_min_n_fold` を payload に追加。

#### 4. archive 拡張

archive Parquet に optional column `median_oos_total_pnl`, `stage_b_gate_kind` を追加。**GENOME_ENTRY_SCHEMA_VERSION は v2 据え置き** (optional/nullable column 追加で互換)。

#### 5. CLI

```python
p.add_argument("--stage-b-gate-kind", choices=["legacy", "profit_safe_pfr"], default=None)
```

main で override:

```python
if args.stage_b_gate_kind is not None:
    config = replace(config, stage_gate=replace(config.stage_gate, stage_b_gate_kind=args.stage_b_gate_kind))
```

#### 6. selection_score 後段 mask (trade_sharpe_stage_b > 0)

archive 集計後・GA selection 前のステップで profit_safe_pfr mode のとき:

```python
if config.stage_gate.stage_b_gate_kind == "profit_safe_pfr":
    for entry in genome_entries:
        if entry.get("stage_b_pass") and entry.get("trade_sharpe_stage_b") is not None:
            if entry["trade_sharpe_stage_b"] <= 0:
                entry["stage_b_pass"] = False
                entry["stage_b_reason_codes"] = (
                    (entry.get("stage_b_reason_codes") or "") + ";trade_sharpe_stage_b<=0_post_filter"
                ).lstrip(";")
```

## 質問

### Q1. 上記設計を APPROVE するか?

特に以下の点に懸念がないか確認:

- `evaluate_stage_b` 内 fold loop での `fold_total_pnl` 集計は既存 `bt.total_pnl` (BacktestMetrics) から取得。fold 失敗時は 0.0 を imputed する (= legacy `oos_sharpes_imputed` と同じ pattern)。これは合理か?
- archive schema version を v2 据え置きで optional column 追加は後方互換性を維持するか?
- post-filter (trade_sharpe_stage_b <= 0 で stage_b_pass を false に reverse) の配置は archive 集計後・GA selection 前で問題ないか? あるいは evaluate_stage_b 内で直接判定すべきか?

### Q2. NaN 伝播 / エッジケース

- `bt.total_pnl` が `None` の場合 (fold 計算成功でも metrics 一部 None の可能性) の挙動は?
- `median_oos_total_pnl` が NaN になるケースは?
- profit_safe_pfr mode で n_fold=0 / n_fold=1 のエッジケース (現行 legacy は no_folds / insufficient_folds を append) と整合か?

### Q3. 既存テストへの影響

- 既存 `tests/alpha_factory/test_stage_gate.py` の Stage B fixture が **default `legacy`** で動作することは保証されるか? それとも一部テストが fail するか?
- archive schema v2 据え置きで既存テスト (test_archive.py) は不変か?

### Q4. 考慮漏れ

- 上記設計に Critical / Warning レベルの考慮漏れはあるか?
- 特に「stage_b_reason_codes」の文字列フォーマット (post-filter で `";trade_sharpe_stage_b<=0_post_filter"` を append) は既存パーサと整合か?
- ロング/ショート別の pnl 検証は本施策では実装しないが、profit_safe_pfr mode が「ロングのみ強い、ショートで赤字補填」を見落とす可能性は? (improvement-plan §H-monitor は別 TODO)

### Q5. メモリ・パフォーマンス

- `oos_total_pnls` を payload に追加することで in-memory payload サイズが増えるが、24GB / 2 ワーカー (各 3GB) で問題ないか?
