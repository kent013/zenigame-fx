2. clause 1 collapse (active_clause 1.01)、多様性崩壊 (unique fp 6.2%)

### 統合改善提案

#### #1 [Critical] T099 MODIFY (profit-safe pfr)

Stage B gate を opt-in で改修:
- 新 mode `profit_safe_pfr`: `pfr >= 0.4 AND median_oos_total_pnl >= 0 AND trade_sharpe_stage_b > 0`
- default mode `legacy` (現状: `median_oos_sharpe + pfr` AND) は不変
- CLI `--stage-b-gate-kind {legacy, profit_safe_pfr}` で切替
- Run 75 smoke で `profit_safe_pfr` を実行、legacy 比で A/B 評価
- 変更分類: **Structural** (新ガード追加、Reactive Parametric ではない)
- target_metric: Stage B 通過群 median_oos_total_pnl ≥ 0 達成率 / Stage C trade_sharpe median / Stage C pass count
- failure_mode: Run 74 で Stage B 通過 96 個体全員赤字、ρ(median_oos_sharpe → stage_c_sharpe) = -0.361
- causal_path: median sign 検査 → curve-fit 選好 → Stage B 通過個体が実利益を伴わない → Stage C で剥落
- falsification: profit_safe_pfr mode で (a) Stage B pass 数 が legacy 比でほぼ 0 に崩壊、(b) Stage B 通過群 median total_pnl が依然 negative、(c) Stage C trade_sharpe median が legacy より悪化 → いずれか発生で仮説否定
- success_criterion: profit_safe_pfr mode で Stage B 通過群 median_oos_total_pnl ≥ 0 ∧ Stage C trade_sharpe median ≥ legacy ∧ Stage B pass 数が運用可能水準を維持

## 質問

#### Q1. #1 (profit-safe pfr) の最終確定

施策 #1 を以下の確定形で APPROVE するか:

- 実装方針:
  - `StageGateConfig` に `stage_b_gate_kind: Literal["legacy", "profit_safe_pfr"]` + `pfr_threshold: float = 0.4` を追加
  - `evaluate_stage_b` 分岐:
    - `legacy`: 現行 (`median_oos_sharpe + positive_fold_ratio` AND)
    - `profit_safe_pfr`: `positive_fold_ratio_effective >= pfr_threshold AND median_oos_total_pnl >= 0 AND trade_sharpe_stage_b > 0`
  - CLI `--stage-b-gate-kind {legacy, profit_safe_pfr}`
  - payload に `stage_b_gate_kind` / `pfr_threshold` / 各条件の値を記録
- Run 75 smoke 実行: `--stage-b-gate-kind profit_safe_pfr --instrument EUR_JPY --population-size 96 --generations 60 --seed 60 --max-workers 2 --mutation-rate 0.5`
- 失敗時 (falsification 条件 a/b/c のいずれか発生) の挙動: cycle 23 で legacy に戻し、別仮説 (clause 強制 / multi-instrument) を試す

**archive 列確認結果**:
- 既存列: `total_pnl`, `fold_sign_ratio`, `n_fold_effective`, `positive_fold_ratio_effective`, `median_oos_sharpe`, `trade_sharpe_stage_b`
- **`median_oos_total_pnl` は archive に存在しない** → **新規集計が必要**

実装追加:
- `evaluate_stage_b` の fold loop で各 fold の total_pnl を集計し、median を計算 (`median_oos_total_pnl` フィールドとして payload に追加)

- これは Structural 変更（fold 評価メトリクス追加）で Reactive Parametric ではない
