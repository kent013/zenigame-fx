## 2. `InstrumentMeta` 拡張

```python
# src/broker/mock.py
@dataclass(frozen=True)
class InstrumentMeta:
    """MockBroker が個別銘柄について把握しておくべき最小情報。

    SSOT 境界:
        * `src/domain/instrument.py::CurrencyPair` は ingest / oanda 層 SSOT で、
          pip_location / minimum_trade_size / maximum_order_units を含む
          full pair catalog を保持する。
        * `InstrumentMeta` は broker / backtest 層 SSOT で、P&L 計算・margin 検証に
          最低限必要な情報のみを保持する。pip_size / display_precision は
          テスト・ログ・将来の slippage モデルでの利用を見越して**派生情報として
          保持**する（CurrencyPair からコピー可能）。

    Phase 4 note:
        * 本 Phase では home=quote を前提に動作する。Phase 4 で
          `home != quote` をサポートする際は、MockBroker 側で
          `fx_rate_provider` (新規引数) を受け取り quote→home 換算を実行する設計。
    """

    oanda_name: str
    base_currency: str
    quote_currency: str
    margin_rate: Decimal
    # 以下は後方互換のため default 付き追加
    pip_size: Decimal = Decimal("0.0001")
    display_precision: int = 5

    def __post_init__(self) -> None:
        if self.pip_size <= 0:
            raise ValueError(f"pip_size must be > 0: {self.pip_size}")
        if self.display_precision < 0:
            raise ValueError(f"display_precision must be >= 0: {self.display_precision}")
```

**デフォルト値の根拠**: default は USD-quote pair (EUR_USD 等) の標準値 (0.0001 / 5)。既存 USD_JPY / EUR_JPY ヘルパ (`usd_jpy_meta` 等) は引数無指定だと USD-quote default が返るが、`test_mock_broker.py` は `entry_price * units` 系の検算しかしておらず `pip_size` を参照しない → **挙動不変**。しかし明示的に正しい値を渡すために `_helpers.py` 側で JPY default を渡すよう更新する（§4 参照）。

### 2.1 frozen dataclass で `__post_init__` を使う注意点

`@dataclass(frozen=True)` で `__post_init__` は許可されるが、属性への再代入は不可。上記は validate のみで値変更していないので問題なし。

### 6.2 Scale 不変性 Sharpe 計算

`src/backtest/metrics.py::compute_metrics` で Sharpe を取得。Sharpe 計算は trade-based のため、2 ケースとも trades を発生させる必要がある。`DslStrategy` をそのまま使うと複雑なので、**シンプルな hand-crafted 2 trade** で済ませる:

- 時刻 0-5 の 6 bar（USD_JPY なら minutes=0-5）で単調上昇 → open_long + close_position を test が直接 submit
- scale ケース A: initial_cash=1_000_000, units=10_000
- scale ケース B: initial_cash=10_000_000, units=10_000（= k=10）
- 両者で Sharpe を計算、diff < 1e-6

**補足**: trades 2 件では Sharpe の分散が不安定（std が極小 → Sharpe 極大）。多数 trade を捏造するよりも、**equity_curve ベースで returns の std/mean を取って比較**する方が確実。MockBroker.equity は linear scale で 1_000_000 にも 10_000_000 にも乗るので、returns (diff/prev) は scale 不変。

実装簡略化: Sharpe ではなく `equity_curve returns の std / mean` を直接比較してもよい。テストの**実質的な検証は「home 通貨の数値スケール変更で P&L 系列が比例する」ことが核**なので:

```python
def _equity_returns(broker, bars):
    snapshots = [broker.snapshot().equity for ... ]
    returns = [(s1-s0)/s0 for s0, s1 in zip(snap[:-1], snap[1:])]
    return returns
```

returns 系列がほぼ同一 → Sharpe 同一が結論される。実装は**両方 (equity returns 近似 + Sharpe 直接) の assert** を置き、仕組みの堅牢性を示す。
