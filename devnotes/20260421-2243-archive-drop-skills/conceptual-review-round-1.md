- [Suggestion] Fact: 提案内容は期間延長・閾値緩和・GA 歪曲・取引回数操作・オーバーナイト化を含みません。

- [Critical] Fact: 設計本文自身が「`_archived/` 配下を skill 候補として自動検出しないか未確認」としています。

- [Warning] Fact: `git mv` と README 追加だけなら技術的難度は低いです。  
  Interpretation: 実装自体は容易ですが、成功判定は skill 検出仕様に強く依存します。  
  修正提案: 実現可能性の節に「実装容易 / 検証依存」の二段構造を書き分けてください。

  Interpretation: もし他の `zenigame-*` skill も現段階で実用不能なら、ノイズ削減効果は限定的です。  
  修正提案: 全 skill を棚卸しし、「archive 対象」「残置対象」「将来移植対象」の 3 区分を先に定義してください。少なくとも「なぜ 7 件だけで十分か」の根拠が必要です。
- [Suggestion] Fact: sample size や collider bias は本件では主論点ではありません。  
  Interpretation: ただし「候補数が減る = 誤起動が減る」は因果としては妥当でも、検出ロジック未確認のため効果推定はまだ弱いです。

  Interpretation: 一律に「動かない skill」とだけ書くと、将来の port 判断材料を失います。  
  修正提案: README に各 skill ごとに「依存先」「現状 NG 理由」「FX 側で再設計するなら何を置換するか」を 1 行ずつ残してください。
