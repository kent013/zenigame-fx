## 概念設計

# 概念設計: 無取引優位の遮断設計 (risk-no-trade-fitness-guard)

## 背景・課題

### Run 9 で観測された構造的問題

- archive 全 120 個体: total_pnl 全 0.0, fitness_pen mean=-8.91 / max=0.0
- trade_count=0 個体が 90 (75%) — fitness_pen=0.0 付近に集まる
- trade_count>0 個体 30 のうち sharpe は全て負 (min=-93.10, max=-4.76) → fitness_pen 大きく負
- 結果: GA 選択圧で「無取引個体 (fitness_pen=0)」が「取引するが負 sharpe (fitness_pen<<0)」より相対優位
- best 個体が g0_i1 (trade_count=0, fitness=0) で固定、世代を経ても plateau

### 構造的根本原因

stage_a の no_trades reason は記録されるが、fitness_pen の数値そのものがペナルティ対象になっていない。stage_a 通過判定では弾かれても、GA 選択 (runner._tournament / sort by fitness_pen) には fitness_pen が直接使われるため、「stage 通過しなくても fitness_pen=0 が選ばれる」 → 無取引個体が survive。

これは禁止事項 #6 「取引回数を削減して見かけの成績を上げる」の構造的・自然発生バージョン。ルール緩和をしていなくても、評価関数の形が「取引しないほど有利」を生む。

## 改善アイデア

trade_count が最小エクスポージャ閾値未達の個体について、fitness_pen を「リスク評価不能」として明示的に大きい負値領域に送る。

- GaConfig に新規フィールド min_exposure_trade_count: int を追加
- Individual の fitness_pen 計算前に、trade_count < min_exposure_trade_count なら fitness_pen を _NO_EXPOSURE_FITNESS (-1e10 程度) に置換
- evaluator から渡される meta に trade_count が含まれていることを前提
- 書き換え後の fitness_pen を archive にも保存

### 設計原則

- trade_count_min (live_criteria) の閾値は弄らない (禁止事項 #4)
- 新閾値は live_criteria より十分小さい値
- fitness_raw は変更しない (観察値は保持。ペナルティは fitness_pen のみ)
- stage_a の判定ロジックは変更しない

## 期待効果

- Sharpe: 取引する個体に GA 選択圧が向く → 正 sharpe 個体が発生する素地
- Total PnL: 同上
- Max Drawdown: 実測値が出る → リスク制御の動作テストが入る
- Trade Count: trade_count_min 達成への進化経路が確保
- Stage 到達率: 「stage_a 通過の前提条件」が GA 選択側でも満たされやすい
- diagnose 可能性: archive 上で「reason='no_exposure'」が事後追跡可能

## 実装方針

| コンポーネント | 変更内容 |
|---------------|---------|
| src/ga/runner.py | GaConfig に min_exposure_trade_count 追加 / _evaluate で meta['trade_count'] を参照し閾値未満なら fitness_pen を _NO_EXPOSURE_FITNESS に上書き |
| config/alpha_factory/default.yaml | ga.min_exposure_trade_count の追加 |
| scripts/alpha_factory/run_ga.py | YAML → GaConfig 注入経路 |
| src/alpha_factory/archive.py | (任意) no_exposure_penalty 列追加検討 |
| tests | test_runner_no_exposure_penalty.py 新規 |

stage_gate.py の判定は触らない。fitness.py の _FAILURE_FITNESS も触らない。

## 制約・前提

- イントラデイ前提 (変更なし)
- ロング・ショート両方向 (変更なし)
- evaluator が meta['trade_count'] を返している
- 既存テスト：fitness_pen 直接比較箇所が破壊されないこと

## スコープ外

- live_criteria.trade_count_min の変更
- Stage B/C の閾値変更
- fitness_raw の変更
- max_pos / max_dd / time_stop 等の他リスク統制
- 評価指標の根本変更
- complexity penalty の構造変更

## 想定リスク

- min_exposure_trade_count を高くしすぎると初期世代で全員ペナルティ → GA 機能不全
- _NO_EXPOSURE_FITNESS を -math.inf にすると数値演算破綻 → 有限な大負値 (-1e10)
- trade_count が meta に無い evaluator (dummy) との後方互換 → デフォルト 0 + 警告ログ

## 関連背景情報 (C4 確認用)

- src/ga/runner.py で fitness_pen は GA 選択 (sort/tournament) のキー
- src/ga/fitness.py で _FAILURE_FITNESS = -1e12 (metric 不能時)
- src/alpha_factory/stage_gate.py で stage_a は no_trades / below_threshold 等の reason を記録するが、これは stage 通過判定であり GA 選択ではない
- src/alpha_factory/archive.py の row template で fitness_pen のデフォルトは 0.0
- live_criteria.trade_count_min = 50 (config/alpha_factory/default.yaml)
