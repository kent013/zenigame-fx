## レビュー観点 (Falsification-first、 Round 1)

### 1. 数式実装が synthesis § 6 + 概念設計 と 厳密一致

- compute_sr_session_worst の Bartlett kernel 数式 (gamma_b(k)、 sigma2_LR_b、 SR_b)
- compute_session_block_win_rate_worst の trade=0 → 0.5 neutral
- compute_signed_slacks の denom_floor=1e-6 厳密
- annual 換算 `sr_worst_block_scale * sqrt(N_BLOCKS_PER_YEAR=756)` の責務単一化
- gate_worst_gap = max_m max(0, -slack_m)、 gate_pass <=> gap <= GATE_PASS_TOLERANCE AND is_feasible
- log_pf_clip = clip(log((GP+1e-6)/(GL+1e-6)), -2, 2)
- slack_to_range の 3 分岐 (value<L / L<=value<=U / value>U) と numerator/denom 分離契約

### 2. 入力契約 invariant 検証 (concept Round 1 [W1] [W2] 反映)

- `TradeRecord.__post_init__`: UTC-aware + utcoffset==0、 entry<exit、 business_day_index>=0、 pnl_net finite
- `BarEquitySeries.__post_init__`: len>=1、 全 timestamp UTC-aware、 strict monotone increasing、 全 equity finite
- `CanonicalFiveThresholds.__post_init__`: 全 field finite>0、 trade_count_min<=trade_count_max、 win_rate_min in (0,1)、 max_dd_max in (0,1)
- _validate_trade_attribution(provider) hook の interface signature 妥当性

### 3. 出力契約 (CanonicalFiveResult)

- raw 6 field (block-scale + annual_estimate)
- per-bucket diagnostics (sr / wr / low_sample_buckets)
- signed slack 5 + aggregate 2 + auxiliary 3 (log_pf_clip / bucket_validator_version / invariants)
- frozen dataclass であること

### 4. concept Round 3 [W1] / [W2] / [S2] 吸収

- [W1] `infeasible_reason_codes` の 2 分類 prefix (`strategic_*` / `input_*`) は明確に区別できているか
- [W2] `GATE_PASS_TOLERANCE = 1e-9` が numerical noise 許容として妥当か
- [S2] `bucket_validator_version` (default "unvalidated"、 provider 注入時 provider.version 記録)

### 5. 例外設計

- `CanonicalMetricsInputError` (基底)、 `TradeRecordInvalidError` / `BarEquityInvalidError` (派生)
- top-level `evaluate_canonical_five` は raw exception を呼出側に伝播せず、 全て `infeasible_reason_codes` に変換 + gate_pass=False で返す deterministic 契約
