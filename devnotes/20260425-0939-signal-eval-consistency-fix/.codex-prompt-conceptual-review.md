## 概念設計

# 概念設計: signal-eval-consistency-fix (評価・選抜の整合性修復)

## 背景・課題

### 観察事実 (run-9 / run-8 / run-7 横断)

run-9 (run_20260425_002330) の archive 横断分析で、以下の構造的問題が確認された:

1. **`trade_count > 0` でも全個体 `total_pnl = 0.0`**:
   - n=120 で `total_pnl` の min=max=mean=0.0
   - 30 個体 (25%) で `trade_count > 0` であるにもかかわらず `total_pnl = 0.0`
   - これは PnL 集計経路ではなく **記録経路の不整合** が主因

2. **無取引個体 (`trade_count = 0`) が選抜優位**:
   - `fitness_pen = 0` の個体 90/120 (75%) はすべて `trade_count = 0`
   - 取引した 30 個体は `fitness_pen = -8.91 ~ -93.10` (全て負 Sharpe)
   - `(stage_c_pass, stage_b_pass, stage_a_pass, fitness_pen)` の辞書式 best 選抜で、Stage A 不通過個体間では `fitness_pen = 0` (無取引) > `fitness_pen < 0` (損失) が成立

3. **GA が「無取引」へ世代収束**:
   - 世代平均 `trade_count`: 380.9 → 100.6 → 44.7 → 14.2 → 22.15 → 82.1
   - 中盤に強い無取引偏向、終盤にやや回復

### コード側の検証 (C4: 前提検証)

`src/alpha_factory/archive.py` `collect_stage_a` (L337-346): `total_pnl` の更新が無い
`src/alpha_factory/stage_gate.py` `evaluate_stage_a` payload (L325-333): `total_pnl` を payload に入れていない
`collect_stage_b` の `total_pnl` 更新 (L398-401): Stage B が走らない (Stage A 不通過) 個体は **`total_pnl` が schema default の 0.0 のまま** 永続化される。

### 選抜面の構造問題

`run_ga.py` (Phase 2 ga-architecture) は archive の `(stage_c_pass, stage_b_pass, stage_a_pass, fitness_pen)` 辞書式比較で best を選ぶ。
**Stage A 不通過個体の比較で `fitness_pen` が支配的** だが、現状:
- 無取引 → `fitness_pen = None` → archive default `0.0`
- 取引したが負 Sharpe → `fitness_pen < 0`

→ 0.0 > 負値 で **無取引が常勝**。これは「取引回数削減で見かけ成績を上げる」禁止事項 #6 の構造的再発。

## 改善アイデア

### A. Archive 記録経路の整合性修復 (Fact 修復)

**A-1. Stage A payload に `total_pnl` を載せる**:
`evaluate_stage_a` の payload に `bt.total_pnl` を追加。
`collect_stage_a` で `row["total_pnl"]` を更新。

### B. 選抜面の「無取引優位」是正 (構造修復)

**B-1. `fitness_pen = None` (system_failure / no_trades / metric_unavailable) を archive で明示的に負の番兵値で表現**:
- 現状: `payload["fitness_pen"]` が `None` → `_required_float` で `0.0` に default
- 提案: Stage A 不通過時は `fitness_pen` に明示的に「失敗 sentinel」値 (例: `_FAILURE_FITNESS = -1e12`) を archive に転記
- これにより GA selection の `fitness_pen` 比較で「無取引 = 失敗」が「損失付き取引」より下位に位置付けられる

### C. 反証実験による仮説検証

A・B の介入後、同一 seed で短縮 RUN 2 本を実施し:
- `stage_a_pass > 0` の継続維持
- `tc=0` 比率の有意低下 (75% → < 50% target)
- best 個体の `trade_count > 0` 達成率
が改善することを確認。

## 期待効果

### live_criteria 達成パスへの貢献

- **直接効果**: `trade_count > 0` の取引個体が archive 上で正しい `total_pnl` を持つようになり、後段の Stage B 進出判定や best 選抜で「実取引した個体」が浮上する
- **間接効果**: GA selection が「無取引」では reward を得られなくなり、世代を経て取引する個体への進化圧が回復
- **使命寄与**: live_criteria の `trade_count_min: 50` への到達確率が構造的に上昇 (現状 0)

### 観測指標 (改善後の目標)

- `pnl_record_consistency = P(trade_count>0 かつ total_pnl != 0.0)` → 1.0
- `best_no_trade_rate` (取引個体が存在する世代で best が trade_count=0 になる率) → 0
- 世代平均 trade_count の単調減少パターンの解消

## 実装方針 (概要)

### 変更コンポーネント

1. **`src/alpha_factory/stage_gate.py` `evaluate_stage_a`** (Phase A-1)
   - payload に `total_pnl` (= `bt.total_pnl`) を追加
   - exception_caught / no_trades 時は `total_pnl: 0.0` (測定不能)

2. **`src/alpha_factory/archive.py` `collect_stage_a`** (Phase A-1)
   - `row["total_pnl"] = _required_float(payload, "total_pnl")` を追加

3. **`src/alpha_factory/stage_gate.py` `evaluate_stage_a` 不通過時 fitness_pen** (Phase B-1)
   - 不通過理由が `system_failure` / `no_trades` / `metric_unavailable` の場合、`fitness_pen` payload に `_FAILURE_FITNESS = -1e12` を入れる
   - archive 側で `_required_float(default=-1e12)` を適用

4. **`src/ga/runner.py`** (Phase B-1 副作用確認)
   - `(stage_c_pass, stage_b_pass, stage_a_pass, fitness_pen)` 辞書式比較における `fitness_pen` の意味が「未測定 = 0」から「未測定 = -1e12」に変わるため、既存テスト・winner 選抜 期待値を確認

5. **`tests/alpha_factory/test_archive.py` / `test_stage_gate.py`** (テストファースト)
   - 新規回帰テスト

### 実装モード

| 項目 | 内容 |
|------|------|
| 推奨モード | incremental |
| 判断根拠 | 既存 archive schema を変更しない方針で fix する |
| 競合リスク | 同時並行で archive schema 変更を行う TODO があれば衝突。現状無し |
| 想定実装規模 | 中 (~150 LOC + テスト) |
