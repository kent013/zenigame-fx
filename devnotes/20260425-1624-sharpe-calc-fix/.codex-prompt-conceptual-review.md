## 概念設計

# 概念設計: Sharpe Ratio 計算の根本修正 (bar-level annualized → trade-level + threshold)

## 背景・課題

### 観察事実 (Fact, run-9 / run-10 横断)

- Run 10 best 個体: `trade_count=3`, `total_pnl=18860`, `sharpe=18.49`, `fitness=18.48`（[reports/run-reports/run-10.md](../../reports/run-reports/run-10.md)）
- Run 9 では trade_count=0 個体が 75% を占め、Stage A 全滅（pop=20×gen=5 の小規模も寄与）
- 現実の戦略の年率 Sharpe は伝説的なファンドでも 2〜4 程度。**Sharpe 18 は計算式の artifact**
- live_criteria は `sharpe_min=1.0` を要求 → 現状の Sharpe 計算ベースでは sharpe>=1.0 が「楽勝」状態

### コード側の前提検証 (C4 前提検証)

[src/backtest/metrics.py:34-52](../../src/backtest/metrics.py#L34-L52):

```python
BARS_PER_YEAR_M1 = int(24 * 60 * 365 * 5 / 7)  # ≈ 375,428

def _bar_returns(equity_curve):
    rets = []
    prev = None
    for _, eq in equity_curve:
        if prev is not None and prev > 0:
            rets.append(float((eq - prev) / prev))
        prev = eq
    return rets

def _sharpe(returns, periods_per_year=BARS_PER_YEAR_M1):
    if len(returns) < 2: return None
    mean = sum(returns) / len(returns)
    var = sum((r - mean)**2 for r in returns) / (len(returns) - 1)
    std = math.sqrt(var)
    if std == 0: return None
    return (mean / std) * math.sqrt(periods_per_year)
```

`equity_curve` は **M1 全 bar**（ポジ無し時間も含む）から生成。`√375428 ≈ 612.7` で annualize。

### 解釈 (Interpretation)

- 14 日 backtest = 約 20,160 M1 bar。trade_count=3 個体ではポジ保有時間 < 1% → **bar return の 99% 以上が `0`**
- 「ほぼゼロの母集団 + 数本の大きな正リターン」で `mean/std` が異常値、さらに √375428 で増幅
- **i.i.d. 仮定の崩壊**: 連続的に同じリスクを取り続ける前提で annualize しているが、実態は「無ポジ時間が大半」
- GA は fitness=sharpe で選抜しているため、**「スパース取引で artifact を出す個体」を優位に選んでいた**可能性が高い
- これにより Run 9-10 の探索結果はすべて「Sharpe 計算の歪みをハックした個体」を含む。実戦略性能の根拠にならない

## 改善アイデア — Phase 1: trade-level Sharpe + sample-size guard

### 採用する Sharpe 定義

**trade-level Sharpe**:
- 各クローズドトレードの return（`pnl / equity_at_open` または `pnl / risk_unit`）から計算
- Sharpe = mean(trade_returns) / std(trade_returns)
- annualization は `√(trades_per_year_estimate)` を **観測 backtest 期間から推定**
  - `trades_per_year ≈ trade_count × (365 / backtest_days)`
  - もしくは annualize しない「raw trade Sharpe」も併記

### サンプルサイズ・ガード

- `trade_count < N_MIN` (推奨 N_MIN=30) → **`sharpe = None`** を返す
  - GA fitness で None なら `_FAILURE_FITNESS` ✓ 既存の `metric_unavailable` 経路に乗る
- `trade_count < 10` の場合は trade-level Sharpe も解釈不能と明記

### dispatch matrix (排他)

| 条件 | sharpe |
|---|---|
| `trade_count < trade_count_min_for_sharpe` (default 30) | `None` |
| std(trade_returns) == 0 | `None` |
| else | `(mean / std) × annualize_factor` |

### annualize_factor の選択肢

| 候補 | 式 | 利点 | 欠点 |
|---|---|---|---|
| (a) trade-frequency-based | `√(trades_per_year)` | スパース性に対応、解釈整合 | backtest 期間に依存し脆弱 |
| (b) raw (no annualize) | 1 | シンプル、誤解少 | 業界標準値と比較不能 |
| (c) daily-equity-based | 別経路（daily aggregation） | 業界標準 | 短期間で n 不足 |

**推奨**: Phase 1 は **(b) raw trade Sharpe**（annualize なし）。GA fitness の比較には絶対値ではなく相対順序が重要なため、annualize しなくても選抜は機能する。**live_criteria.sharpe_min も raw trade Sharpe ベースで再校正**する（別途）。

## 反証可能仮説 (Falsifiable hypotheses)

- **H1**: 旧 bar-level Sharpe の高い個体（>5 以上）の trade-level Sharpe は大半が 0.3〜1.0 程度に縮む
- **H2**: 既存 Run 10 の best 個体 (sharpe=18.49) の trade-level Sharpe を再計算すると 1 桁以下になる
- **H3**: trade-level Sharpe で再選抜しても上位個体の総 PnL は大きく入れ替わらない（PnL は別軸の真実）

## 成功基準 / kill criteria

### Success
- 既存 best 個体の Sharpe が現実的な範囲（trade-level で 0.5〜3.0 程度）に収まる
- GA fitness が sharpe artifact を選抜しなくなる（trade_count<30 個体の上位淘汰）
- live_criteria.sharpe_min を raw trade Sharpe に合わせて再校正できる

### Kill
- trade-level Sharpe でも全個体が同じ値（distribution flat）→ 識別性なし → 別の fitness 軸へ
- trade_count_min_for_sharpe を厳しくしすぎて GA が初期世代から枯渇 → 緩和して再評価

## 後方互換 (Critical)

- **既存 archive の `sharpe` 列は旧計算値**。新 archive と混在すると比較不能。
  - schema バージョン管理: `sharpe_calc_version` 列を archive に追加（旧=`v1_bar_annualized`、新=`v2_trade_level`）
  - 旧 archive 読み込み時は警告ログ + 新 metric と比較しないガード
- DSR (Deflated Sharpe) は `sharpe_ratio: bar 単位 (non-annualized)` を期待 → trade-level Sharpe に切り替えると引数の意味論が変わる。**DSR の入力定義も合わせて更新**
- live_criteria.sharpe_min はそのまま使うと意味論不整合 → 旧値を `1.0` から例えば `0.3` 程度に再校正必要
- cross_pair の per-pair Sharpe も同じく trade-level に切り替え
