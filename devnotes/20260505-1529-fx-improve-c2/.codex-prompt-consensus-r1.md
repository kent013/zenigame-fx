## 入力: マージ統合提案

### Critical (P1): Stage B WF 窓設計の契約化

- **target_metric**: Stage B fold 生成可能性 (品質保証の前提条件)
- **failure_mode**: B 期間 97003 bars (67 日) に WF train=60d+test=10d を当てると fold max=2 が構造的必然、 wf_min_folds_required 引き上げは fail-closed 化
- **causal_path**: partition (T087) と WF 窓 (`wf_train_days / wf_test_days / wf_step_days / wf_min_folds_required`) の幾何的整合が契約化されていない。 DB データ拡張時 / partition 変更時に fold 数が予測不能
- **falsification**: 契約 guard 実装 + データ不足時 fail-closed 化、 充足時に WF 設計を健全化 (train/test 短縮 or B 期間拡張 or step 縮小)
- **success_criterion**: 契約 guard 実装、 現データ (B=97003 bars) で fold 数 ≥ 5 達成 (例: wf_train=20d+test=5d+step=5d 程度)

具体的な実装方向:
1. `validate_stage_b_window` のような guard 関数を追加 (B 期間 ≥ wf_train + (wf_min_folds-1)*wf_step + wf_test の幾何的成立判定)
2. 充足時に WF 設定 (train_days / test_days / step_days) を **新 partition に整合する値** に変更 (Principled Parametric)
3. 契約違反時は RuntimeError fail-closed (Structural)

### Warning (P2): Stage B pass 品質監査 (trade_count 層別)

- target_metric: Stage B 偽陽性検出
- failure_mode: pass 22 件で trade_count mean=16.5 (Stage A 65.5 から急減)、 total_pnl mean=-14,303
- falsification: trade_count 層別 (10-20 / 20-40 / 40+) で Stage B pass 優位が消えなければ「回数削減主因」棄却
- success_criterion: 層別後 「trade_count 40+ 帯で Stage B pass total_pnl mean positive」 もしくは構造改善で偽陽性減少
- 注: n=22<30 で因果断定不可 (C7)、 cycle 2 では分析のみ、 修正は cycle 3 以降
