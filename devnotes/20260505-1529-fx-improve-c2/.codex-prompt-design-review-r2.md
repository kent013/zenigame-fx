# cycle 2 詳細設計レビュー (Round 2)

Round 1 で CHANGES_REQUESTED。 Codex の Critical 指摘 (SSOT 不整合、 schema 未定義、 設計の二重基準) を全面採用して refactor。 これで APPROVED 取れるか確認してください。

## Round 1 で受けた指摘 (再掲)

- [Critical] 既存 `compute_max_folds` (observed-day SSOT) があり、 提案の `bars_per_day` 式は SSOT 不整合
- [Critical] per_generation 欠落 key は **schema 未定義** (writer 欠陥でない)
- [Critical] `wf_min_folds_required=2` のまま「実質 min=5 を guard で確保」 は設計の二重基準
- [Critical] 擬似コード `passed` ログ → 例外の順序逆転
- [Warning] `projected_fold_count` 負値化リスク
- 収束案: 「1 仮説 = 有効 fold 不足、 1 最小変更 = 既存 `compute_max_folds` 判定を起動時 fail-closed 化」

## Claude の対応 (refactor 全面採用)

### cycle 2 確定施策 (P4 / P2 持ち越し)

**P1-1 (改良)**: `compute_max_folds` 起動時 fail-closed 化
- 既存 `compute_max_folds(n_unique_dates_b, wf_train, wf_embargo, wf_test, wf_step)` を呼ぶ (SSOT 一致)
- 新規 yaml key `wf_min_safe_folds=5` を導入 (statistical safety floor)
- 既存 `wf_min_folds_required=2` (worker 短絡判定用) と意図的分離
- log 順序: `evaluating` → 不足なら例外 → 充足なら `passed`
- run_ga.py:1493 周辺、 既存 preflight 計算の直後に guard 追加

**P1-2 (改良)**: WF 値変更で `compute_max_folds(...) >= 5` 達成
- SSOT 一致: 自前 bars_per_day 式不採用、 既存 `compute_max_folds` で algebraic 算出
- 実装フェーズで n_unique_dates(bars_stage_b) を実測 → 新 wf_train/test/step を algebraic 確定 (Codex 提示出発点 train=20/test=5/step=5)
- 閾値 (sharpe_min / positive_fold_min / dsr_min / fold_trade_count_min) は **不変** = 「閾値緩和でステージ飛ばし」 (禁止事項 4) 回避
- P1-1 と一体運用必須 (順序: yaml key 追加 → guard logic 追加 → テスト → n_unique_dates 実測 → WF 値算出 → yaml 更新 → テスト再走破 → RUN)

### 持ち越し (cycle 3 以降)

**P4 (per_generation observability)**: schema 未定義と判明、 cycle 3 で「追加観測項目の定義・算出式・保存先」 を確定 (writer 補修でない)

**P2 (trade_count 層別監査)**: INCONCLUSIVE 許容、 cycle 2 では実行省略可。 cycle 3 で P3 (selection_score 監査) と統合

### Run 35 実行パラメータ (R34 新からの変更)

- `wf_train_days`: 60 → (実測算出値、 train=20d 出発点)
- `wf_test_days`: 10 → (実測算出値、 test=5d 出発点)
- `wf_step_days`: 10 → (実測算出値、 step=5d 出発点)
- `wf_min_safe_folds`: 5 (新規 key)
- 他 (population/generations/mutation/seed/threshold/instrument/stage gate 閾値) 不変

### Principled Parametric 根拠 (Round 1 指摘解消)

- **SSOT 一致**: 既存 `compute_max_folds` (observed-day) をそのまま使う
- **事前定義反証条件**: 「`compute_max_folds(actual_n_unique_dates, new_wf_*) >= 5`」 が確認される
- **閾値不変**: median_oos_sharpe_min=0.05 / positive_fold_min=0.6 / dsr_min=0.0 / fold_trade_count_min=10 不変
- 窓短縮は **fold 生成 enabled/disabled の二値 (geometry)** を変えるのみで、 「合格基準」 不変

### 設計の二重基準解消

- `wf_min_folds_required=2` (既存): worker 短絡判定用、 graceful degrade 経路
- `wf_min_safe_folds=5` (新規): 起動時 fail-closed 用、 statistical safety floor
- 役割を意図的分離、 docs (stage-gates.md) で明示
