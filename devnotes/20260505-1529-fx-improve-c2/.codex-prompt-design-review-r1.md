## 入力: 詳細設計サマリー

### P1-1: Stage B window guard

- 反証可能仮説: 「現実装は WF 窓の幾何契約を validate しないため、 partition / config 変更時に fold max=2 のような不整合が silently 発生」
- 実装方向: `validate_stage_b_window(stage_b_bars, bars_per_day, wf_train_days, wf_test_days, wf_step_days, wf_embargo_days, wf_min_folds_required) -> None`
  - 必要最小 bars 算出式: `bars_per_day * (wf_train_days + wf_test_days + (wf_min_folds_required - 1) * wf_step_days + wf_embargo_days)`
  - projected_fold_count: `(stage_b_bars - bars_per_day * (wf_train_days + wf_test_days + wf_embargo_days)) // (bars_per_day * wf_step_days) + 1`
  - 不足時 RuntimeError fail-closed
- 起動 log: `stage_b_window_guard.{passed|failed} required_bars=X actual_bars=Y projected_fold_count=Z wf_*=...`
- 配置: `src/alpha_factory/stage_partition_guard.py` 拡張 (or 新規モジュール)

### P1-2: WF 窓値変更

- 旧: `wf_train_days=60, wf_test_days=10, wf_step_days=10, wf_embargo_days=1, wf_min_folds_required=2`
- 新: `wf_train_days=20, wf_test_days=5, wf_step_days=5, wf_embargo_days=1, wf_min_folds_required=2`
- 算出根拠: 必要最小 bars (fold=5) = bars_per_day * (20 + 5 + 4*5 + 1) = bars_per_day * 46d。 B=97003 bars / bars_per_day ≈ 67d で余裕あり
- 分類: Principled Parametric (B 期間幾何制約から algebraic 算出)
- 注意: 「閾値緩和でステージ飛ばし」(禁止事項 4) との境界要確認

### P4: per_generation observability 補修

- 現状: best_fitness_raw / median_fitness_pen / stage_X_pass_count / population_diversity が 61/61 全 null
- 実装方向: run_ga.py の per_generation build 経路を Read で特定、 計測値が存在すれば writer に渡す。 計算自体が disable / 未実装なら docs に明記して持ち越し
- 計測ロジック不変

### P2 (分析のみ): trade_count 層別監査

- 層別: [10-20), [20-40), [40-5000)
- 各層で Stage A pass / Stage B pass の median / sign_rate を比較
- INCONCLUSIVE 許容 (n<30、 C7/C8)

R34 から WF 窓のみ変更 (train=60→20, test=10→5, step=10→5)、 他 (population/generations/mutation/seed/threshold/instrument) 不変。
