## 修正版抜粋 (差分)

### §4.3 並列モードの context 配布 — initializer 一括 broadcast

```python
class ParallelEvaluator:
    def __init__(
        self,
        max_workers: int,
        stage_gate_cfg: StageGateConfig,
        cross_pair_cfg: CrossPairConfig,
        prim_evaluator: RegistryEvaluator,
        lane_contexts: Mapping[str, LaneEvalContext],  # RUN 中 immutable
    ):
        if max_workers <= 1:
            self._pool = None
            self._lane_contexts = lane_contexts
            return
        ctx = multiprocessing.get_context("spawn")
        self._pool = ctx.Pool(
            processes=max_workers,
            initializer=_init_worker,
            initargs=(stage_gate_cfg, cross_pair_cfg, prim_evaluator, dict(lane_contexts)),
        )

    def evaluate_population(self, lane_id, generation, population):
        args = [(lane_id, generation, g) for g in population]
        if self._pool is None:
            return [_evaluate_genome_inproc(a, ...) for a in args]
        return self._pool.map(_eval_genome_worker, args)  # population 順保持

    def __enter__(self): return self
    def __exit__(self, exc_type, exc, tb):
        if self._pool is None:
            return
        if exc_type is None:
            self._pool.close()  # graceful
        else:
            self._pool.terminate()  # 異常系即時停止
        self._pool.join()

# worker module-global は __init_worker で 1 度だけ書き込み、以後 immutable 扱い
_LANE_CONTEXTS: dict[str, LaneEvalContext] = {}

def _init_worker(stage_gate_cfg, cross_pair_cfg, prim_evaluator, lane_contexts):
    global _LANE_CONTEXTS, ...
    ensure_registered()
    _LANE_CONTEXTS = lane_contexts  # spawn deep copy 済 → process-local immutable
    ...

def _eval_genome_worker(args):
    lane_id, gen, genome = args
    ctx = _LANE_CONTEXTS[lane_id]
    return evaluate_genome(genome, ctx, ...)
```

**設計上の制約 (明文化)**:
- `lane_contexts` は `ParallelEvaluator.__init__` で確定し、Pool 寿命中は変更不可
- 将来 multi-lane / 動的 lane 追加が必要になったら Pool を作り直す (= LaneManager を再構築)。これは別 TODO のスコープ
- 構造的に worker 間 context 不整合経路を排除

### §4.6 fallback / failure handling
- worker 内例外 → `GenomeEvalError(stage, error_code, fixed_message)` に正規化
- pool 寿命:
  - 正常終了: `LaneManager.close()` (= `__exit__`) で `pool.close()` + `pool.join()`
  - 異常終了: `pool.terminate()` + `pool.join()`
  - `__del__` には依存しない

### §4.6.1 例外正規化決定表

| 例外型 | error_code | fixed_message | 対象 stage |
|---|---|---|---|
| `numpy.linalg.LinAlgError` | `BACKTEST_LINALG_ERROR` | "linalg numerical error" | A/B/C |
| `RuntimeError` (msg に "primitive" 含む) | `PRIMITIVE_LOOKUP_FAIL` | "primitive registry lookup failed" | A/B/C |
| `ValueError` (msg に "stage_b" / "wf" 含む) | `STAGE_B_FOLD_INVALID` | "walk-forward fold invalid" | B |
| `MemoryError` | `WORKER_OOM` | "worker out of memory" | A/B/C |
| `KeyboardInterrupt` / `SystemExit` | (re-raise) | — | — |
| その他 `Exception` | `WORKER_UNCLASSIFIED` | "unclassified worker exception" | A/B/C |

`parallel_eval._classify_exception(exc, stage)` に実装。テストで既知パターンを pin。
**自由文取り込み禁止** (`str(e)` を `fixed_message` に流入させない)。
